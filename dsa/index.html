Data Structures and Algorithms

← All topicsStart: Complexity →

A data structure is a way of organising data so the operations you need are fast: an array, a hash map, a tree, a graph. An algorithm is a precise step-by-step procedure for solving a problem: sorting, searching, finding the shortest route. Choosing the right pair is the difference between a program that answers in a millisecond and one that never finishes.

Each page below covers one area with animated step-through demos, pseudocode, Python code, complexity tables, real-world use cases, and a set of solved practice questions showing how to recognise and solve typical problems. Work through them in order, or jump to what you need.

Cheat sheet: what complexity fits the input size?

A typical machine does roughly 108 simple operations per second. Use the input size to guess the intended solution.

Input size nAcceptable complexityTypical techniques
n ≤ 10-12O(n!)All permutations, brute force
n ≤ 20-25O(2n), O(2n·n)Subsets, bitmask DP, backtracking, meet in the middle (n ≤ 40)
n ≤ 500O(n³)Floyd-Warshall, interval DP
n ≤ 5,000O(n²)2-D DP, all pairs, simple nested loops
n ≤ 106O(n log n)Sorting, heaps, binary search, segment trees, divide and conquer

How to study and solve problems

  1. Understand the problem: restate it, write down inputs, outputs, constraints, and two or three examples including edge cases (empty, one element, duplicates, negatives, huge values).
  2. Brute force first: say the simplest correct solution and its complexity. It gives a baseline and often reveals the structure.
  3. Find the bottleneck: which repeated work can be avoided? Look for a pattern (see page 19): sorted input → binary search or two pointers; "contiguous subarray" → sliding window or prefix sums; "all combinations" → backtracking; overlapping sub-problems → DP; "shortest" in an unweighted graph → BFS.
  4. Choose structures that make the frequent operation cheap (lookup → hash map, min → heap).
  5. Write pseudocode, then code. Dry-run it on an example by hand, exactly like the animations do.
  6. Analyse time and space, then test edge cases.

Suggested learning order

Complexity → arrays and hashing → two pointers, sliding window → stacks and queues → linked lists → binary search → sorting → recursion and backtracking → trees → heaps → graphs → dynamic programming → greedy → advanced structures, strings, math → advanced graphs and modern algorithms. Solve 5-10 problems per topic before moving on, and revisit old ones after a week.
