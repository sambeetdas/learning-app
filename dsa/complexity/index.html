1. Complexity and Big-O

Why measure complexity?

Two programs can give the same answer while one takes a millisecond and the other a week. Timing them on your laptop is not enough: the result depends on the machine, the language and the input you tried. Complexity analysis describes how the cost of an algorithm grows as the input grows, independent of hardware. It is the main tool for comparing algorithms before you write them.

  • Time complexity: how the number of basic steps grows with input size n.
  • Space complexity: how much extra memory is needed (beyond the input itself), including the recursion call stack.

Big-O, Big-Omega and Big-Theta

NotationMeaningPlain English
O(f(n)) – Big-OUpper bound: cost ≤ c·f(n) for large n"It grows no faster than f(n)." Used for worst cases.
Ω(f(n)) – Big-OmegaLower bound: cost ≥ c·f(n)"It needs at least this much." E.g. comparison sorting is Ω(n log n).
Θ(f(n)) – Big-ThetaBoth: tight bound"It grows exactly like f(n)."
o(f(n)), ω(f(n))Strict versionsStrictly slower / strictly faster growth. Rare in practice.

In everyday use, "Big-O" usually means the tight worst-case bound, and people write O(n) when they mean Θ(n).

Simplification rules

  1. Drop constants: 3n + 7 → O(n). 0.5n² → O(n²).
  2. Keep the dominant term: n² + 100n + 5000 → O(n²), because for large n the n² part dwarfs the rest.
  3. Sequential steps add: a loop of n, then a loop of m → O(n + m).
  4. Nested steps multiply: a loop of n inside a loop of m → O(n·m).
  5. Different inputs get different letters: comparing two strings of lengths n and m is O(n·m), not O(n²).
  6. Logarithm base does not matter: log₂ n and log₁₀ n differ by a constant factor, so both are O(log n).

Hidden costs in library calls

  • x in my_list is O(n); x in my_set is O(1) on average.
  • list.insert(0, x) and list.pop(0) are O(n) (everything shifts). Use collections.deque.
  • s[a:b] slicing copies: O(b - a). sorted() is O(n log n).
  • Building a string with += in a loop can be O(n²) in many languages because strings are immutable; collect pieces in a list and "".join() them.

Best, average, worst and amortised

  • Worst case: the maximum over all inputs of size n. The usual guarantee. Linear search: O(n) when the item is last or missing.
  • Best case: the minimum. Linear search: O(1) when the item is first. Rarely useful on its own.
  • Average case: expected cost over a distribution of inputs. Quicksort: O(n log n) on average, O(n²) worst; hash tables: O(1) average, O(n) worst.
  • Amortised: the average cost per operation over a sequence of operations, guaranteed. A dynamic array append is usually O(1) but occasionally O(n) when it resizes; because it doubles its capacity, n appends cost O(n) in total, so each append is amortised O(1). (See the animation on the arrays page.)
  • Expected (randomised): for algorithms that use randomness, such as randomised quicksort or skip lists, the cost averaged over the algorithm's own random choices, for any input.

Space complexity

  • Count the extra memory: new arrays, hash maps, and the recursion stack (each pending call uses a stack frame).
  • Reversing an array in place: O(1) extra. Copying it: O(n). Recursive DFS on a path-shaped tree of n nodes: O(n) stack.
  • Time-space trade-off: memoisation and hash maps spend memory to save time; streaming algorithms spend time (or accuracy) to save memory.

Recurrences and the Master theorem

Recursive algorithms are described by a recurrence: the cost of a problem of size n in terms of smaller problems. For divide-and-conquer recurrences of the form

T(n) = a · T(n / b) + f(n)        a = number of sub-problems, n/b = their size, f(n) = work to split and combine

compare f(n) with nlogb a (the total work at the leaves of the recursion tree):

CaseConditionResultExample
1. Leaves dominatef(n) grows slower than nlogb aT(n) = Θ(nlogb a)Karatsuba: T = 3T(n/2) + n → O(n1.585)
2. Balancedf(n) = Θ(nlogb a)T(n) = Θ(nlogb a log n)Merge sort: T = 2T(n/2) + n → O(n log n); binary search: T = T(n/2) + 1 → O(log n)
3. Root dominatesf(n) grows faster (and is "regular")T(n) = Θ(f(n))T = 2T(n/2) + n² → O(n²)

Other common recurrences (not covered by the Master theorem):

  • T(n) = T(n-1) + O(1) → O(n) (simple recursion over a list).
  • T(n) = T(n-1) + O(n) → O(n²) (selection sort, worst-case quicksort).
  • T(n) = 2T(n-1) + O(1) → O(2n) (naive Fibonacci, Towers of Hanoi).
  • Recursion-tree method: draw the tree of calls, sum the work per level, multiply by the number of levels. That is how all of the above are derived.

Beyond Big-O: what matters in practice

  • Constants matter for real sizes: an O(n log n) algorithm with a huge constant can lose to an O(n²) one for small n. That is why library sorts switch to insertion sort for tiny sub-arrays.
  • Memory access patterns: arrays are contiguous and cache-friendly; linked structures jump around memory. A linear scan of an array can beat a "faster" pointer-based structure.
  • I/O dominates: for data on disk or network, count disk reads or round trips (that is why databases use B-trees with hundreds of keys per node).
  • Parallelism: work (total operations) versus span (longest chain of dependent steps) describes how well an algorithm parallelises.
  • Complexity classes P and NP: some problems (travelling salesman, SAT, knapsack in general) have no known polynomial algorithm; for them we use approximation, heuristics, or exponential algorithms on small inputs.

Practice questions

Work out each complexity yourself, then open the solution.

Q1. Two loops in a row easy 
for i in range(n): print(i)
for j in range(m): print(j)

Solution

The loops run one after another, so their costs add: O(n + m) time, O(1) space. Do not write O(n) unless m is known to be at most n.

Q2. Inner loop depends on the outer one easy 
for i in range(n):
    for j in range(i):
        work()

Solution

The inner loop runs 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 times. Dropping constants and lower terms gives O(n²).

Q3. Doubling counter easy 
i = 1
while i < n:
    i = i * 2

Solution

After k steps, i = 2k. The loop stops when 2k ≥ n, so k = log₂ n: O(log n).

Q4. Logarithmic loop inside a linear one medium 
for i in range(n):
    j = 1
    while j < n:
        j *= 2

Solution

The outer loop runs n times and the inner loop log n times each: O(n log n).

Q5. The harmonic loop medium 
for i in range(1, n + 1):
    for j in range(0, n, i):    # step size i
        work()

Solution

The inner loop runs n/i times. Total n/1 + n/2 + n/3 + ... + n/n = n · H(n), where the harmonic sum H(n) ≈ ln n. So O(n log n). This pattern appears in the sieve of Eratosthenes (which is even better, O(n log log n)).

Q6. Naive recursive Fibonacci medium 
def fib(n):
    if n < 2: return n
    return fib(n - 1) + fib(n - 2)

Solution

T(n) = T(n-1) + T(n-2) + O(1). Each call makes two more, so the call tree has about φn ≈ 1.618n nodes: O(2n) (tight bound O(φn)). Space is O(n) for the deepest chain of calls.

With memoisation each fib(k) is computed once: O(n) time. See the DP page animation.

Q7. Recursive binary search and merge sort medium

Give the recurrence and complexity of (a) binary search, (b) merge sort.

Solution

  • (a) T(n) = T(n/2) + O(1). Master theorem: a = 1, b = 2, nlog21 = 1 = f(n) → case 2 → O(log n).
  • (b) T(n) = 2T(n/2) + O(n). nlog22 = n = f(n) → case 2 → O(n log n). Intuitively: log n levels, each doing O(n) merging work.
Q8. String building in a loop medium 
s = ""
for word in words:          # n words, total length L
    s = s + word

Solution

In languages with immutable strings, each + may copy the whole string built so far, so the total copying is 1 + 2 + ... ≈ O(L²). (CPython sometimes optimises this, but you should not rely on it.) Fix: "".join(words), which is O(L). In C#/Java use StringBuilder.

Q9. Is this O(n²)? hard 
j = 0
for i in range(n):
    while j < n and a[j] < a[i]:
        j += 1

Solution

It looks nested, but j is never reset: across the whole run it moves forward at most n times. Total work = n (outer) + n (all inner steps together) = O(n). This "amortised pointer" argument is why two-pointer and sliding-window solutions are linear.

Q10. Choose an algorithm from the constraints hard

You must answer whether any two numbers in a list of n = 200,000 integers sum to a target. Which approaches fit in about one second?

Solution

  • All pairs: n²/2 = 2×1010 operations, about 200 seconds. Too slow.
  • Sort + two pointers: O(n log n) ≈ 3.5×106. Fine.
  • Hash set of seen values, check target - x: O(n) expected. Best. (See the hashing page.)
Q11. Space of recursion medium 
def total(node):            # binary tree with n nodes
    if not node: return 0
    return node.val + total(node.left) + total(node.right)

Solution

Time O(n) (each node visited once). Space is the maximum recursion depth = the tree height h: O(log n) for a balanced tree, O(n) for a degenerate (list-like) tree.
