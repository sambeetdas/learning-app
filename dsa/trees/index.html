What is a tree?

A tree is a hierarchy: one root node, and every other node has exactly one parent. There are no cycles, so there is exactly one path between any two nodes. File systems, the HTML DOM, organisation charts, JSON documents and database indexes are all trees.

Traversals

"Visiting every node" can be done in several orders. Depth-first orders use recursion (the call stack); breadth-first uses a queue.

Tree traversal

Iterative versions (no recursion limit)

def inorder_iterative(root):
    out, st, cur = [], [], root
    while cur or st:
        while cur:                 # go left as far as possible
            st.append(cur); cur = cur.left
        cur = st.pop()
        out.append(cur.val)        # visit
        cur = cur.right
    return out

def preorder_iterative(root):
    out, st = [], [root] if root else []
    while st:
        n = st.pop(); out.append(n.val)
        if n.right: st.append(n.right)   # push right first so left is processed first
        if n.left: st.append(n.left)
    return out

Morris traversal does inorder in O(1) extra space by temporarily threading right pointers back to ancestors.

The recursive recipe for tree problems

solve(node):
    if node is empty: return the base value        (0, None, True, ...)
    left  = solve(node.left)
    right = solve(node.right)
    combine left, right and node.val into this node's answer
    (optionally update a global best, e.g. diameter or max path sum)
    return what the PARENT needs from this subtree

Height: 1 + max(left, right). Size: 1 + left + right. Balanced: both balanced and heights differ by at most 1. Most tree questions are this template with a different "combine".

Binary search trees (BST)

A BST adds one rule: for every node, keys in the left subtree are smaller and keys in the right subtree are larger. Then searching is like binary search: each comparison discards a whole subtree. Operations cost O(h), where h is the height: O(log n) if balanced, but O(n) if keys arrive in sorted order and the tree degenerates into a stick.

BST operations

Try deleting 20 (leaf), 80 (one child), 30 or 50 (two children).

Ordered operations a BST gives you (and a hash map does not)

  • Min / max: walk left / right as far as possible.
  • Floor / ceiling: the largest key ≤ x / the smallest key ≥ x, by a single root-to-leaf walk.
  • Successor / predecessor of a node, and sorted iteration (inorder).
  • Range queries: all keys between a and b in O(h + k) for k results.
  • Rank / k-th smallest: store subtree sizes in each node ("order-statistic tree").
def is_valid_bst(node, lo=float('-inf'), hi=float('inf')):
    if not node: return True
    if not (lo < node.val < hi): return False
    return is_valid_bst(node.left, lo, node.val) and is_valid_bst(node.right, node.val, hi)

Self-balancing trees

To guarantee O(log n), a balanced BST restructures itself after inserts and deletes using rotations: local re-wirings of three nodes that keep the BST order but change the shape.

B-trees and B+ trees: trees for disks and databases

Reading from disk (or SSD) is thousands of times slower than reading memory, and data comes in whole pages (4-16 KB). A B-tree stores many keys per node (often hundreds), so the tree is very shallow: with 500 keys per node, 3 levels hold 125 million keys, so any lookup needs about 3 page reads. 

                    [ 30 | 60 ]                         every node holds between t-1 and 2t-1 keys
                 /       |       \                       all leaves are at the same depth
      [10 | 20]      [40 | 50]      [70 | 80 | 90]       a full node SPLITS in two and pushes its middle key up

B+ tree: all values live in the leaves, and the leaves are linked:  [10 20] -> [30 40 50] -> [60 70 80 90]
         so a range scan is "find the start, then walk the leaf chain".
  • Used by: almost every relational database index (PostgreSQL, MySQL InnoDB, SQL Server), file systems (NTFS, ext4 directories, Btrfs, APFS), and key-value stores.
  • Alternative for write-heavy workloads: LSM trees (Cassandra, RocksDB), see advanced structures.

Real-world use cases

  • File systems and the DOM: folders and HTML elements are n-ary trees; du computes sizes with a postorder traversal.
  • Databases: B+ tree indexes make WHERE id = ? and ORDER BY fast.
  • Language runtimes: sorted maps and sets (red-black trees); compilers build syntax trees.
  • Networking: routers use tries/radix trees for longest-prefix IP matching.
  • Games and graphics: scene graphs, BSP trees, bounding-volume hierarchies for ray tracing.
  • Version control and blockchains: Merkle trees detect exactly which parts changed.

Practice questions

Q1. Maximum depth of a binary tree easy recursion template 
def max_depth(n):
    return 0 if not n else 1 + max(max_depth(n.left), max_depth(n.right))

O(n) time, O(h) space. BFS counting levels also works.

Q2. Invert (mirror) a binary tree easy 
def invert(n):
    if n: n.left, n.right = invert(n.right), invert(n.left)
    return n
Q3. Same tree / symmetric tree easy 
def same(a, b):
    if not a or not b: return a is b
    return a.val == b.val and same(a.left, b.left) and same(a.right, b.right)

def symmetric(root):
    def mirror(a, b):
        if not a or not b: return a is b
        return a.val == b.val and mirror(a.left, b.right) and mirror(a.right, b.left)
    return mirror(root, root)
Q4. Level order traversal (list per level) medium BFS 
from collections import deque
def levels(root):
    res, q = [], deque([root] if root else [])
    while q:
        res.append([])
        for _ in range(len(q)):            # exactly the nodes of this level
            n = q.popleft(); res[-1].append(n.val)
            if n.left: q.append(n.left)
            if n.right: q.append(n.right)
    return res

Variants: right side view (last of each level), zigzag order, average per level.

Q5. Validate a BST medium bounds

Pass down the allowed (low, high) range (code above). Checking only each node against its children is a classic mistake: a deep descendant can violate an ancestor. Alternatively, an inorder traversal must be strictly increasing.

Q6. k-th smallest element in a BST medium inorder 
def kth_smallest(root, k):
    st, cur = [], root
    while True:
        while cur: st.append(cur); cur = cur.left
        cur = st.pop(); k -= 1
        if k == 0: return cur.val
        cur = cur.right

O(h + k). With subtree sizes stored, O(h).

Q7. Lowest common ancestor (BST and general tree) medium

BST: walk from the root; if both values are smaller go left, if both larger go right, otherwise the current node is the LCA. O(h).

def lca(n, p, q):                  # general binary tree
    if not n or n is p or n is q: return n
    l, r = lca(n.left, p, q), lca(n.right, p, q)
    return n if l and r else l or r

For many queries on a fixed tree, use binary lifting (O(log n) per query), see advanced graphs.

Q8. Diameter of a binary tree medium global best 
def diameter(root):
    best = 0
    def h(n):
        nonlocal best
        if not n: return 0
        l, r = h(n.left), h(n.right)
        best = max(best, l + r)          # longest path passing through n
        return 1 + max(l, r)             # what the parent needs: height
    h(root); return best
Q9. Path sum II (all root-to-leaf paths with a given sum) medium backtracking 
def path_sum(root, target):
    res, path = [], []
    def dfs(n, rem):
        if not n: return
        path.append(n.val); rem -= n.val
        if not n.left and not n.right and rem == 0: res.append(path[:])
        dfs(n.left, rem); dfs(n.right, rem)
        path.pop()                        # undo the choice
    dfs(root, target); return res
Q10. Construct a tree from preorder and inorder medium divide and conquer

The first preorder value is the root; its position in the inorder list splits left and right subtrees. Use a hash map from value to inorder index for O(n) total.

def build(pre, ino):
    idx = {v: i for i, v in enumerate(ino)}; it = iter(pre)
    def go(lo, hi):
        if lo > hi: return None
        v = next(it); n = TreeNode(v)
        n.left = go(lo, idx[v] - 1); n.right = go(idx[v] + 1, hi)
        return n
    return go(0, len(ino) - 1)
Q11. Balanced binary tree check easy

Return the height from each subtree, or -1 as soon as an imbalance is found, so the whole check is one O(n) pass instead of O(n log n).

Q12. Binary tree maximum path sum hard global best

A path can start and end anywhere; values may be negative.

def max_path_sum(root):
    best = float('-inf')
    def gain(n):
        nonlocal best
        if not n: return 0
        l, r = max(gain(n.left), 0), max(gain(n.right), 0)   # drop negative branches
        best = max(best, n.val + l + r)                      # path bending at n
        return n.val + max(l, r)                             # path continuing upwards
    gain(root); return best
Q13. Serialise and deserialise a binary tree hard preorder with nulls 
def serialize(root):
    out = []
    def go(n):
        if not n: out.append("#"); return
        out.append(str(n.val)); go(n.left); go(n.right)
    go(root); return ",".join(out)

def deserialize(s):
    it = iter(s.split(","))
    def go():
        v = next(it)
        if v == "#": return None
        n = TreeNode(int(v)); n.left = go(); n.right = go(); return n
    return go()
Q14. Convert a sorted array into a balanced BST easy divide and conquer

Pick the middle element as the root and recurse on both halves: height O(log n), O(n) time.
