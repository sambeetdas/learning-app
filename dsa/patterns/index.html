Let the constraints guide you

The input size often reveals the intended complexity (full table on the DSA home page): n ≤ 20 suggests exponential/bitmask, n ≤ 5,000 allows O(n²), n up to 105-106 needs O(n log n) or O(n), and n around 109 or more needs O(log n) or a formula.

Templates to know by heart

Sliding window (variable)

left = 0
for right, x in enumerate(a):
    add(x)
    while not valid():
        remove(a[left]); left += 1
    best = max(best, right - left + 1)

Binary search (first true)

lo, hi = 0, n            # answer in [lo, hi]
while lo < hi:
    mid = (lo + hi) // 2
    if ok(mid): hi = mid
    else: lo = mid + 1
return lo

BFS (shortest steps)

q = deque([start]); dist = {start: 0}
while q:
    u = q.popleft()
    for v in neighbours(u):
        if v not in dist:
            dist[v] = dist[u] + 1
            q.append(v)

Backtracking

def go(state):
    if done(state): record(state); return
    for choice in choices(state):
        if valid(choice):
            apply(choice)
            go(state)
            undo(choice)

Tree DFS (return what the parent needs)

def dfs(node):
    if not node: return BASE
    l, r = dfs(node.left), dfs(node.right)
    update_global(node, l, r)
    return combine(node, l, r)

DP (top-down)

@functools.cache
def f(i, state):
    if base_case(i): return BASE
    return best(f(next_i, next_state)
                for each choice)

Monotonic stack

st = []
for i, x in enumerate(a):
    while st and a[st[-1]] < x:
        answer[st.pop()] = x
    st.append(i)

Top-k with a heap

h = []
for x in stream:
    heapq.heappush(h, x)
    if len(h) > k: heapq.heappop(h)
return h        # the k largest

Interview and problem-solving playbook

  1. Clarify (2-3 minutes): restate the problem; ask about input sizes, value ranges, duplicates, negatives, empty input, sortedness, and what to return on failure. Write two examples, including an edge case.
  2. Brute force first: state the obvious solution and its complexity. It proves you understand the problem and gives a fallback.
  3. Optimise: name the bottleneck ("for each element we scan the rest"). Ask: what structure makes that lookup cheap? Is there a monotonic property? Is work repeated (DP)? Can sorting help?
  4. Agree on the approach before coding; mention time and space complexity.
  5. Code cleanly: meaningful names, small helper functions, handle edge cases explicitly.
  6. Test by hand: walk through your example step by step (as the animations on these pages do), then the edge cases. Look for off-by-one errors, empty inputs, overflow and infinite loops.
  7. Discuss trade-offs and follow-ups: what if the data does not fit in memory, arrives as a stream, or must be served concurrently?

Common mistakes

  • Coding before understanding; missing a constraint that rules out the approach.
  • Off-by-one errors in loops and binary search bounds; forgetting the empty case.
  • Modifying a collection while iterating over it; mutable default arguments in Python.
  • Marking BFS nodes visited when dequeued instead of when enqueued (duplicates in the queue).
  • Greedy without proof; DP with a state that misses information.
  • Hidden O(n) operations inside loops: list.pop(0), x in list, string concatenation, slicing.
  • Recursion depth limits on large inputs.
