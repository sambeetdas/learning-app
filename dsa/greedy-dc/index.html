14. Greedy algorithms and divide and conquer

Two big algorithm-design strategies

Greedy

Build the answer step by step, always taking the choice that looks best right now, and never revisiting it. Simple and fast, usually a sort plus one pass. The catch: it is only correct for problems with the right structure, and you must be able to prove it.

Divide and conquer

Divide the problem into independent smaller parts, conquer each recursively, and combine the results. Merge sort, quicksort, binary search, FFT and Karatsuba multiplication all follow this shape. Analyse with the Master theorem.

Greedy: when does it work?

A greedy algorithm is correct when the problem has:

  • The greedy-choice property: some optimal solution starts with the greedy choice.
  • Optimal substructure: after making that choice, the rest is a smaller instance of the same problem.

Two standard proof techniques:

  • Exchange argument: take any optimal solution that differs from the greedy one, swap one of its choices for the greedy choice, and show it does not get worse.
  • Greedy stays ahead: show that after every step, the greedy partial solution is at least as good as any other partial solution.

Where greedy fails

  • Coin change with coins {1, 3, 4} and amount 6: greedy takes 4 + 1 + 1 (3 coins); the optimum is 3 + 3 (2 coins). Greedy works only for "canonical" coin systems such as {1, 2, 5, 10, 20, 50}. Use DP otherwise.
  • 0/1 knapsack: taking the best value-per-weight items first can be far from optimal. (Fractional knapsack, where items can be split, is greedy.)
  • Longest path, travelling salesman: nearest-neighbour heuristics give decent but not optimal tours.

Always test a greedy idea against brute force on small random inputs before trusting it.

Huffman coding

Huffman's algorithm (1952) builds the optimal prefix-free code for compressing symbols with known frequencies: repeatedly merge the two least frequent trees. It is inside ZIP/DEFLATE, gzip, PNG, JPEG and MP3.

Building a Huffman tree

import heapq
from collections import Counter
from itertools import count
def huffman(text):
    tick = count()                                   # tie-breaker so the heap never compares trees
    heap = [(f, next(tick), ch) for ch, f in Counter(text).items()]
    heapq.heapify(heap)
    while len(heap) > 1:
        f1, _, a = heapq.heappop(heap); f2, _, b = heapq.heappop(heap)
        heapq.heappush(heap, (f1 + f2, next(tick), (a, b)))
    codes = {}
    def walk(node, code):
        if isinstance(node, str): codes[node] = code or "0"; return
        walk(node[0], code + "0"); walk(node[1], code + "1")
    walk(heap[0][2], ""); return codes

Karatsuba: multiplying big numbers faster than school

Split x = a·10m + b and y = c·10m + d. Then x·y = ac·102m + (ad + bc)·10m + bd, and the middle term equals (a+b)(c+d) - ac - bd: only three multiplications instead of four.

def karatsuba(x, y):
    if x < 10 or y < 10: return x * y
    m = max(len(str(x)), len(str(y))) // 2
    a, b = divmod(x, 10 ** m); c, d = divmod(y, 10 ** m)
    ac, bd = karatsuba(a, c), karatsuba(b, d)
    mid = karatsuba(a + b, c + d) - ac - bd
    return ac * 10 ** (2 * m) + mid * 10 ** m + bd

Python's own big integers use Karatsuba for large numbers. In 2019 Harvey and van der Hoeven reached O(n log n) for integer multiplication, the long-conjectured optimum.

Closest pair of points in O(n log n)

closest(P sorted by x):
    if |P| ≤ 3: brute force
    split at the median x into L and R
    d = min(closest(L), closest(R))
    strip = points within d of the dividing line, sorted by y
    for each point in strip: compare only with the next 7 points in y order
    return the smallest distance found

The "only 7 neighbours" fact comes from packing: at most 8 points with mutual distance ≥ d fit in a d × 2d rectangle.

Divide and conquer in the real world: parallel and distributed computing (MapReduce, Spark: split data, process partitions, combine), multithreaded sorts, image processing on tiles, and recursive rendering.

Real-world use cases

  • Compression: Huffman codes in DEFLATE (zip, gzip, PNG), JPEG and MP3.
  • Networking: Dijkstra-based routing (OSPF); greedy packet scheduling.
  • Scheduling: earliest-deadline-first in real-time operating systems; meeting room booking.
  • Finance: making change in canonical currencies; greedy portfolio heuristics.
  • Big data: MapReduce and Spark are divide and conquer over clusters.
  • Cryptography and computer algebra: Karatsuba and FFT-based multiplication of huge numbers.

Practice questions

Q1. Jump game I and II medium greedy reach 
def can_jump(a):
    reach = 0
    for i, x in enumerate(a):
        if i > reach: return False
        reach = max(reach, i + x)
    return True

def min_jumps(a):                    # BFS by levels, done greedily
    jumps = end = far = 0
    for i in range(len(a) - 1):
        far = max(far, i + a[i])
        if i == end: jumps += 1; end = far
    return jumps
Q2. Gas station medium greedy restart 
def start_station(gas, cost):
    if sum(gas) < sum(cost): return -1
    tank = start = 0
    for i in range(len(gas)):
        tank += gas[i] - cost[i]
        if tank < 0: start, tank = i + 1, 0     # nothing before i+1 can work
    return start
Q3. Non-overlapping intervals (minimum removals) medium earliest end

Count the maximum set of compatible intervals with the earliest-finish rule (animated above); the answer is n minus that count. O(n log n).

Q4. Minimum arrows to burst balloons medium earliest end

Sort by end. Shoot at the end of the first balloon; skip every balloon that starts at or before that point; shoot again at the next balloon's end.

Q5. Partition labels medium greedy extend 
def partition_labels(s):
    last = {c: i for i, c in enumerate(s)}
    out, start, end = [], 0, 0
    for i, c in enumerate(s):
        end = max(end, last[c])
        if i == end: out.append(end - start + 1); start = i + 1
    return out
Q6. Assign cookies easy sort + two pointers

Sort children by greed and cookies by size; give each child the smallest cookie that satisfies them. O(n log n).

Q7. Candy hard two passes

Each child gets at least one candy, and a child with a higher rating than a neighbour gets more than that neighbour. Minimum total?

def candy(r):
    n = len(r); c = [1] * n
    for i in range(1, n):
        if r[i] > r[i-1]: c[i] = c[i-1] + 1
    for i in range(n - 2, -1, -1):
        if r[i] > r[i+1]: c[i] = max(c[i], c[i+1] + 1)
    return sum(c)
Q8. Lemonade change easy greedy with canonical coins

Keep counts of 5s and 10s. For a 20, prefer giving 10 + 5 (keeps more 5s, the most flexible coin) over 5 + 5 + 5.

Q9. Majority element by divide and conquer medium D&C

The majority of the whole array must be the majority of at least one half. Recurse on both halves; if they disagree, count both candidates in the current range. O(n log n). (Boyer-Moore voting does it in O(n), O(1).)

Q10. Different ways to add parentheses medium D&C + memo 
from functools import cache
@cache
def ways(expr):
    if expr.isdigit(): return [int(expr)]
    out = []
    for i, c in enumerate(expr):
        if c in "+-*":
            for a in ways(expr[:i]):
                for b in ways(expr[i + 1:]):
                    out.append(a + b if c == "+" else a - b if c == "-" else a * b)
    return out
Q11. The skyline problem hard D&C or sweep + heap

Divide and conquer: compute the skylines of each half and merge them like merge sort, walking both lists and taking the max height at every x. O(n log n). Alternatively, sweep over sorted building edges with a max-heap of active heights.

Q12. Is this greedy idea right? medium testing technique

You think "always take the activity with the shortest duration" maximises the number of activities.

Counter-example: [1, 5), [4, 7), [6, 10). Shortest is [4, 7) and it blocks both others (1 activity), while [1, 5) + [6, 10) gives 2. Write a brute-force checker over small random inputs to find such counter-examples automatically.
