5. Hashing: hash maps and hash sets

The idea

Searching an unsorted array takes O(n). A hash table does better by computing where a key should live. A hash function turns the key into a number, and hash(key) % m picks one of m slots. To find the key later, compute the same slot and look only there. On average, insert, lookup and delete are all O(1).

  • Hash map / dictionary: key → value (dict, Dictionary<K,V>, HashMap, JavaScript Map).
  • Hash set: keys only, for membership (set, HashSet<T>).
  • Counter / multiset: key → count (collections.Counter).
ages = {"ana": 31, "bo": 25}
ages["cy"] = 40                  # insert / update   O(1) average
"bo" in ages                     # lookup            O(1) average
del ages["ana"]                  # delete            O(1) average
seen = set([3, 1, 4]); 4 in seen # True

Hash functions

A good hash function for tables is:

  1. Deterministic: the same key always gives the same hash.
  2. Uniform: spreads keys evenly over the slots, so few keys collide.
  3. Fast: it runs on every operation.
  4. Consistent with equality: if a == b then hash(a) == hash(b). Override both together (__eq__/__hash__, Equals/GetHashCode). Mutable objects such as lists cannot be keys, because changing them would change their hash.
// integers:  h(k) = k mod m          (choose m prime, or use a multiplicative hash: (k * A) >> shift)
// strings:   polynomial rolling hash
h = 0
for each character c in s:
    h = (h * 31 + code(c)) mod BIG_PRIME
slot = h mod m

Collisions: chaining vs open addressing

With more possible keys than slots, two keys will eventually land in the same slot: a collision. (By the birthday paradox, with only 23 people the chance that two share a birthday is already over 50%.) There are two main strategies:

Separate chaining

Each slot holds a small list of all keys that hash there. Simple; tolerates high load. Java's HashMap does this, and turns long chains into red-black trees.

Open addressing

All keys live in the array itself. On a collision, probe other slots: linear (i+1, i+2...), quadratic (i+1², i+2²...), or double hashing. Cache-friendly; needs a lower load factor. Python's dict and modern "Swiss tables" use open addressing.

Build a hash table

The default keys (15, 22, 8, 29, 36, 43 are all 1 mod 7) were chosen to collide badly, showing why a good hash function and resizing matter. Try words instead, such as apple, kiwi, plum, fig, lime, pear.

Load factor and resizing

  • Load factor α = keys / slots. Expected chain length (or probe count) grows with α. With chaining, a lookup costs about 1 + α; with linear probing, an unsuccessful lookup costs about ½(1 + 1/(1-α)²), which explodes as α → 1.
  • Tables resize (usually doubling) when α passes a threshold (0.75 in Java, about 2/3 in Python, 0.875 in Swiss tables). Every key is re-hashed into the bigger table. Like dynamic arrays, the cost is amortised O(1) per insert.
  • Worst case is O(n) when many keys collide (bad hash function or a deliberate attack). Java's tree-ified buckets cap it at O(log n).
  • Deleting with open addressing must leave a "tombstone" marker, otherwise later lookups would stop early at the hole.

Real-world use cases

  • Caches: memcached, Redis, CDN and browser caches are giant hash maps (often combined with LRU lists).
  • Databases: hash indexes for equality lookups, and hash joins that build a table on one side and probe it with the other.
  • Compilers and interpreters: symbol tables; object attributes in Python and JavaScript are dictionaries.
  • Distributed systems: sharding by hash(key) % N, or with consistent hashing to limit movement when servers change.
  • Deduplication: backup systems and Git store content by its cryptographic hash.
  • Security: password storage (salted slow hashes), message authentication (HMAC), checksums.
  • Data processing: group-by, distinct counts, joins in Spark and SQL engines.

Practice questions

Q1. Two Sum (unsorted) easy complement lookup 
def two_sum(a, target):
    seen = {}                            # value -> index
    for i, x in enumerate(a):
        if target - x in seen: return [seen[target - x], i]
        seen[x] = i

O(n) time and space, versus O(n²) for checking all pairs.

Q2. Contains duplicate easy set

return len(set(a)) != len(a), or stop early when an element is already in the set. O(n). Sorting first is O(n log n) with O(1) extra space.

Q3. Valid anagram easy counting

Compare character counts (Counter(s) == Counter(t), or a 26-slot array for lowercase). O(n).

Q4. Group anagrams medium canonical key 
from collections import defaultdict
def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups[''.join(sorted(w))].append(w)     # or a tuple of 26 letter counts
    return list(groups.values())

O(n · L log L) with sorted keys, or O(n·L) with count keys.

Q5. Top K frequent elements medium count + bucket

Approach

Count with a hash map. Then either use a heap of size k (O(n log k)), or bucket sort by frequency: bucket[f] lists values seen f times; walk buckets from high to low.

from collections import Counter
def top_k(a, k):
    cnt = Counter(a)
    buckets = [[] for _ in range(len(a) + 1)]
    for x, f in cnt.items(): buckets[f].append(x)
    out = []
    for f in range(len(buckets) - 1, 0, -1):
        for x in buckets[f]:
            out.append(x)
            if len(out) == k: return out

O(n).

Q6. Longest consecutive sequence medium set

Length of the longest run of consecutive integers (in any order), in O(n).

Approach

Put everything in a set. Only start counting from numbers that begin a run (x - 1 not in the set), then extend while x + 1 is present. Each number is visited at most twice.

def longest_consecutive(a):
    s, best = set(a), 0
    for x in s:
        if x - 1 not in s:
            y = x
            while y + 1 in s: y += 1
            best = max(best, y - x + 1)
    return best
Q7. Subarray sum equals k medium prefix-sum map

Count prefix sums seen so far; for each new prefix s, add the count of s - k. Full code on the arrays page. O(n).

Q8. Isomorphic strings easy two maps

Can the characters of s be replaced to get t, with a one-to-one mapping?

def isomorphic(s, t):
    a, b = {}, {}
    for x, y in zip(s, t):
        if a.setdefault(x, y) != y or b.setdefault(y, x) != x: return False
    return len(s) == len(t)
Q9. 4Sum II (count tuples summing to zero) medium meet in the middle

Given four lists A, B, C, D of length n, count (i, j, k, l) with A[i]+B[j]+C[k]+D[l] = 0.

Count all sums a+b in a map (n² entries), then for every c+d add the count of -(c+d). O(n²) instead of O(n⁴).

Q10. Design a hash map medium chaining 
class MyHashMap:
    def __init__(self, m=1024): self.b = [[] for _ in range(m)]
    def _bucket(self, k): return self.b[hash(k) % len(self.b)]
    def put(self, k, v):
        bk = self._bucket(k)
        for pair in bk:
            if pair[0] == k: pair[1] = v; return
        bk.append([k, v])
    def get(self, k):
        for kk, v in self._bucket(k):
            if kk == k: return v
        return -1
    def remove(self, k):
        bk = self._bucket(k); bk[:] = [p for p in bk if p[0] != k]

Add resizing when count / buckets > 0.75 for guaranteed O(1) average.

Q11. Happy number easy cycle detection with a set

Repeatedly replace n by the sum of the squares of its digits. Does it reach 1?

Either it reaches 1 or it loops. Store seen values in a set (or use Floyd's fast/slow pointers for O(1) space).

Q12. Longest substring with at most k distinct characters medium window + counts 
def longest_k_distinct(s, k):
    cnt, l, best = {}, 0, 0
    for r, c in enumerate(s):
        cnt[c] = cnt.get(c, 0) + 1
        while len(cnt) > k:
            cnt[s[l]] -= 1
            if cnt[s[l]] == 0: del cnt[s[l]]
            l += 1
        best = max(best, r - l + 1)
    return best

O(n).
