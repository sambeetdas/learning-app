16. String algorithms

Text is everywhere: search boxes, logs, DNA, source code, network packets. String algorithms answer questions like "where does this pattern occur?", "how similar are these two strings?", and "what is the longest repeated piece?" far faster than comparing character by character from every position. Basic string techniques (two pointers, sliding windows, counting) are on the arrays page.

Knuth-Morris-Pratt (KMP)

The naive matcher, after a mismatch, slides the pattern one step and starts comparing again from scratch, re-reading text it has already seen. KMP pre-computes, for every prefix of the pattern, the longest proper prefix that is also a suffix (the failure table, or LPS array). After a mismatch it reuses that knowledge, so the text pointer never moves backwards.

KMP step by step

def kmp_search(text, p):
    lps, k = [0] * len(p), 0
    for i in range(1, len(p)):
        while k and p[i] != p[k]: k = lps[k - 1]
        if p[i] == p[k]: k += 1
        lps[i] = k
    out, j = [], 0
    for i, c in enumerate(text):
        while j and c != p[j]: j = lps[j - 1]
        if c == p[j]: j += 1
        if j == len(p): out.append(i - j + 1); j = lps[j - 1]
    return out

Prefix-function tricks: the smallest period of s is n - lps[n-1] (if it divides n, s is a repetition); building lps of pattern + "#" + text finds all matches; the shortest palindrome by adding characters in front uses lps of s + "#" + reverse(s).

Z-algorithm

z[i] = length of the longest substring starting at i that is also a prefix of s. It is computed in O(n) by reusing a window [l, r) of the rightmost match found so far. Pattern matching: compute Z of p + "$" + text; every position with z = len(p) is a match.

def z_function(s):
    n = len(s); z = [0] * n; l = r = 0
    for i in range(1, n):
        if i < r: z[i] = min(r - i, z[i - l])           # reuse what the window already tells us
        while i + z[i] < n and s[z[i]] == s[i + z[i]]: z[i] += 1
        if i + z[i] > r: l, r = i, i + z[i]
    return z

Rabin-Karp and rolling hashes

Compare hashes instead of strings. A polynomial hash can be updated in O(1) when the window slides one step: remove the leading character's contribution, shift, add the new one. Equal hashes are verified character by character, because different strings can collide.

Rolling hash search

The tiny modulus 17 is chosen so you can see collisions (windows 10 and 11); real code uses a large prime (around 109) or two moduli at once.

  • Substring equality in O(1): pre-compute prefix hashes H[i] and powers of the base; the hash of any substring is H[r] - H[l] · Br-l. Combined with binary search this finds the longest repeated substring or compares suffixes quickly.
  • Hash attacks: a fixed base and modulus can be attacked with crafted inputs; choose a random base at runtime for adversarial settings.

Boyer-Moore and practical search

Boyer-Moore compares the pattern from right to left and, on a mismatch, uses two rules (bad character, good suffix) to skip ahead, often by the full pattern length. On natural text it inspects only a fraction of the characters, so it gets faster as patterns get longer. Variants (Boyer-Moore-Horspool, two-way) power grep, text editors, and many standard library find functions; modern implementations add SIMD scanning for the first character.

Aho-Corasick: many patterns at once

Build a trie of all patterns, then add failure links (like KMP's, but across the trie) computed by BFS. Scanning the text once follows trie edges and failure links and reports every pattern occurrence.

build trie of all patterns
BFS from the root:  fail[child] = the deepest trie node that is a proper suffix of child's string
                    output[child] also includes output[fail[child]]
scan text:  node = root
            for each character c:
                while node has no edge c and node != root: node = fail[node]
                if node has edge c: node = child(node, c)
                report every pattern in output[node]

Used by antivirus scanners, intrusion detection systems (Snort), spam and profanity filters, fgrep, and DNA motif search.

Palindromes and Manacher's algorithm

Expanding around each of the 2n-1 centres finds the longest palindromic substring in O(n²) with O(1) memory: simple and often enough. Manacher's algorithm does it in O(n): it remembers the rightmost palindrome found so far and mirrors already-known radii from the left side. 

def longest_palindrome(s):                   # Manacher, O(n)
    t = "^#" + "#".join(s) + "#$"            # separators handle even lengths
    p, c, r = [0] * len(t), 0, 0
    for i in range(1, len(t) - 1):
        if i < r: p[i] = min(r - i, p[2 * c - i])     # mirror of i around c
        while t[i + p[i] + 1] == t[i - p[i] - 1]: p[i] += 1
        if i + p[i] > r: c, r = i, i + p[i]
    k = max(range(len(p)), key=p.__getitem__)
    start = (k - p[k]) // 2
    return s[start:start + p[k]]

Suffix arrays, LCP and suffix automata

The suffix array lists the starting positions of all suffixes in sorted order. Every substring is a prefix of some suffix, so binary searching the suffix array finds any pattern in O(m log n). The LCP array (longest common prefix of neighbouring suffixes, Kasai's algorithm, O(n)) unlocks more:

  • Longest repeated substring = max LCP.
  • Number of distinct substrings = n(n+1)/2 - sum(LCP).
  • Longest common substring of two strings: build on a + "#" + b and take the max LCP between suffixes from different strings.
def suffix_array(s):                         # prefix doubling, O(n log^2 n): simple and fast enough
    n, k = len(s), 1
    rank = [ord(c) for c in s]; sa = list(range(n))
    while True:
        key = lambda i: (rank[i], rank[i + k] if i + k < n else -1)
        sa.sort(key=key)
        new = [0] * n
        for j in range(1, n): new[sa[j]] = new[sa[j - 1]] + (key(sa[j]) != key(sa[j - 1]))
        rank = new
        if rank[sa[-1]] == n - 1: return sa
        k *= 2

Faster builds: SA-IS and DC3 run in O(n). A suffix automaton (the smallest automaton accepting all substrings, at most 2n states) and suffix trees (Ukkonen's algorithm) answer the same questions in O(n). The FM-index (based on the Burrows-Wheeler transform) compresses the text and still allows fast search: it is the core of DNA read aligners such as BWA and Bowtie.

More things to know about strings

  • Regular expressions: Thompson's construction turns a regex into an NFA that runs in O(n·m) without backtracking (RE2, Rust's regex, Go). Backtracking engines (PCRE, Python, JavaScript, .NET) support more features but can take exponential time on some patterns ("catastrophic backtracking", a real cause of outages, such as Cloudflare's in 2019).
  • Burrows-Wheeler transform: sorts all rotations of the text; similar contexts end up together, which makes the output highly compressible (bzip2).
  • Unicode: normalise (NFC/NFD) before comparing, and use library functions for case folding and grapheme clusters.
  • Fuzzy matching at scale: n-gram indexes, BK-trees for edit distance, and the MinHash / embedding techniques on the modern algorithms page.

Real-world use cases

  • Search: Ctrl+F, grep, IDE "find in files", full-text engines (Lucene, Elasticsearch use inverted indexes plus string algorithms).
  • Security: intrusion detection and antivirus signatures (Aho-Corasick).
  • Bioinformatics: genome assembly and read alignment (suffix arrays, FM-index, Smith-Waterman).
  • Version control and sync: diff (LCS), rsync and deduplicating backups (rolling hashes / content-defined chunking).
  • Plagiarism and near-duplicate detection: fingerprints from rolling hashes (winnowing, MOSS).
  • Compression: LZ77/LZ78 (zip, gzip, zstd) find repeated substrings; BWT in bzip2.

Practice questions

Q1. Find the index of the first occurrence (strStr) easy KMP / Z

KMP (code above) gives O(n + m) guaranteed. In practice, the language's str.find is already optimised (CPython uses a two-way / Boyer-Moore-Horspool hybrid).

Q2. Repeated substring pattern easy prefix function

Is s made of a substring repeated several times ("abcabc")?

With the LPS array: let p = n - lps[n-1]; the answer is yes when lps[n-1] > 0 and n % p == 0. The neat trick s in (s + s)[1:-1] also works.

Q3. Shortest palindrome by adding characters in front hard KMP

Find the longest palindromic prefix: compute lps of s + "#" + s[::-1]; its last value L is that length. Answer = s[L:][::-1] + s. O(n).

Q4. Longest palindromic substring medium expand / Manacher 
def longest_pal(s):                            # expand around centres, O(n^2), O(1) space
    best = ""
    for c in range(len(s)):
        for l, r in ((c, c), (c, c + 1)):        # odd and even centres
            while l >= 0 and r < len(s) and s[l] == s[r]: l -= 1; r += 1
            if r - l - 1 > len(best): best = s[l + 1:r]
    return best

Manacher (above) does it in O(n).

Q5. Count palindromic substrings medium expand around centres

Same expansion as Q4, counting every successful expansion step. O(n²); with Manacher, sum of (p[i] + 1) // 2 over the transformed string gives O(n).

Q6. Find all anagrams of p in s medium fixed window + counts 
def find_anagrams(s, p):
    need, win, out = [0] * 26, [0] * 26, []
    for c in p: need[ord(c) - 97] += 1
    for i, c in enumerate(s):
        win[ord(c) - 97] += 1
        if i >= len(p): win[ord(s[i - len(p)]) - 97] -= 1
        if win == need: out.append(i - len(p) + 1)
    return out
Q7. Longest duplicate substring hard binary search + rolling hash

If a duplicate of length L exists, one of length L-1 does too: binary search L. For a given L, hash every window of length L with a rolling hash and look for a repeat in a set (verify on collision). O(n log n) expected. A suffix array with LCP gives O(n log n) deterministically.

Q8. Search many keywords in one text hard Aho-Corasick

Build the Aho-Corasick automaton (pseudocode above) and scan the text once. Total time is linear in the text, the total length of the keywords, and the number of matches, instead of O(n × keywords).

Q9. Number of distinct substrings hard suffix array + LCP

n(n+1)/2 total substrings minus the sum of the LCP array (each LCP counts prefixes shared with the previous suffix, i.e. duplicates). With a suffix automaton: sum over states of len(state) - len(link(state)).

Q10. Longest common prefix of a list of strings easy vertical scan / sort

Compare character by character across all strings until one differs; or sort the list and compare only the first and last string. O(total length).

Q11. Valid palindrome after deleting at most one character easy two pointers

Move inwards from both ends; at the first mismatch, check whether skipping the left or the right character leaves a palindrome. O(n).

Q12. String compression (run-length encoding) easy read/write pointers

"aaabcc" → "a3bc2": walk runs with a read pointer, write the character and its count (if > 1) with a write pointer, in place. O(n).
