Finding things fast

Searching means locating an item, a position, or a value that satisfies a condition. On unsorted data you must look at everything: linear search, O(n). On sorted data, binary search halves the candidates at every step: O(log n), so a billion items need only about 30 comparisons. And binary search is much more than "find x in an array": it finds boundaries, minimum feasible values and optimal answers whenever a yes/no condition flips exactly once.

Getting binary search right

Binary search is famous for off-by-one bugs (Jon Bentley found that most professional programmers got it wrong, and a bug in Java's library version went unnoticed for nine years). Fix the meaning of lo and hi, keep it true in every step, and the code writes itself:

// Template: find the FIRST index where condition(i) is true,
// given condition is false ... false, true ... true  (monotonic)
lo = 0, hi = n                      // the answer is somewhere in [lo, hi]; hi = n means "none"
while lo < hi:
    mid = lo + (hi - lo) // 2       // this form never overflows in fixed-width integers
    if condition(mid): hi = mid     // mid may be the answer: keep it
    else:              lo = mid + 1 // mid is definitely not: drop it
return lo
import bisect
a = [1, 3, 3, 5, 5, 5, 8]
bisect.bisect_left(a, 5)     # 3: first index with a[i] >= 5   (lower bound)
bisect.bisect_right(a, 5)    # 6: first index with a[i] > 5    (upper bound)
bisect.bisect_right(a, 5) - bisect.bisect_left(a, 5)   # 3 occurrences of 5
bisect.insort(a, 4)          # insert keeping order (O(n) because of shifting)
# C#: Array.BinarySearch / List<T>.BinarySearch return ~insertionPoint when not found
# C++: std::lower_bound, std::upper_bound, std::equal_range

Binary search on the answer

Many optimisation problems ask for "the minimum X such that something is possible". If being possible is monotonic (whenever X works, every bigger X works too), you can binary search over X and use a simple feasibility check. Signals: "minimise the maximum", "maximise the minimum", "smallest capacity / speed / time / distance such that...".

Minimum ship capacity to deliver within D days

The same pattern solves: Koko eating bananas (minimum eating speed), split array largest sum, aggressive cows / magnetic force (maximise the minimum distance), minimum time to complete trips, and the square root of x.

Quickselect: the k-th smallest in O(n)

Like quicksort, but after partitioning you only continue into the side that contains position k. On average the work halves each time: n + n/2 + n/4 + ... ≈ 2n.

Quickselect

Worst case is O(n²) with bad pivots; random pivots make it unlikely, and the median of medians algorithm guarantees O(n) (used in introselect as a fallback). Library versions: std::nth_element, numpy.partition.

Real-world use cases

  • Databases: B-tree index lookups are a multi-way binary search; sorted string tables (SSTables) are binary searched on disk.
  • git bisect: binary search over commits to find the one that introduced a bug, in log₂(commits) test runs.
  • Debugging and tuning: finding the largest batch size that fits in memory, the timeout threshold, or the first failing input.
  • Networking: routing tables, IP-range lookups (find the range containing an address).
  • Games and graphics: collision times, ray marching, root finding (the bisection method).
  • Statistics: percentiles and medians of huge data (quickselect, streaming quantile sketches).

Practice questions

Q1. Search insert position easy lower bound

The answer is exactly the lower bound: first index with a[i] ≥ target (template above, or bisect_left). O(log n).

Q2. First and last position of a target medium two bounds

first = lower_bound(t); last = lower_bound(t + 1) - 1 (or upper_bound - 1). If first is out of range or a[first] != t, return [-1, -1]. Two O(log n) searches.

Q3. Integer square root easy search on answer 
def isqrt(x):
    lo, hi = 0, x + 1                     # find the first m with m*m > x
    while lo < hi:
        mid = (lo + hi) // 2
        if mid * mid > x: hi = mid
        else: lo = mid + 1
    return lo - 1
Q4. Search in a rotated sorted array medium sorted half

At every step one half around mid is sorted; check whether the target lies in that sorted half (animated above). O(log n). With duplicates the worst case becomes O(n), because a[lo] == a[mid] tells you nothing; shrink lo by one in that case.

Q5. Minimum in a rotated sorted array medium compare with the end 
def find_min(a):
    lo, hi = 0, len(a) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] > a[hi]: lo = mid + 1     # the drop is to the right of mid
        else: hi = mid
    return a[lo]
Q6. Find a peak element medium binary search on slope

Return any index that is larger than its neighbours.

If a[mid] < a[mid+1], a peak must exist to the right (the values climb and must come down or end); otherwise one exists at mid or to its left. O(log n) even though the array is not sorted.

Q7. Koko eating bananas medium search on answer

Piles of bananas, h hours; at speed k Koko eats up to k from one pile per hour. Minimum k to finish?

Hours needed at speed k = sum(ceil(p / k)), which decreases as k grows: binary search k in [1, max(piles)]. O(n log max).

Q8. Split an array into k parts minimising the largest sum hard search on answer

Exactly the ship-capacity demo: binary search the maximum allowed part sum in [max, total]; greedily count how many parts are needed. O(n log total). (A DP solution is O(k n²).)

Q9. Search a 2-D matrix medium flatten / staircase

If every row starts after the previous row ends, treat it as one sorted array of length m·n: index i maps to (i // n, i % n). If rows and columns are only sorted individually, use the staircase walk from the top-right: O(m + n).

Q10. Median of two sorted arrays hard partition search

Approach

Binary search a cut i in the shorter array A (and j = half - i in B) so that everything left of both cuts is ≤ everything right of them: A[i-1] ≤ B[j] and B[j-1] ≤ A[i]. Then the median comes from the four boundary values.

def median_two(A, B):
    if len(A) > len(B): A, B = B, A
    m, n = len(A), len(B); half = (m + n + 1) // 2
    lo, hi = 0, m
    while lo <= hi:
        i = (lo + hi) // 2; j = half - i
        Al = A[i - 1] if i else float('-inf'); Ar = A[i] if i < m else float('inf')
        Bl = B[j - 1] if j else float('-inf'); Br = B[j] if j < n else float('inf')
        if Al <= Br and Bl <= Ar:
            if (m + n) % 2: return max(Al, Bl)
            return (max(Al, Bl) + min(Ar, Br)) / 2
        if Al > Br: hi = i - 1
        else: lo = i + 1

O(log min(m, n)).

Q11. K-th smallest element in a sorted matrix medium search on value

Binary search on the value v in [min, max]; count elements ≤ v with the staircase walk in O(n). The smallest v with count ≥ k is the answer. O(n log range). A heap of row heads also works: O(k log n).

Q12. Find the duplicate number (values 1..n in n+1 slots) medium search on value / Floyd

Binary search on value v: if more than v numbers are ≤ v, the duplicate is ≤ v (pigeonhole). O(n log n), O(1) space. Or treat i → a[i] as a linked list and find the cycle start with Floyd's algorithm: O(n).

Q13. Time-based key-value store medium binary search per key

set(key, value, timestamp); get(key, t) returns the value with the largest timestamp ≤ t.

Timestamps arrive in increasing order, so each key's list stays sorted: bisect_right(times, t) - 1 gives the answer in O(log n).
