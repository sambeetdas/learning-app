What is a linked list?

A linked list is a chain of nodes. Each node holds a value and a pointer (reference) to the next node. The list itself only remembers the first node, the head. Nodes can live anywhere in memory, so the list can grow and shrink one node at a time, and inserting or deleting next to a node you already hold is O(1). The price: there is no index arithmetic, so reaching the k-th element means walking k steps. 

class Node:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

head = Node(1, Node(2, Node(3)))       # 1 -> 2 -> 3 -> None

def traverse(head):
    cur = head
    while cur:
        print(cur.val)
        cur = cur.next

Linked list vs array

OperationArray / dynamic arrayLinked list
Access k-th elementO(1)O(k)
Insert / delete at the frontO(n)O(1)
Insert / delete at the endO(1) amortisedO(1) with a tail pointer (delete needs doubly linked)
Insert / delete next to a known nodeO(n) (shifting)O(1)
Memory per elementJust the valueValue + 1 or 2 pointers
Cache friendlinessExcellent (contiguous)Poor (nodes scattered)

In practice dynamic arrays win most of the time because of the cache. Linked lists win when you hold references to nodes and splice them often (LRU cache, intrusive lists in operating-system kernels, free lists in memory allocators).

Inserting and deleting

Pointer surgery, step by step

def insert_after(node, x):           # O(1)
    node.next = Node(x, node.next)

def delete_value(head, x):           # O(n) to find, O(1) to unlink
    dummy = Node(0, head); prev = dummy
    while prev.next and prev.next.val != x:
        prev = prev.next
    if prev.next:
        prev.next = prev.next.next
    return dummy.next

Reversing a list

The classic linked-list exercise: walk once, flipping each next pointer to point backwards. Three pointers are enough.

In-place reversal

def reverse_recursive(head):         # O(n) time, O(n) stack
    if not head or not head.next:
        return head
    new_head = reverse_recursive(head.next)
    head.next.next = head            # the node after me points back to me
    head.next = None
    return new_head

Fast and slow pointers

Two pointers moving at different speeds solve several problems with O(1) memory: find the middle (when fast reaches the end, slow is halfway), detect a cycle (inside a loop the fast one must eventually lap the slow one), and find the cycle start. This is Floyd's tortoise and hare algorithm.

Floyd's cycle detection

(-1 = no cycle)

Why phase 2 finds the start

Let the distance from head to the cycle start be a, and let the pointers meet b steps into the cycle of length c. Slow walked a + b, fast walked 2(a + b), and fast's extra distance is a whole number of loops: a + b = k·c. So a = k·c - b: walking a steps from head, or a steps from the meeting point, both land on the cycle start.

def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
    return slow                      # second middle for even lengths

Techniques that come up again and again

  • Dummy head: dummy = Node(0, head) lets you treat the first node like any other; return dummy.next.
  • Two pointers with a gap: to remove the n-th node from the end, move one pointer n steps ahead, then move both until the first hits the end.
  • Split, process, merge: find the middle, reverse the second half, then compare or weave (palindrome check, reorder list).
  • Merge two sorted lists by repeatedly taking the smaller head; this is the heart of merge sort on lists (O(n log n), no extra arrays).
  • Hash map from old node to new node to deep-copy lists with extra pointers.

Use case: LRU cache (hash map + doubly linked list)

A Least-Recently-Used cache must return a value by key in O(1) and evict the oldest item in O(1). A hash map gives O(1) lookup; a doubly linked list keeps items in usage order and lets you move any node to the front, or drop the tail, in O(1). Browsers, CDNs, databases (buffer pools) and operating systems (page caches) all use this idea. 

class LRU:
    def __init__(self, cap):
        self.cap, self.map = cap, {}
        self.head, self.tail = Node(0), Node(0)        # sentinels: head.next = most recent
        self.head.next, self.tail.prev = self.tail, self.head

    def _remove(self, n): n.prev.next, n.next.prev = n.next, n.prev
    def _add_front(self, n):
        n.prev, n.next = self.head, self.head.next
        self.head.next.prev = n; self.head.next = n

    def get(self, key):
        if key not in self.map: return -1
        n = self.map[key]; self._remove(n); self._add_front(n)
        return n.val

    def put(self, key, val):
        if key in self.map: self._remove(self.map[key])
        n = Node(val); n.key = key
        self.map[key] = n; self._add_front(n)
        if len(self.map) > self.cap:
            lru = self.tail.prev; self._remove(lru); del self.map[lru.key]
# (Node here needs .prev as well as .next.)  In Python, collections.OrderedDict with move_to_end() does all of this for you.

Real-world use cases

  • Operating systems: the Linux kernel's process lists and many queues are intrusive doubly linked lists.
  • Memory allocators: free blocks are chained in "free lists".
  • Hash tables with chaining: each bucket is a short linked list (see hashing).
  • Undo / redo and browser history: doubly linked lists of states.
  • Music playlists and round-robin schedulers: circular lists.
  • Functional languages: immutable linked lists share their tails safely between versions (persistent data structures).
  • Blockchains are, conceptually, linked lists where each block holds the hash of the previous one.

Practice questions

Q1. Reverse a linked list easy pointers

Approach

Iterate with prev / cur / next, flipping each arrow (animated above). Recursive version shown above too.

Complexity

O(n) time, O(1) space (iterative).

Q2. Merge two sorted lists easy dummy head 
def merge(a, b):
    dummy = tail = Node(0)
    while a and b:
        if a.val <= b.val: tail.next, a = a, a.next
        else:              tail.next, b = b, b.next
        tail = tail.next
    tail.next = a or b
    return dummy.next

Complexity

O(n + m) time, O(1) space.

Q3. Middle of the list easy fast/slow

Move slow by 1 and fast by 2; when fast reaches the end, slow is in the middle (code above). O(n), O(1).

Q4. Linked list cycle I and II medium Floyd

Does the list have a cycle? If yes, where does it start?

Approach

Q5. Remove the n-th node from the end medium gap pointers 
def remove_nth_from_end(head, n):
    dummy = Node(0, head); fast = slow = dummy
    for _ in range(n + 1): fast = fast.next        # open a gap of n nodes
    while fast: fast, slow = fast.next, slow.next
    slow.next = slow.next.next                     # slow is just before the target
    return dummy.next

Complexity

One pass: O(n), O(1).

Q6. Palindrome linked list medium middle + reverse

Approach

  1. Find the middle with fast/slow.
  2. Reverse the second half.
  3. Compare the two halves node by node.
  4. (Optionally reverse back to restore the list.)

Complexity

O(n) time, O(1) space (copying into an array is O(n) space).

Q7. Intersection of two lists easy two pointers

Two lists merge at some node. Find it.

Approach

Walk pointer A through list A then list B, and pointer B through B then A. Both travel lenA + lenB, so they arrive at the intersection at the same time (or both reach null).

def intersection(a, b):
    p, q = a, b
    while p is not q:
        p = p.next if p else b
        q = q.next if q else a
    return p
Q8. Add two numbers stored as lists medium carry

Digits are stored in reverse order (2 → 4 → 3 is 342). Return the sum as a list.

def add(a, b):
    dummy = tail = Node(0); carry = 0
    while a or b or carry:
        s = carry + (a.val if a else 0) + (b.val if b else 0)
        carry, d = divmod(s, 10)
        tail.next = Node(d); tail = tail.next
        a = a.next if a else None; b = b.next if b else None
    return dummy.next

Complexity

O(max(n, m)).

Q9. Copy a list with random pointers medium hash map

Each node also has a random pointer to any node (or null). Deep-copy the list.

Approach

Pass 1: create a copy of every node and store old → new in a map. Pass 2: set new.next = map[old.next] and new.random = map[old.random]. An O(1)-space trick interleaves copies between originals, then splits them apart.

Complexity

O(n) time, O(n) space (map version).

Q11. Merge k sorted lists hard heap

Approach

Push the head of every list into a min-heap. Repeatedly pop the smallest node, append it to the result, and push its successor.

import heapq
def merge_k(lists):
    h = [(l.val, i, l) for i, l in enumerate(lists) if l]
    heapq.heapify(h)
    dummy = tail = Node(0)
    while h:
        _, i, node = heapq.heappop(h)
        tail.next = node; tail = node
        if node.next: heapq.heappush(h, (node.next.val, i, node.next))
    return dummy.next

Complexity

O(N log k) for N total nodes. (Pairwise divide-and-conquer merging has the same bound.)

Q12. Reverse nodes in k-groups hard reversal + bookkeeping

Reverse every consecutive block of k nodes; a final block shorter than k stays as it is.

Approach

Keep group_prev (the node before the block). Check that k nodes exist; reverse exactly those k with the standard three-pointer loop; reconnect: group_prev.next becomes the block's new first node, and the old first node (now last) points to the next block. Advance group_prev to that node and repeat.

dummy.next = head; group_prev = dummy
loop:
    kth = walk k steps from group_prev;  if none: break
    group_next = kth.next
    reverse nodes from group_prev.next up to kth (stop at group_next)
    old_first = group_prev.next
    group_prev.next = kth;  old_first.next = group_next
    group_prev = old_first
return dummy.next

Complexity

O(n) time, O(1) space.
