9. Advanced graph algorithms

This page builds on graph basics (BFS, DFS, shortest paths, MST). It covers the algorithms behind connectivity analysis, network capacity, assignment problems, logic constraints and tree queries, plus the most important recent research results.

Strongly connected components (SCC)

In a directed graph, an SCC is a maximal group of vertices where every vertex can reach every other. Collapsing each SCC to one node always yields a DAG (the condensation), so SCCs let you apply DAG techniques to any directed graph.

Tarjan's algorithm

Kosaraju's algorithm (simpler to remember)

1. DFS the graph; record vertices in order of finishing time.
2. Reverse every edge.
3. Process vertices in decreasing finishing time; each DFS on the reversed graph
   from an unvisited vertex collects exactly one SCC.           O(V + E)

Uses: finding mutually dependent modules, deadlock cycles, clusters of web pages, and 2-SAT (below).

Bridges and articulation points

A bridge is an edge whose removal disconnects the graph; an articulation point (cut vertex) is such a vertex. They are the single points of failure in networks. One DFS with discovery times and low-links finds them all (also by Tarjan): edge u–v (v a child) is a bridge if low[v] > disc[u]; u is an articulation point if low[v] ≥ disc[u] for some child v (the root needs two or more children). 

def bridges(n, adj):
    disc, low, t, out = [-1] * n, [0] * n, [0], []
    def dfs(u, parent):
        disc[u] = low[u] = t[0]; t[0] += 1
        for v in adj[u]:
            if v == parent: continue
            if disc[v] == -1:
                dfs(v, u); low[u] = min(low[u], low[v])
                if low[v] > disc[u]: out.append((u, v))      # no back edge jumps over u-v
            else:
                low[u] = min(low[u], disc[v])
    for u in range(n):
        if disc[u] == -1: dfs(u, -1)
    return out

Maximum flow and minimum cut

A flow network has edge capacities (pipes, bandwidth, lanes). The maximum flow problem asks how much can be sent from a source s to a sink t. The max-flow min-cut theorem says the answer equals the smallest total capacity of edges whose removal separates s from t: the bottleneck of the network.

Many problems reduce to flow: bipartite matching, assigning workers to jobs, project selection (min cut), image segmentation (foreground/background as a min cut), baseball elimination, edge-disjoint paths, network reliability.

Bipartite matching and assignment

Match people to jobs, students to schools, ads to slots: each left vertex to at most one right vertex, maximising the number (or value) of pairs.

def max_bipartite_matching(adj, n_left, n_right):     # Kuhn's algorithm, O(V E)
    match_r = [-1] * n_right
    def try_assign(u, seen):
        for v in adj[u]:
            if v in seen: continue
            seen.add(v)
            if match_r[v] == -1 or try_assign(match_r[v], seen):   # free, or its partner can move
                match_r[v] = u; return True
        return False
    return sum(try_assign(u, set()) for u in range(n_left))
  • Hopcroft-Karp: augments along many shortest paths at once: O(E√V).
  • Hungarian algorithm: minimum-cost perfect assignment in O(n³) (scipy.optimize.linear_sum_assignment).
  • Stable marriage (Gale-Shapley): a matching with no pair preferring each other over their partners; used for medical residency matching.
  • König's theorem: in bipartite graphs, maximum matching = minimum vertex cover.

Euler paths and circuits

An Euler path uses every edge exactly once. It exists in an undirected connected graph when 0 or 2 vertices have odd degree (directed: in-degree equals out-degree everywhere, except possibly one start and one end). Hierholzer's algorithm finds it in O(E).

def euler_path(adj, start):           # adj: dict of lists, edges consumed as used (directed)
    st, path = [start], []
    while st:
        u = st[-1]
        if adj[u]: st.append(adj[u].pop())
        else: path.append(st.pop())
    return path[::-1]

A Hamiltonian path (every vertex once) sounds similar but is NP-hard; the travelling salesman problem is its weighted version (bitmask DP for n ≤ ~20, heuristics beyond). Uses of Euler paths: DNA sequence assembly (de Bruijn graphs), route inspection (Chinese postman), drawing a figure without lifting the pen.

2-SAT: satisfying pairwise constraints

Given boolean variables and clauses of the form (a OR b), is there an assignment that satisfies all of them? Each clause gives two implications: NOT a → b and NOT b → a. Build the implication graph and find SCCs: the formula is satisfiable exactly when no variable is in the same SCC as its negation. O(V + E). (3-SAT, with three literals per clause, is NP-complete.)

Uses: scheduling with "either/or" rules, placing labels on a map without overlaps, configuration validation.

Lowest common ancestor and tree queries

For many LCA or distance queries on a fixed tree, pre-compute binary lifting tables: up[k][v] = the 2k-th ancestor of v. Each query lifts the deeper node to the same depth, then lifts both while their ancestors differ.

LOG = 17                                # 2^17 > number of nodes
def preprocess(parent, depth, n):
    up = [parent[:]] + [[0] * n for _ in range(LOG - 1)]
    for k in range(1, LOG):
        for v in range(n): up[k][v] = up[k - 1][up[k - 1][v]]
    return up

def lca(u, v, up, depth):
    if depth[u] < depth[v]: u, v = v, u
    for k in range(LOG - 1, -1, -1):
        if depth[u] - (1 << k) >= depth[v]: u = up[k][u]
    if u == v: return u
    for k in range(LOG - 1, -1, -1):
        if up[k][u] != up[k][v]: u, v = up[k][u], up[k][v]
    return up[0][u]
# distance(u, v) = depth[u] + depth[v] - 2 * depth[lca(u, v)]
  • O(n log n) pre-processing, O(log n) per query. An Euler tour + sparse table gives O(1) queries.
  • Heavy-light decomposition splits a tree into chains so path queries ("sum of values on the path u–v") become O(log² n) segment-tree queries.
  • Centroid decomposition recursively removes the node that splits the tree most evenly; solves path-counting problems in O(n log n).

def pagerank(adj, d=0.85, iters=50):          # adj: node -> list of nodes it links to
    nodes = list(adj); n = len(nodes)
    pr = {u: 1 / n for u in nodes}
    for _ in range(iters):
        new = {u: (1 - d) / n for u in nodes}
        for u in nodes:
            outs = adj[u] or nodes            # a dead end spreads evenly
            for v in outs: new[v] += d * pr[u] / len(outs)
        pr = new
    return pr

Recent breakthroughs (for the curious)

  • Max flow in almost-linear time (2022): Chen, Kyng, Liu, Peng, Probst Gutenberg and Sachdeva solved maximum flow and min-cost flow in m1+o(1) time, decades after the classic algorithms.
  • Negative-weight shortest paths in near-linear time (2022): Bernstein, Nanongkai and Wulff-Nilsen beat Bellman-Ford's O(VE) for integer weights.
  • Dijkstra is "universally optimal" (2024): Haeupler, Hladík, Rozhoň, Tarjan and Tětek showed that Dijkstra with a suitable heap is optimal on every graph structure, not just in the worst case (FOCS 2024 best paper).
  • Breaking the sorting barrier for shortest paths (2025): Duan, Mao, Mao, Shu and Yin gave an O(m log2/3 n) deterministic algorithm for directed single-source shortest paths (STOC 2025 best paper).

These matter mostly for theory and very large graphs today; in practice BFS, Dijkstra, Dinic and union-find still solve almost everything.

Real-world use cases

  • Network reliability: bridges and articulation points show single points of failure in power grids and computer networks.
  • Logistics and telecoms: max flow for capacity planning; min-cost flow for routing shipments.
  • Matching markets: ride-hailing driver assignment, ad auctions, kidney exchange programmes, school admissions.
  • Compilers: SCCs for mutually recursive functions, graph colouring for register allocation, dominator trees for optimisation.
  • Genomics: Euler paths in de Bruijn graphs assemble DNA reads.
  • Search and social media: PageRank, community detection, recommendation graphs.

Practice questions

Q1. Critical connections in a network hard bridges

Return every connection whose removal disconnects some servers.

These are exactly the bridges: use the low-link DFS above. O(V + E).

Q2. Count strongly connected components medium Tarjan / Kosaraju

Run Tarjan (animated above) or Kosaraju and count the components. To find the minimum number of edges to add to make the graph strongly connected: build the condensation DAG; the answer is max(#sources, #sinks) (or 0 if there is only one SCC).

Q3. Assign workers to jobs medium bipartite matching

Each worker can do some jobs; maximise the number of assigned jobs.

Bipartite matching with Kuhn's algorithm (code above), or max flow with s→workers (capacity 1), workers→jobs (1), jobs→t (1). If assignments have costs, use the Hungarian algorithm.

Q4. Reconstruct an itinerary hard Euler path

Use every ticket exactly once, starting from "JFK", choosing the lexicographically smallest itinerary.

An Euler path with Hierholzer's algorithm; sort each adjacency list in reverse so pop() takes the smallest destination first. O(E log E).

Q5. Project selection (maximum profit with prerequisites) hard min cut

Projects have profits (positive) or costs (negative); choosing a project forces choosing its prerequisites. Maximise total profit.

Source → profitable project (capacity = profit), costly project → sink (capacity = cost), project → prerequisite (capacity ∞). Answer = sum of positive profits - min cut. The source side of the cut is the chosen set.

Q6. LCA queries on a large tree medium binary lifting

Pre-process with binary lifting (code above) and answer each query in O(log n). For the distance between two nodes, use depths and the LCA.

Q7. Minimum height trees medium peel leaves

Which roots give a tree of minimum height?

Repeatedly remove all current leaves (like Kahn's topological sort, on degrees). The last 1 or 2 remaining nodes are the centres of the tree. O(n).

Q8. Currency arbitrage hard negative cycle

Given exchange rates, can you start with one currency and end with more of it?

Use edge weights -log(rate): a cycle whose rates multiply to more than 1 becomes a negative cycle. Detect it with Bellman-Ford (one extra relaxation round still improves something).

Q9. 2-SAT feasibility hard implication graph + SCC

Build two nodes per variable (x and not-x), add the two implications per clause, compute SCCs. Unsatisfiable if x and not-x share an SCC; otherwise assign x = true when comp[x] comes after comp[not x] in topological order.

Q10. Longest path in a DAG / count paths medium DP on topological order

Process nodes in topological order: best[v] = max(best[v], best[u] + w) and ways[v] += ways[u] for every edge u→v. O(V + E). (Longest path in a general graph is NP-hard.)

Q11. Travelling salesman on a small graph hard bitmask DP

dp[mask][v] = cheapest way to visit exactly the cities in mask, ending at v. Transition by adding one unvisited city. O(2n n²): fine for n ≤ 20. See the DP page.
