18. Probabilistic, big-data and latest algorithms

DSA home← MathProblem patterns →

Classic algorithms assume the data fits in memory and the answer must be exact. Modern systems often break both assumptions: billions of events per day, streams you see only once, machines that fail, and embeddings with hundreds of dimensions. The algorithms on this page trade a little accuracy, or a tiny chance of error, for enormous savings in memory and time. They run inside databases, CDNs, search engines, AI systems and every large web service.

Bloom filters: membership with tiny memory

Bloom filter

import hashlib, math
class Bloom:
    def __init__(self, n, fp=0.01):
        self.m = math.ceil(-n * math.log(fp) / math.log(2) ** 2)    # optimal number of bits
        self.k = max(1, round(self.m / n * math.log(2)))            # optimal number of hashes
        self.bits = bytearray((self.m + 7) // 8)
    def _pos(self, x):
        h = hashlib.blake2b(str(x).encode()).digest()
        a, b = int.from_bytes(h[:8], "little"), int.from_bytes(h[8:16], "little")
        return [(a + i * b) % self.m for i in range(self.k)]        # double hashing: k hashes from 2
    def add(self, x):
        for p in self._pos(x): self.bits[p // 8] |= 1 << (p % 8)
    def __contains__(self, x):
        return all(self.bits[p // 8] >> (p % 8) & 1 for p in self._pos(x))
  • Variants: counting Bloom filters (support deletion), cuckoo filters (deletion, better space at low error rates), xor and ribbon filters (static sets, ~20-30% smaller than Bloom), quotient filters (resizable, cache-friendly), learned Bloom filters (a model filters first).
  • Used in: LSM-tree databases (RocksDB, Cassandra, HBase) to skip files that cannot hold a key; CDNs to avoid caching one-hit wonders; web crawlers to avoid revisiting URLs; spell checkers; Bitcoin light clients; malicious-URL lists in browsers.

HyperLogLog: counting distinct items

Hash every item to a random-looking bit string. In uniformly random bits, a run of k leading zeros appears roughly once every 2k items, so the longest run seen estimates log₂(distinct count). One estimate is noisy, so HyperLogLog splits items into m buckets by their first bits, keeps the maximum run per bucket, and combines them with a harmonic mean. With m = 16,384 buckets of 6 bits (12 KB) the typical error is about 0.8%, for counts in the billions. 

for each item x:
    h = hash(x)
    j = first p bits of h                  // which of the 2^p buckets
    w = remaining bits
    M[j] = max(M[j], leading_zeros(w) + 1)
estimate = alpha * m^2 / sum(2^(-M[j]))    // plus small/large-range corrections
merge two sketches = element-wise max     // so per-day sketches combine into per-month counts

Used by Redis (PFADD/PFCOUNT), BigQuery and Snowflake (APPROX_COUNT_DISTINCT), Presto/Trino, Elasticsearch cardinality aggregations, and network monitoring (unique source IPs).

Count-Min sketch and heavy hitters

Count-Min sketch

  • Top-k / heavy hitters: combine a Count-Min sketch with a small heap of the current top items, or use Space-Saving / Misra-Gries, which keep k counters and guarantee finding every item that occurs more than n/k times.
  • Quantiles: t-digest, KLL and DDSketch estimate percentiles (p50, p99 latency) from streams with small, mergeable summaries; used by Prometheus-style monitoring, Datadog, Elasticsearch and Apache DataSketches.
  • Uses: trending hashtags and searches, DDoS detection (which IPs send the most), database query planners (frequency estimates), ad-click counting.

Random sampling and shuffling

Reservoir sampling (k = 3 from a stream of 12)

import random
def fisher_yates(a):                       # uniform shuffle in O(n): every permutation equally likely
    for i in range(len(a) - 1, 0, -1):
        j = random.randint(0, i)           # NOT randint(0, len(a)-1): that version is biased
        a[i], a[j] = a[j], a[i]

def weighted_pick(weights):                # pick index i with probability w[i] / sum(w)
    prefix = list(itertools.accumulate(weights))
    return bisect.bisect_right(prefix, random.random() * prefix[-1])
# Many picks from fixed weights: Walker's alias method, O(1) per pick after O(n) setup.

Randomised algorithms come in two flavours: Las Vegas (always correct, random running time: randomised quicksort, skip lists) and Monte Carlo (fixed time, small chance of a wrong answer: Miller-Rabin, Bloom filters, HyperLogLog).

Near-duplicate detection: MinHash, LSH and SimHash

  • Jaccard similarity of two sets = |A ∩ B| / |A ∪ B| (documents as sets of word shingles).
  • MinHash: apply a random hash to every element and keep the minimum. The probability that two sets get the same minimum equals their Jaccard similarity. With 128 hash functions, each document becomes a 128-number signature whose agreement estimates similarity.
  • Locality-sensitive hashing (LSH): split signatures into bands and hash each band; similar documents collide in at least one band with high probability. You only compare candidates that collide, instead of all n² pairs.
  • SimHash: a single 64-bit fingerprint per document where similar documents differ in few bits (Hamming distance); used for web-scale near-duplicate detection.
  • Uses: de-duplicating web crawls and training data for language models, plagiarism detection, clustering news stories, finding similar products.
def minhash_signature(tokens, num=128, seed=1):
    rnd = random.Random(seed)
    salts = [rnd.getrandbits(64) for _ in range(num)]
    return [min(hash((s, t)) for t in tokens) for s in salts]

def estimated_jaccard(sig_a, sig_b):
    return sum(x == y for x, y in zip(sig_a, sig_b)) / len(sig_a)

Vector search: approximate nearest neighbours

Modern AI represents text, images and users as embedding vectors with hundreds of dimensions; "find similar" means "find the nearest vectors" (cosine or dot-product similarity). Exact search compares the query with every vector: O(n·d), too slow for millions. Approximate nearest neighbour (ANN) indexes return almost the same results in milliseconds. They power semantic search, recommendations and retrieval-augmented generation (RAG) for chatbots.

import numpy as np
def cosine_top_k(query, matrix, k=5):      # exact search: fine up to ~1e5-1e6 vectors on a GPU/CPU
    q = query / np.linalg.norm(query)
    m = matrix / np.linalg.norm(matrix, axis=1, keepdims=True)
    scores = m @ q
    return np.argpartition(-scores, k)[:k]   # quickselect, then sort these k if needed

Consistent hashing

With server = hash(key) % N, adding or removing one server changes N, and almost every key moves: a cache stampede or a massive data migration. Consistent hashing places servers and keys on a ring; a key belongs to the next server clockwise. Changing one server only moves the keys in its arc, about 1/N of them.

The hash ring

  • Virtual nodes: each physical server appears at many points on the ring, which evens out the load and lets bigger servers take more points.
  • Rendezvous (highest random weight) hashing: each key goes to the server with the highest hash(key, server); simple and minimal movement without a ring.
  • Jump consistent hash (Google, 2014): a few lines of arithmetic, no memory, perfectly balanced, for numbered buckets. Maglev hashing builds a lookup table for fast load balancing.
  • Used by: Amazon Dynamo and DynamoDB, Cassandra, Riak, memcached client libraries, CDNs (Akamai), load balancers (Google Maglev, Envoy), distributed caches.

import time
class TokenBucket:
    def __init__(self, rate, capacity):
        self.rate, self.cap = rate, capacity
        self.tokens, self.last = capacity, time.monotonic()
    def allow(self):
        now = time.monotonic()
        self.tokens = min(self.cap, self.tokens + (now - self.last) * self.rate)   # lazy refill
        self.last = now
        if self.tokens >= 1: self.tokens -= 1; return True
        return False

Learned and AI-discovered algorithms

  • Learned indexes (2018): Kraska et al. showed that a small model predicting a key's position in a sorted array can replace or accelerate B-trees (RMI, PGM-index, ALEX), with smaller indexes and faster lookups on suitable data.
  • Learned Bloom filters and learned cardinality estimation in query optimisers use models as a first filter, backed by a classic structure for guarantees.
  • AlphaDev (2023): DeepMind's reinforcement-learning agent discovered faster assembly routines for sorting 3, 4 and 5 elements; they were merged into LLVM's libc++ standard library.
  • AlphaTensor (2022) and AlphaEvolve (2025): AI systems discovered new matrix-multiplication schemes (AlphaEvolve: 4×4 complex matrices in 48 multiplications) and improved data-centre scheduling heuristics.
  • Algorithms with predictions: a research area designing algorithms (caching, scheduling, online decisions) that exploit ML predictions when they are good and stay safe when they are wrong.

Practice questions (design and coding)

Q1. Design a rate limiter medium token bucket

One token bucket per client key (user, API key, IP) stored in memory or Redis. For a distributed setup, keep the bucket state in Redis and update it atomically with a Lua script (read tokens and timestamp, refill, decrement, write back). Return HTTP 429 with a Retry-After header when empty.

Q2. Count unique visitors per day across 100 servers medium HyperLogLog

Each server keeps a HyperLogLog sketch per day; merge sketches with an element-wise max to get the global count (and to roll days up into weeks). 12 KB per sketch instead of a set of all user IDs; about 1% error.

Q3. Avoid re-crawling URLs with limited memory medium Bloom filter

Check a Bloom filter before crawling; add each URL after crawling. A false positive skips a few new URLs (acceptable); a false negative can never happen, so you never crawl twice. Size it with m = -n ln(p) / (ln 2)².

Q4. Random pick with weights medium prefix sums + binary search

Build prefix sums of the weights; draw r uniformly in [0, total) and return bisect_right(prefix, r) (code above). O(log n) per pick. For many picks from fixed weights, the alias method gives O(1).

Q5. Shuffle an array fairly medium Fisher-Yates

Fisher-Yates (code above): for i from n-1 down to 1, swap a[i] with a[j], j uniform in [0, i]. The common mistake of picking j from the whole array produces nn equally likely outcomes, which cannot divide evenly into n! permutations, so it is biased.

Q6. Random node from a linked list of unknown length, in one pass medium reservoir, k = 1 
def random_node(head):
    chosen, i, node = None, 1, head
    while node:
        if random.randrange(i) == 0: chosen = node.val     # keep with probability 1/i
        node, i = node.next, i + 1
    return chosen
Q7. Find the top 100 search queries of the day from a stream hard heavy hitters

Exact: a hash map of counts plus a min-heap of size 100 (needs memory for every distinct query). At huge scale: a Count-Min sketch for frequencies plus a heap of the current top 100, or the Space-Saving algorithm with a few thousand counters. Shard by query hash across machines and merge each shard's top list.

Q8. Distribute cache keys across servers that come and go medium consistent hashing

A sorted list of virtual-node positions; look up the first position ≥ hash(key) with binary search (wrapping around). Adding a server inserts its virtual nodes and moves only about 1/N of the keys (see the demo above).

import bisect
class Ring:
    def __init__(self, nodes, vn=100):
        self.ring = sorted((h(f"{n}#{i}"), n) for n in nodes for i in range(vn))
        self.keys = [p for p, _ in self.ring]
    def owner(self, key):
        i = bisect.bisect_left(self.keys, h(key)) % len(self.ring)
        return self.ring[i][1]
Q9. Find near-duplicate documents among 10 million hard MinHash + LSH

Shingle each document (e.g. 5-word windows), compute a 128-value MinHash signature, split it into 32 bands of 4 values, and hash each band into buckets. Only documents sharing a bucket are compared exactly. Tune bands and rows so pairs above your similarity threshold almost always collide.

Q10. Build semantic search over a million documents hard embeddings + ANN

Embed each chunk with a sentence-embedding model; store vectors in an HNSW index (pgvector, FAISS, a vector database). For a query, embed it, retrieve the top 50 by cosine similarity, optionally combine with keyword search (BM25) and re-rank with a cross-encoder. Measure recall against exact search on a sample to tune M and ef.

Q11. Generate unique, sortable IDs without a central database medium Snowflake

64 bits = 41-bit millisecond timestamp + 10-bit machine ID + 12-bit per-millisecond sequence. IDs are unique, roughly time-ordered (good for B-tree indexes), and generated locally. UUIDv7 is the standardised equivalent with 128 bits.
