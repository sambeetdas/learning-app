What is a heap?

A priority queue always gives you the most important item next: the smallest deadline, the shortest distance, the highest score. The usual way to build one is a binary heap: a complete binary tree where every parent is ≤ its children (a min-heap) or ≥ them (a max-heap). The root is the minimum, available in O(1); inserting and removing cost O(log n).

Push and pop: sift up, sift down

  • Push: put the new value in the next free spot (end of the array), then sift up: swap with its parent while it is smaller.
  • Pop: take the root, move the last element to the root, then sift down: swap with the smaller child while it is larger.

Min-heap: tree view and array view

Building a heap in O(n)

Bottom-up heapify

Why O(n): half the nodes are leaves (0 work), a quarter sift down at most 1 level, an eighth at most 2... The sum n/4·1 + n/8·2 + n/16·3 + ... converges to about n.

Heap patterns

Top-K: keep a heap of size k

For the k largest items in a stream, keep a min-heap of size k: if a new item beats the smallest of the current top k (the root), replace it. O(n log k) time, O(k) memory, works on streams that do not fit in memory.

def k_largest(stream, k):
    h = []
    for x in stream:
        if len(h) < k: heapq.heappush(h, x)
        elif x > h[0]: heapq.heapreplace(h, x)     # pop root, push x
    return sorted(h, reverse=True)

Running median: two heaps

Keep the smaller half in a max-heap and the larger half in a min-heap, balanced in size. The median is at the top of one or both. Each insert is O(log n), each median query O(1).

class MedianFinder:
    def __init__(self): self.lo, self.hi = [], []      # lo: max-heap (negated), hi: min-heap
    def add(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))   # move the largest of lo to hi
        if len(self.hi) > len(self.lo):
            heapq.heappush(self.lo, -heapq.heappop(self.hi))
    def median(self):
        if len(self.lo) > len(self.hi): return -self.lo[0]
        return (-self.lo[0] + self.hi[0]) / 2

K-way merge

Merge k sorted lists by keeping the current head of each in a heap: O(N log k). This is how external sorting merges sorted runs from disk, and how databases merge index segments.

Scheduling and simulation

Process events in time order: push future events with their timestamps; always pop the earliest. Meeting rooms, CPU scheduling, discrete-event simulation, timers in event loops.

Greedy graph algorithms

Dijkstra's shortest paths and Prim's minimum spanning tree repeatedly pick the closest unvisited vertex from a heap. See graphs.

Without decrease-key, Dijkstra simply pushes a new (distance, node) pair and skips stale entries when they are popped ("lazy deletion"). That is what most real implementations do.

Real-world use cases

  • Operating systems: priority-based process scheduling, timer queues.
  • Networking: priority queuing of packets (quality of service), routing (Dijkstra in OSPF).
  • Maps and games: shortest paths and A* pathfinding.
  • Data processing: top-K queries (ORDER BY ... LIMIT k), external merge sort, streaming leaderboards.
  • Compression: Huffman coding builds its tree by repeatedly merging the two rarest symbols (see greedy).
  • Job systems: task queues with priorities and deadlines; load balancers choosing the least-loaded server.

Practice questions

Q1. K-th largest element in an array medium heap / quickselect

Approach

Min-heap of size k: after processing all elements, the root is the k-th largest. O(n log k). Alternatively, quickselect (see searching) gives O(n) on average.

def kth_largest(a, k):
    h = a[:k]; heapq.heapify(h)
    for x in a[k:]:
        if x > h[0]: heapq.heapreplace(h, x)
    return h[0]
Q2. Last stone weight easy max-heap simulation

Repeatedly smash the two heaviest stones; the difference (if any) goes back. What is left?

def last_stone(stones):
    h = [-s for s in stones]; heapq.heapify(h)
    while len(h) > 1:
        a, b = -heapq.heappop(h), -heapq.heappop(h)
        if a != b: heapq.heappush(h, -(a - b))
    return -h[0] if h else 0
Q3. K closest points to the origin medium top-K

Max-heap of size k keyed by distance (push (-d, point); pop when size exceeds k), or heapq.nsmallest(k, pts, key=lambda p: p[0]**2 + p[1]**2). O(n log k).

Q4. Find the median from a data stream hard two heaps

Two heaps (code above). O(log n) per insert, O(1) per median.

Q5. Meeting rooms II (minimum rooms needed) medium heap of end times 
def min_rooms(intervals):
    intervals.sort()
    ends = []                                  # end times of meetings in progress
    for s, e in intervals:
        if ends and ends[0] <= s: heapq.heapreplace(ends, e)   # reuse the room that frees first
        else: heapq.heappush(ends, e)
    return len(ends)

O(n log n). Alternative: sort starts and ends separately and sweep.

Q6. Task scheduler with cooldown medium greedy + heap

Tasks with the same letter need n idle slots between them. Minimum total time?

Approach

Greedy: in each cycle of n+1 slots, run the most frequent remaining tasks first (max-heap of counts). A formula also works: max(len(tasks), (maxf - 1) * (n + 1) + count_of_maxf).

Q7. Reorganise a string so no two neighbours are equal medium max-heap

Repeatedly place the most frequent remaining character that differs from the previous one: pop the top, append it, and push back the previously used character (with its count reduced). If the top count ever exceeds (n+1)/2, it is impossible.

Q9. Smallest range covering elements from k lists hard heap + running max

Approach

Keep one pointer per list in a min-heap and track the current maximum among them. The range [heap min, current max] covers all lists. Pop the minimum, advance that list, update the max, and record the best range; stop when any list runs out.

O(N log k).

Q10. Maximise capital (IPO) hard two heaps, greedy

Start with capital w; each project needs capital c[i] and earns p[i]. Do at most k projects.

Sort projects by required capital. Each round, push every now-affordable project's profit into a max-heap, then take the most profitable one. O(n log n).

Q11. Sliding window median hard two heaps + lazy deletion

Two heaps as in the stream median, plus a hash map of "to be deleted" counts. When an element leaves the window, mark it and rebalance; remove marked items only when they reach the top of a heap. O(n log k). (A sorted container such as SortedList gives a simpler solution.)
