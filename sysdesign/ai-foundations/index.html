AI systems fundamentals

System design home

AI applications built on large language models (LLMs) are still distributed systems, with a few new constraints: requests are slow and variable (seconds, streamed token by token), expensive per call (priced in tokens), served by scarce GPUs, non-deterministic, and exposed to new attack types such as prompt injection. This page explains the building blocks shared by every AI case study: RAG, agents, multi-agent systems, AI gateways, LLM serving and more.

How LLM inference works (and why it is slow)

  • Tokens: models read and write tokens (~4 characters of English). Price, latency and limits are all counted in tokens. The context window (e.g. 128 k to 1 M tokens) caps prompt + output.
  • Prefill: the whole prompt is processed in parallel; cost grows with prompt length and dominates time to first token (TTFT).
  • Decode: output tokens are generated one at a time, each needing a pass over the model weights; limited by GPU memory bandwidth. This sets the time per output token (TPOT), e.g. 20-60 tokens/s per request.
  • KV cache: attention keys and values for every token so far are kept in GPU memory, growing with context length and batch size: often the real limit on how many requests a GPU can serve.

Continuous batching

GPUs are efficient only when they process many sequences together. Static batching waits for the slowest sequence before starting a new batch, wasting slots. Continuous (in-flight) batching admits a new request into any slot the moment one finishes. Used by vLLM, TensorRT-LLM, SGLang and hosted model APIs.

Retrieval-augmented generation in brief

  1. Ingest: extract text from documents, split into chunks (a few hundred tokens, with overlap or by structure), add metadata and access rights.
  2. Embed and index: an embedding model turns each chunk into a vector; store vectors and text in a vector + keyword index.
  3. Retrieve: embed the (rewritten) question; run hybrid search (vectors + BM25) filtered by the user's permissions; take the top 20-50.
  4. Rerank: a cross-encoder reorders them; keep the best 3-8.
  5. Generate: the LLM answers using only those chunks and cites them.
  6. Evaluate: retrieval quality (did we fetch the right chunks?) and answer quality (grounded, relevant, complete).

Agents in brief

  • The loop: the model reads the goal and context, decides on an action (a tool call), the runtime executes it, the result is added to the context, and the loop repeats until the model answers or a limit is hit.
  • Tools are described by JSON schemas; the model returns structured calls. MCP (Model Context Protocol) standardises how agents discover and call tools and data sources; A2A (Agent2Agent) standardises agent-to-agent communication.
  • Memory: short-term (conversation and scratchpad in the context), long-term (facts and preferences stored and retrieved), and episodic (past task traces).
  • Controls: step, time and cost budgets; least-privilege tool permissions; sandboxed code execution; human approval for risky actions; full tracing.

Evaluation and observability

  • Offline evaluation: a curated test set of questions with expected answers or rubrics; run on every prompt, model or retrieval change (like unit tests). Metrics: groundedness/faithfulness, relevance, correctness, retrieval recall, task success for agents, safety.
  • LLM-as-judge: a strong model grades outputs against a rubric; calibrate it against human ratings.
  • Online: user feedback (thumbs, edits, escalations), A/B tests, and sampled human review.
  • Tracing: log every step (retrieval results, prompts, tool calls, tokens, latency, cost) with OpenTelemetry's generative AI conventions, keeping PII rules in mind.
  • Versioning: prompts, models, indexes and tools are all versioned artefacts; roll them out like code (canary, rollback). See LLMOps.

Cost: the token maths

Cost per request = input tokens × input price + output tokens × output price (+ retrieval and tool costs). A RAG answer with 6,000 input tokens and 400 output tokens, at $2.50 / $10 per million tokens, costs about $0.019; at 1 million questions a month that is ~$19,000. Halving retrieved context or routing 60% of questions to a model 10× cheaper changes the bill dramatically. Size GPUs and token budgets with the LLM serving calculator.

  • Cache: exact-match and semantic caches for repeated questions; prompt caching for shared prefixes.
  • Trim: retrieve fewer, better chunks; summarise long histories; cap output length.
  • Route: small models first, escalate on low confidence; batch offline workloads.
  • Reserve: provisioned throughput or committed-use discounts for steady volumes.
