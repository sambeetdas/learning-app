Evaluating RAG, LLM and AI systems

System design home

Traditional software is tested with exact assertions. AI systems are non-deterministic, usually have no single correct answer, and fail in many subtle ways: retrieving the wrong passage, inventing a fact, ignoring an instruction, calling the wrong tool, leaking data, being slow or expensive. You cannot improve what you do not measure, so evaluation is a core part of the design, not an afterthought. This page defines the metrics at every layer, shows how they are computed, and how to run evaluation offline (before release) and online (in production).

The evaluation layers

LayerQuestionExample metrics
1. Retrieval (RAG, search)Did we fetch the right information?Recall@k, precision@k, MRR, nDCG, context precision/recall
2. GenerationIs the answer correct, grounded, relevant and well-formed?Faithfulness / groundedness, answer relevance, correctness, completeness, citation accuracy, format validity
3. Task / agentDid the system accomplish the user's goal?Task success rate, tool-call accuracy, trajectory quality, steps and cost per task
4. Safety and responsibilityIs it safe, fair and secure?Harmful-content rate, jailbreak / prompt-injection success rate, PII leakage, bias, over-refusal
5. OperationsIs it fast, reliable and affordable?TTFT, latency p95, throughput, error rate, tokens and cost per request, cache hit rate
6. User and businessDoes it help people and the business?Satisfaction, thumbs-up rate, resolution / deflection rate, acceptance rate, time saved, retention

Evaluate the layers separately as well as end to end: if answers are bad, component metrics tell you whether to fix retrieval, the prompt, the model or the tools.

Retrieval metrics

For each test question you need to know which documents (or chunks) are relevant, ideally with graded relevance (0 = irrelevant, 3 = perfect). Then compare the ranked list the retriever returned.

Operational and business metrics

Operational

  • Time to first token (p50/p95), time per output token, end-to-end latency (p50/p95/p99)
  • Throughput and goodput (requests meeting the latency SLO)
  • Error, timeout and rate-limit (429) rates; availability
  • Input/output tokens per request, cost per request / session / task
  • Cache hit rates (prompt cache, semantic cache), GPU utilisation

User and business

  • Thumbs-up ratio, CSAT, regenerate / edit rate
  • Resolution or deflection rate (support bots), escalation to a human
  • Acceptance rate and retention of accepted suggestions (copilots)
  • Time saved per task, conversion, adoption and weekly active users
  • Cost per successful outcome (the metric that ties quality to money)

Building evaluation datasets

  • Sources: real (anonymised) production questions, subject-matter experts, synthetic questions generated from your documents by an LLM (reviewed by humans), and adversarial cases from red teaming.
  • Coverage: common and rare intents, easy and hard questions, multi-hop questions, unanswerable questions, ambiguous ones, different languages and user roles (permissions).
  • Labels: reference answers, key facts, relevant document ids with graded relevance, expected tool calls for agents, and the expected refusal for disallowed requests.
  • Size: start with 50-200 well-chosen cases to iterate quickly; grow to 1,000+ for release decisions; keep a hidden hold-out set to avoid overfitting prompts to the test set.
  • Maintenance: add every production failure as a new test case (regression set); refresh when documents change; version datasets alongside prompts and indexes.
  • Repeat runs: outputs vary between runs; run each case several times (or at temperature 0) and report averages with confidence intervals.

Code: computing metrics

import math
def retrieval_metrics(ranked_ids, relevance, k):     # relevance: {doc_id: grade 0..3}
    top = ranked_ids[:k]
    rel = [1 if relevance.get(d, 0) > 0 else 0 for d in top]
    total_rel = sum(1 for g in relevance.values() if g > 0)
    precision = sum(rel) / k
    recall = sum(rel) / total_rel if total_rel else 0
    mrr = next((1 / (i + 1) for i, r in enumerate(rel) if r), 0)
    dcg = sum((2 ** relevance.get(d, 0) - 1) / math.log2(i + 2) for i, d in enumerate(top))
    ideal = sorted(relevance.values(), reverse=True)[:k]
    idcg = sum((2 ** g - 1) / math.log2(i + 2) for i, g in enumerate(ideal))
    return {"precision@k": precision, "recall@k": recall, "mrr": mrr, "ndcg@k": dcg / idcg if idcg else 0}

FAITHFULNESS_JUDGE = """You are grading whether an answer is supported by the context.

2. For each claim, output SUPPORTED, CONTRADICTED or NOT_FOUND based ONLY on the CONTEXT.
Return JSON: {"claims": [{"claim": "...", "verdict": "..."}]}
CONTEXT: {context}
ANSWER: {answer}"""
