What are PyTorch and deep learning?

Deep learning is machine learning with neural networks that have many layers. Instead of a human designing features, the network learns them from raw data: pixels, words, sound. Each layer turns the output of the previous one into something more abstract (edges, then shapes, then faces).

PyTorch is an open-source Python library for building and training such networks. It gives you three things:

  • Tensors: NumPy-like multi-dimensional arrays that run on GPUs.
  • Autograd: automatic differentiation. You write the forward calculation; PyTorch works out all the gradients for you.
  • Building blocks: layers, loss functions, optimizers and data loaders (torch.nn, torch.optim, torch.utils.data) to assemble and train models.

Deep learning in a nutshell

  1. Neuron: multiplies its inputs by weights, adds them up with a bias, and passes the sum through an activation function: output = f(w1·x1 + w2·x2 + ... + b).
  2. Layer: many neurons side by side. A network stacks layers: input → hidden layers → output.
  3. Non-linearity is essential: without activation functions, any number of layers collapses into one linear function. The activation lets the network bend its decision boundary.
  4. Loss: one number measuring how wrong the output is compared with the truth.
  5. Learning: compute the gradient of the loss with respect to every weight (backpropagation) and nudge the weights downhill (gradient descent). Repeat on batches of data, many times.
  6. Why "deep"? Each layer builds on the previous one, so depth lets a network compose simple features into complex ones with far fewer parameters than one huge flat layer.

Why deep learning took off around 2012

Three things arrived together: big labelled datasets (ImageNet), GPUs that do thousands of multiplications in parallel, and better training tricks (ReLU, dropout, normalisation, residual connections, Adam). Today's added ingredient is scale: more data, more parameters, more compute.

Tensors: the data structure of PyTorch

A tensor is an n-dimensional array of numbers: a scalar (0-D), a vector (1-D), a matrix (2-D), or more (an image batch is 4-D: batch, channels, height, width). Every tensor has a shape, a dtype (float32, int64, bfloat16...) and a device (CPU or GPU). Operations on tensors run in optimised C++/CUDA, not in Python loops.

Broadcasting: arithmetic between different shapes

PyTorch automatically "stretches" size-1 dimensions so tensors of different shapes can be combined, without copying data. The rule: line the shapes up from the right; each pair of sizes must be equal, or one must be 1 (or missing). Try your own shapes.

Things to remember about tensors

  • Shapes cause most bugs. Print x.shape constantly. Convention: the first dimension is the batch; images are [N, C, H, W] (channels first).
  • View vs copy: view, slicing, transpose share memory (changing one changes the other); clone() makes a real copy. reshape returns a view when it can, otherwise a copy.
  • Devices must match: you cannot add a CPU tensor to a GPU tensor. Move model and data with .to(device).
  • dtype matters: float32 is the default; bfloat16/float16 save memory and speed on GPUs; class labels are int64 (long).
  • Internally a tensor is a block of memory (storage) plus a shape, strides (how many elements to skip per dimension) and a dtype. That is why views are free.

Autograd: automatic differentiation

Training needs the gradient of the loss with respect to every weight. Writing those derivatives by hand for a million-parameter network is impossible, so PyTorch records each operation on tensors that have requires_grad=True into a computation graph, then loss.backward() walks that graph backwards, applying the chain rule at every node (this is called reverse-mode differentiation, or backpropagation). 

w = torch.tensor(1.5, requires_grad=True)     # a parameter to learn
b = torch.tensor(0.5, requires_grad=True)
x, t = torch.tensor(2.0), torch.tensor(1.0)   # input and target (no gradient needed)

loss = (w * x + b - t) ** 2                   # forward: the graph is built here
loss.backward()                               # backward: fills w.grad and b.grad
print(w.grad, b.grad)                         # tensor(10.)  tensor(5.)

Autograd rules you must know

  • Gradients accumulate: every backward() adds to .grad. That is why training loops call optimizer.zero_grad() each iteration. (It is also what makes gradient accumulation possible on purpose.)
  • torch.no_grad() turns off graph recording: use it for validation and inference to save memory and time.
  • .detach() cuts a tensor out of the graph; .item() turns a one-value tensor into a Python number (use it when logging the loss).
  • The graph is freed after backward() (to save memory). Calling backward twice on the same graph fails unless you pass retain_graph=True.
  • In-place operations (x += 1, x.relu_()) can overwrite values autograd needs and raise errors. Prefer out-of-place code.
  • Only leaf tensors with requires_grad keep a .grad. nn.Parameters inside modules are such leaves.

Building models with torch.nn

A model is a class that inherits nn.Module. You create layers in __init__ and describe how data flows in forward. Anything assigned as a layer is tracked automatically: model.parameters() returns all learnable weights, model.to(device) moves them all, and state_dict() saves them. 

import torch.nn as nn
import torch.nn.functional as F

class Net(nn.Module):
    def __init__(self, in_dim=784, hidden=128, classes=10):
        super().__init__()
        self.fc1  = nn.Linear(in_dim, hidden)       # weights [128, 784] + bias [128]
        self.fc2  = nn.Linear(hidden, classes)
        self.drop = nn.Dropout(0.2)

    def forward(self, x):                           # x: [batch, 1, 28, 28]
        x = x.flatten(1)                            # -> [batch, 784]
        x = self.drop(F.relu(self.fc1(x)))
        return self.fc2(x)                          # raw scores ("logits"), NOT softmax

model = Net()
print(sum(p.numel() for p in model.parameters()))   # 101,770 learnable parameters

The training loop

PyTorch gives you the pieces, and you write the loop. This is the heart of every PyTorch program, and it is the same whether you train a tiny classifier or a giant language model. Step through it below. It trains a model with a single weight so every number is visible.

The loop, one line at a time

model = nn.Linear(1, 1, bias=False)                  # one weight, w = 0.5
loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
 
for step in range(5):                                # x = 2, target y = 3
    pred = model(x)               # 1. forward pass:   pred = w * x
    loss = loss_fn(pred, y)       # 2. loss:           (pred - y) ** 2
    optimizer.zero_grad()         # 3. clear old gradients
    loss.backward()               # 4. backward pass:  fills w.grad
    optimizer.step()              # 5. update:         w = w - lr * w.grad

A complete, realistic training script

import torch, torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset, random_split

device = "cuda" if torch.cuda.is_available() else "cpu"

# 1. Data: X float tensor [N, features], y long tensor [N] of class ids
ds = TensorDataset(X, y)
train_ds, val_ds = random_split(ds, [0.8, 0.2])
train_dl = DataLoader(train_ds, batch_size=64, shuffle=True)
val_dl   = DataLoader(val_ds, batch_size=256)

# 2. Model, loss, optimizer
model   = Net().to(device)
loss_fn = nn.CrossEntropyLoss()                       # expects raw logits + class ids
opt     = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)

# 3. Train + validate
for epoch in range(10):
    model.train()
    for xb, yb in train_dl:                           # one batch at a time
        xb, yb = xb.to(device), yb.to(device)
        loss = loss_fn(model(xb), yb)
        opt.zero_grad()
        loss.backward()
        opt.step()

    model.eval()
    correct = 0
    with torch.no_grad():                             # no graph needed for evaluation
        for xb, yb in val_dl:
            xb, yb = xb.to(device), yb.to(device)
            correct += (model(xb).argmax(dim=1) == yb).sum().item()
    print(f"epoch {epoch}  val accuracy {correct / len(val_ds):.3f}")

torch.save(model.state_dict(), "model.pt")

The algorithms of deep learning, explained

"Algorithms" in deep learning come in two groups: the learning algorithms that train any network (backpropagation, optimizers, normalisation, regularisation), and the architectures that define what the network looks like (CNN, RNN, transformer...). Both are explained here.

A. How networks learn

Backpropagation

  • Problem: a network has millions of weights; which way should each one move to reduce the loss?
  • Idea: the network is a chain of functions, so the chain rule of calculus gives the gradient of the loss for every weight. Compute it layer by layer, starting from the output and moving backwards, reusing intermediate results so the cost is only about 2-3 times one forward pass.
  • In PyTorch: loss.backward(). Autograd does all of it; the animation in the Autograd section shows it on a small graph.
  • Trouble spots: vanishing gradients (they shrink to ~0 through many saturating layers; fixed by ReLU-like activations, residual connections, normalisation, good initialisation) and exploding gradients (fixed by gradient clipping, torch.nn.utils.clip_grad_norm_).

Gradient descent and its variants

  • Batch gradient descent: gradient from the entire dataset per step. Accurate but slow and memory-hungry.
  • Stochastic (SGD): one sample per step. Fast, very noisy.
  • Mini-batch (what everyone uses): 16-1024 samples per step. A good balance, and it maps well to GPUs. The noise even helps escape poor spots.
  • Learning rate is the single most important setting: too small trains slowly, too large overshoots and diverges (try it in the playground).

Learning-rate schedules

  • Step / MultiStep decay: multiply the rate by 0.1 every N epochs (StepLR).
  • Cosine annealing: smoothly decrease along a cosine curve (CosineAnnealingLR); very common.
  • Warm-up: start tiny and ramp up for the first steps; essential for transformers, because early large steps on random weights can wreck training.
  • One-cycle: ramp up then down (OneCycleLR); fast convergence.
  • ReduceLROnPlateau: cut the rate when validation loss stops improving.

1. MLP: multi-layer perceptron (feed-forward network)

  • How it works: each layer computes activation(W·x + b) and feeds the next. Every neuron connects to every neuron in the next layer.
  • Strengths: universal approximator (with enough width it can fit any reasonable function); simple. Weaknesses: ignores structure (spatial or sequential), many parameters for images.
  • Use for: tabular data, small problems, and as the "feed-forward" part inside bigger models like transformers. (On tabular data, gradient boosting often wins.)
  • Code: the Net class in the nn section above.

2. CNN: convolutional neural network

  • Problem it solves: a 224×224 colour image has 150,000 numbers; a fully connected layer would need billions of weights and would not know that a cat in the corner is the same cat as in the middle.
  • How it works: a small filter (kernel, e.g. 3×3) slides across the image; at each position it multiplies and sums, producing a feature map. The same weights are reused everywhere (weight sharing), so the network detects a pattern wherever it appears (translation equivariance). Early layers learn edges, middle layers textures and parts, deep layers whole objects.
  • Other ingredients: stride (step size of the slide), padding (border zeros to keep size), pooling (shrink by taking max/average of a region), channels (many filters per layer), and a final linear layer to classify.

In a real CNN the kernel values are not chosen by hand: they are weights that training learns.

  • Famous models: LeNet (1998, digits), AlexNet (2012, the breakthrough), VGG (deep stacks of 3×3), Inception (parallel filter sizes), ResNet (2015: skip connections let you train 50-150+ layers), MobileNet / EfficientNet (small and efficient), ConvNeXt (modernised CNN).
  • Residual (skip) connection: output = x + F(x). The layer only learns the change, and gradients can flow straight through the shortcut, which cures vanishing gradients in very deep networks.
  • Beyond classification: object detection (Faster R-CNN, YOLO, SSD), segmentation (U-Net, Mask R-CNN), pose estimation, image super-resolution. All available in torchvision.models.
  • Also used on: audio spectrograms, 1-D signals (Conv1d), video (Conv3d), and even text.
class CNN(nn.Module):
    def __init__(self, classes=10):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 32, 3, padding=1), nn.BatchNorm2d(32), nn.ReLU(), nn.MaxPool2d(2),   # 28x28 -> 14x14
            nn.Conv2d(32, 64, 3, padding=1), nn.BatchNorm2d(64), nn.ReLU(), nn.MaxPool2d(2),  # 14x14 -> 7x7
        )
        self.head = nn.Sequential(nn.Flatten(), nn.Linear(64 * 7 * 7, 128), nn.ReLU(), nn.Linear(128, classes))
    def forward(self, x):                                  # x: [batch, 1, 28, 28]
        return self.head(self.features(x))

class ResBlock(nn.Module):                                 # the building block of ResNet
    def __init__(self, ch):
        super().__init__()
        self.body = nn.Sequential(nn.Conv2d(ch, ch, 3, padding=1), nn.BatchNorm2d(ch), nn.ReLU(),
                                  nn.Conv2d(ch, ch, 3, padding=1), nn.BatchNorm2d(ch))
    def forward(self, x):
        return F.relu(x + self.body(x))                    # skip connection: x + F(x)

3. RNN, LSTM and GRU: models with memory

  • Problem: sequences (sentences, sensor readings, music) have variable length and order matters.
  • How an RNN works: it reads one element at a time and keeps a hidden state that summarises what it has seen: ht = tanh(W·xt + U·ht-1 + b). The same weights are reused at every step.
  • Weakness: to learn from step 1 at step 100, gradients must pass through 100 multiplications, so they vanish (or explode): plain RNNs forget quickly.
  • LSTM: adds a separate cell state (a conveyor belt of memory) controlled by three gates: forget (what to erase), input (what to write) and output (what to reveal). Gradients flow along the cell state almost unchanged. GRU is a lighter version with two gates.
  • Seq2seq: an encoder RNN compresses the input into a vector; a decoder RNN generates the output (translation, summarisation). Adding attention let the decoder look back at every input word: this was the step towards transformers.
  • Today: transformers replaced RNNs for language, but LSTM/GRU still appear in small, streaming and time-series models, and newer state-space models (Mamba) revisit recurrence for long sequences.
class LSTMClassifier(nn.Module):
    def __init__(self, vocab, emb=128, hidden=256, classes=2):
        super().__init__()
        self.emb  = nn.Embedding(vocab, emb)                # word id -> vector
        self.lstm = nn.LSTM(emb, hidden, batch_first=True)
        self.out  = nn.Linear(hidden, classes)
    def forward(self, tokens):                              # tokens: [batch, seq_len] integer ids
        _, (h, _) = self.lstm(self.emb(tokens))             # h: [1, batch, hidden] = last hidden state
        return self.out(h[-1])

4. Attention and the Transformer

  • Self-attention idea: to understand a word, look at all the other words and decide how much each one matters. In "The cat sat on the mat", the word "sat" should pay attention to "cat" (who sat?).
  • How it works: every token is turned into three vectors: a query (what am I looking for?), a key (what do I contain?) and a value (what do I pass on?). Scores = query · key for every pair; softmax turns scores into weights that sum to 1; the output is the weighted average of the values.
Attention(Q, K, V) = softmax( Q · KT / √dk ) · V        (the √dk keeps the scores in a range softmax handles well)

Self-attention weights

Click a word in the top row (the query). Lines show how strongly it attends to every word. The weights here are hand-made to be illustrative; in a real model they are computed from learned queries and keys.

Rows = the word asking, columns = the word looked at, numbers = attention in %. A low temperature makes attention sharp (almost one word); a high temperature spreads it evenly.

  • Multi-head attention: run several attention "heads" in parallel (each with its own queries, keys and values) so the model can track different relationships at once (grammar, meaning, position), then concatenate them.
  • Positional encoding: attention itself ignores word order, so position information is added (sinusoidal, learned, or rotary / RoPE).
  • The block: x = x + Attention(LayerNorm(x)), then x = x + FeedForward(LayerNorm(x)). Stack 12 to 100+ of these blocks. Residual connections and normalisation make that depth trainable.
  • Why it won: every token is processed in parallel (unlike an RNN), so training scales across thousands of GPUs, and attention connects distant tokens directly.
  • Cost: attention compares every token with every other, so compute and memory grow with the square of the sequence length. FlashAttention (built into PyTorch's scaled_dot_product_attention) and sparse or linear variants reduce this.
  • Three families:
    • Encoder-only (BERT): sees the whole text both ways; for understanding: classification, search embeddings, entity extraction.
    • Decoder-only (GPT, LLaMA): a causal mask hides future tokens; trained to predict the next token; for generation. Uses a KV cache at inference to avoid recomputation.
    • Encoder-decoder (T5, original Transformer): reads input, then generates output; translation, summarisation.
  • Beyond text: ViT cuts an image into patches and treats them as tokens; Whisper does speech; transformers also power protein models, time-series models and multimodal systems (CLIP, GPT-4-style).
  • Large language models: decoder-only transformers with billions of parameters, trained on next-token prediction over huge text, then tuned to follow instructions (supervised fine-tuning, RLHF/DPO). Performance improves predictably with more data, parameters and compute ("scaling laws").
class SelfAttention(nn.Module):
    def __init__(self, d, heads):
        super().__init__()
        self.h, self.dk = heads, d // heads
        self.qkv  = nn.Linear(d, 3 * d)                     # produces queries, keys, values at once
        self.proj = nn.Linear(d, d)
    def forward(self, x, causal=False):                     # x: [B, T, d]
        B, T, d = x.shape
        q, k, v = self.qkv(x).view(B, T, 3, self.h, self.dk).permute(2, 0, 3, 1, 4)   # each [B, h, T, dk]
        out = F.scaled_dot_product_attention(q, k, v, is_causal=causal)               # softmax(QK^T/sqrt(dk)) V
        return self.proj(out.transpose(1, 2).reshape(B, T, d))

class Block(nn.Module):                                     # one transformer block
    def __init__(self, d, heads):
        super().__init__()
        self.n1, self.n2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.att = SelfAttention(d, heads)
        self.mlp = nn.Sequential(nn.Linear(d, 4 * d), nn.GELU(), nn.Linear(4 * d, d))
    def forward(self, x):
        x = x + self.att(self.n1(x))                        # attention + residual
        return x + self.mlp(self.n2(x))                     # feed-forward + residual

5. Autoencoders and VAEs

  • Autoencoder: an encoder squeezes the input into a small vector (the latent code) and a decoder rebuilds the input from it. The loss is the reconstruction error; the input is its own target, so no labels are needed (self-supervised).
  • Why useful: compression, denoising, learning features, and anomaly detection (data unlike the training set reconstructs badly, so a high error means "unusual").
  • Variational autoencoder (VAE): the encoder outputs a distribution (mean and variance) instead of a point, and a KL-divergence term keeps the latent space smooth. You can then sample new points and decode them into new, realistic data. The sampling uses the reparameterisation trick so gradients can still flow.
class AE(nn.Module):
    def __init__(self):
        super().__init__()
        self.enc = nn.Sequential(nn.Linear(784, 128), nn.ReLU(), nn.Linear(128, 16))   # squeeze to 16 numbers
        self.dec = nn.Sequential(nn.Linear(16, 128), nn.ReLU(), nn.Linear(128, 784), nn.Sigmoid())
    def forward(self, x): return self.dec(self.enc(x))

# VAE: sampling with the reparameterisation trick, and the extra KL loss
mu, logvar = encoder(x).chunk(2, dim=1)
z = mu + torch.randn_like(mu) * torch.exp(0.5 * logvar)
kl = -0.5 * torch.sum(1 + logvar - mu**2 - logvar.exp())

6. GAN: generative adversarial network

  • Idea: two networks play a game. The generator turns random noise into fake data (images); the discriminator tries to tell fake from real. Each improves by beating the other: like a forger and a detective.
  • Training: alternate: (1) update the discriminator to classify real as 1 and fake as 0; (2) update the generator so the discriminator calls its fakes real.
  • Strengths: sharp, realistic images (StyleGAN faces), fast sampling. Weaknesses: unstable training, mode collapse (the generator produces only a few kinds of output), hard to evaluate. Largely replaced by diffusion for image generation, but still used for super-resolution, style transfer and data augmentation.
bce = nn.BCEWithLogitsLoss()
for real in loader:
    n = real.size(0)
    ones, zeros = torch.ones(n, 1, device=device), torch.zeros(n, 1, device=device)
    fake = G(torch.randn(n, 100, device=device))

    d_loss = bce(D(real), ones) + bce(D(fake.detach()), zeros)   # 1) discriminator: real=1, fake=0
    optD.zero_grad(); d_loss.backward(); optD.step()

    g_loss = bce(D(fake), ones)                                  # 2) generator: make D say "real"
    optG.zero_grad(); g_loss.backward(); optG.step()

7. Diffusion models

  • Idea: gradually destroy an image by adding a little random noise over many steps until it is pure static (the forward process, no learning needed). Then train a network to undo one step: given a noisy image and the step number, predict the noise that was added.
  • Generation: start from pure noise and repeatedly remove the predicted noise, step by step, until a clean image appears. Text prompts steer this using a text encoder (classifier-free guidance).
  • Latent diffusion (Stable Diffusion) does all this in a compressed latent space made by an autoencoder, which makes it far cheaper. The denoiser is a U-Net or a transformer (DiT).
  • Strengths: stable training, high quality, great diversity; also used for video, audio and molecules. Weakness: slower, since it needs many sampling steps (distillation and better samplers cut this to a few).
# one training step of a denoising diffusion model
t     = torch.randint(0, T, (x0.size(0),), device=device)           # random noise level per image
noise = torch.randn_like(x0)
a     = alphas_cumprod[t].view(-1, 1, 1, 1)
xt    = a.sqrt() * x0 + (1 - a).sqrt() * noise                      # the noisy image
loss  = F.mse_loss(model(xt, t), noise)                             # learn to predict the noise

8. Graph neural networks (GNN)

  • Data: things connected to other things: molecules (atoms and bonds), social networks, road maps, knowledge graphs, transaction networks.
  • How it works (message passing): each node gathers the features of its neighbours, combines them (sum / mean / attention), and updates its own representation. After k rounds, a node knows about everything within k hops. Variants: GCN, GraphSAGE, GAT (attention), message-passing networks.
  • Use for: drug and materials discovery, fraud rings, recommendations, traffic forecasting, chip design.
  • Library: PyTorch Geometric (torch_geometric) or DGL.
from torch_geometric.nn import GCNConv

class GCN(nn.Module):
    def __init__(self, inp, hid, out):
        super().__init__()
        self.c1, self.c2 = GCNConv(inp, hid), GCNConv(hid, out)
    def forward(self, x, edge_index):                # edge_index: [2, num_edges] list of connections
        return self.c2(F.relu(self.c1(x, edge_index)), edge_index)

9. Deep reinforcement learning

  • Setting: an agent acts in an environment, gets rewards, and learns a policy to maximise total reward. Neural networks approximate the policy or the value of states.
  • DQN (value-based): a network predicts the future reward (Q-value) of each action; pick the best; learn from a replay buffer of past experience. Good for discrete actions (Atari games).
  • Policy gradient / REINFORCE: directly adjust the policy so actions that led to high return become more likely.
  • Actor-critic, PPO, SAC: an actor chooses actions, a critic estimates how good the situation is, reducing variance. PPO is the common stable choice (robotics, games, and RLHF for language models).
  • Libraries: Gymnasium (environments), Stable-Baselines3, TorchRL, RLlib.
# REINFORCE: make actions that led to high return more likely
dist = torch.distributions.Categorical(logits=policy(state))
action = dist.sample()
loss = -(dist.log_prob(action) * return_).mean()       # return_ = reward collected afterwards

10. Embeddings and contrastive learning

  • Embedding: a learned vector for each item (word, user, product, image). Similar items end up close together. nn.Embedding is a trainable lookup table.
  • Word2vec / GloVe: early word embeddings learned by predicting words from their context.
  • Contrastive learning (SimCLR, CLIP, sentence-transformers): train with pairs. Pull matching pairs together (an image and its caption, two crops of the same photo) and push non-matching ones apart (InfoNCE loss). No labels needed beyond the pairing.
  • Two-tower models: one network embeds users, another embeds items; relevance = dot product. Used with approximate-nearest-neighbour search for recommendation and retrieval at huge scale.
  • Use for: semantic search, retrieval-augmented generation (RAG), recommendations, zero-shot image classification.

11. Transfer learning and fine-tuning

  • Idea: do not train from scratch. Take a model pre-trained on a huge dataset (ImageNet, web text) and adapt it to your small dataset. The early layers already know generally useful features.
  • Feature extraction: freeze the pre-trained body, train only a new final layer. Fast, needs little data.
  • Full fine-tuning: unfreeze everything and train with a small learning rate. Better results, more risk of overfitting and forgetting.
  • Parameter-efficient fine-tuning (LoRA, adapters, prefix tuning): freeze the huge model and train tiny added matrices (often under 1% of the parameters). LoRA adds a low-rank update W + B·A. With QLoRA (4-bit quantised base model) you can fine-tune a multi-billion-parameter LLM on one GPU.
  • Hubs: torchvision.models, timm (image models), Hugging Face Hub (text, vision, audio, multimodal).
from torchvision import models

m = models.resnet18(weights=models.ResNet18_Weights.DEFAULT)    # pre-trained on ImageNet
for p in m.parameters(): p.requires_grad = False                 # freeze the backbone
m.fc = nn.Linear(m.fc.in_features, 5)                            # new head for 5 classes (trainable)
opt = torch.optim.AdamW(m.fc.parameters(), lr=1e-3)

# LLM fine-tuning with LoRA (Hugging Face PEFT)

12. Making models smaller and faster

  • Quantisation: store weights (and activations) in 8-bit or 4-bit integers instead of 32-bit floats: 4-8x smaller, faster on supported hardware, small accuracy loss. (torch.ao.quantization, bitsandbytes, GPTQ/AWQ.)
  • Pruning: remove weights or whole channels that contribute little.
  • Knowledge distillation: train a small "student" to imitate the outputs of a large "teacher" (using soft probabilities), keeping most of the accuracy.
  • Mixed precision: compute in 16-bit (float16 or bfloat16) while keeping critical values in 32-bit.
  • Mixture of experts (MoE): a router sends each token to a few specialised sub-networks, so a model can have huge capacity while using only a fraction of it per token.

PyTorch architecture: what is inside

A PyTorch call passes through several layers, from friendly Python at the top to hand-tuned GPU code at the bottom.

+--------------------------------------------------------------------------+
|  Your code and Python API:  torch, torch.nn, torch.optim, torch.utils.data |
+--------------------------------------------------------------------------+
|  Autograd engine (C++): records the graph, runs backward()                |
+--------------------------------------------------------------------------+
|  Dispatcher (c10): chooses the implementation by device, dtype, layout    |
+--------------------------------------------------------------------------+
|  ATen: the tensor operator library (add, mm, conv2d, softmax, ...)        |
+------------------+------------------+------------------+-----------------+
|  CPU kernels     |  CUDA kernels    |  ROCm / MPS /    |  Compiler path  |
|  MKL, oneDNN     |  cuBLAS, cuDNN,  |  XPU backends    |  torch.compile  |
|  OpenMP          |  NCCL            |                  |                 |
+------------------+------------------+------------------+-----------------+

Follow one operation (c = a @ b) through the stack

ComponentRole
TensorStorage (a flat memory block) + size + strides + dtype + device. Views share storage, which makes slicing and transposing free.
Autograd engineEach differentiable operation creates a grad_fn node. backward() visits nodes in reverse topological order, multiplying local gradients (chain rule), and accumulates them in leaf .grad. It runs in C++ and in multiple threads.
DispatcherOne function name, many implementations. Dispatch keys (autograd, CUDA, CPU, quantized, sparse, batching...) are checked in priority order. This is how features compose without changing your code.
ATen"A Tensor library": the hundreds of operators, each with per-backend kernels. Operators are declared in a central YAML file, and much glue code is generated from it.
Caching memory allocatorKeeps freed GPU memory reserved for reuse, avoiding slow allocations. This is why nvidia-smi shows more memory used than your tensors need; torch.cuda.empty_cache() releases unused blocks.
CUDA streams and async executionGPU kernels are queued and run asynchronously; Python continues immediately. Reading values (.item(), .cpu()) forces a synchronisation.
Distributed (c10d)Collective communication (all-reduce, broadcast) through NCCL on GPUs or Gloo on CPUs, used by DDP and FSDP.
Compiler stack (PyTorch 2)See below.

Eager mode vs torch.compile

By default PyTorch runs in eager mode: each operation executes immediately, one by one. That is easy to debug but leaves speed on the table, because every small operation reads and writes GPU memory. torch.compile (PyTorch 2.0, 2023) keeps eager's user experience but speeds up the model by turning it into fused kernels. 

your Python model
   |   TorchDynamo      watches Python bytecode and captures a graph of tensor operations
   v                    (where it cannot, a "graph break" falls back to normal Python)
FX graph
   |   AOTAutograd      traces the forward AND backward pass ahead of time
   v
TorchInductor           fuses many small ops into one kernel, chooses memory layouts
   v
Triton kernels (GPU)  /  C++ with OpenMP (CPU)

model = torch.compile(model)      # one line; the first call is slow (compilation), later calls are fast
  • Typical speed-ups are 1.3-2x for training and inference with no code change; more with large models and careful use.
  • Related tools: torch.export (capture a full graph for deployment), TorchScript (older, now legacy), ONNX export, ExecuTorch (mobile/edge).

A sanity-check recipe for any new model

  1. Check shapes and dtypes of a batch; look at actual inputs and labels (plot a few images, print some text).
  2. Check the initial loss: for C balanced classes with cross-entropy it should be near ln(C) (about 2.3 for 10 classes).
  3. Overfit one small batch until the loss is near zero.
  4. Train on the full set with a simple baseline model, then add complexity.
  5. Watch both training and validation curves; compare against a trivial baseline.

Quick reference and learning path

The PyTorch recipe

  1. Put data in a Dataset and DataLoader.
  2. Define the model as an nn.Module.
  3. Pick a loss and an optimizer (AdamW is a good start).
  4. Loop: forward → loss → zero_grad → backward → step.
  5. Validate with eval() + no_grad(); save the best checkpoint.
  6. Scale: GPU, mixed precision, torch.compile, DDP.

Which architecture?

  • Tabular: gradient boosting first; MLP if needed.
  • Images: fine-tune a pre-trained ResNet / EfficientNet / ViT.
  • Text: fine-tune a pre-trained transformer; use an LLM for generation.
  • Sequences / sensors: 1-D CNN, GRU/LSTM or transformer.
  • Generate images: diffusion.
  • Graphs: GNN.
  • Decisions with rewards: reinforcement learning.

Suggested learning path

  1. Python and NumPy; the basics of linear algebra, derivatives and probability.
  2. PyTorch tensors, autograd, and a hand-written training loop on a toy problem (like the demos above).
  3. Train an MLP and a CNN on MNIST or CIFAR-10; add augmentation, schedulers, checkpoints.
  4. Transfer learning with a pre-trained image model on your own small dataset.
  5. Sequences and transformers: build the attention block above, then fine-tune a Hugging Face model.
  6. Generative models: an autoencoder, then a small diffusion model.
  7. Engineering: mixed precision, torch.compile, multi-GPU, exporting and serving a model.
  8. Read papers alongside the code (Attention Is All You Need, ResNet, Adam, LoRA) and reproduce a result.
