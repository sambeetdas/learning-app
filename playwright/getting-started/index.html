Install, first script and codegen

This page takes you from an empty folder to a passing Playwright test: installing the package and browsers, choosing between the sync and async APIs, writing a first script and a first pytest test, recording a test with codegen, and pausing a test in the Playwright Inspector. It ends with a recommended project set-up and fixes for the installation problems people hit most often (corporate proxies, missing browsers, long paths on Windows).

Install

You need Python 3.10 or newer (Playwright 1.64 requires it). Always work in a virtual environment so the project's packages and versions are separate from everything else on the machine.

mkdir shopbot-e2e; cd shopbot-e2e
py -m venv .venv
.venv\Scripts\Activate.ps1          # prompt now starts with (.venv)
python -m pip install --upgrade pip
pip install pytest-playwright       # installs playwright + pytest too
playwright install chromium         # downloads the browser build for this version
playwright --version                # Version 1.64.1
mkdir shopbot-e2e && cd shopbot-e2e
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install pytest-playwright
playwright install chromium
playwright --version
pip install pytest-playwright
playwright install --with-deps chromium   # also installs the OS libraries (uses sudo / apt)
# or, in two steps:
playwright install chromium
playwright install-deps chromium

Just want the library, without pytest? pip install playwright. Want the async pytest fixtures? pip install pytest-playwright-asyncio.

What the two install steps actually do

Where do the browsers go? A shared cache per user: %LOCALAPPDATA%\ms-playwright on Windows, ~/.cache/ms-playwright on Linux, ~/Library/Caches/ms-playwright on macOS. Set PLAYWRIGHT_BROWSERS_PATH to use another folder (for example inside a Docker image). Headless Chromium runs on the small Chrome Headless Shell build; headed runs use the full Chromium build.

Branded browsers (channels)

Playwright's own Chromium is the default. To test in the Chrome or Edge that your users actually run, or when your company blocks the browser download, use a channel:

browser = p.chromium.launch(channel="chrome")     # installed Google Chrome
browser = p.chromium.launch(channel="msedge")     # installed Microsoft Edge
pytest --browser-channel chrome

Sync or async API?

Playwright for Python has two APIs with the same methods. The sync API is simpler and is what pytest-playwright uses; choose async when your program already runs on asyncio (a FastAPI app, an async agent, Jupyter) or you want to drive many pages concurrently in one process.

first_sync.py
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto("http://127.0.0.1:8000/products")
    print(page.title())                      # Products - ShopBot
    page.get_by_role("link", name="Ceramic Mug").click()
    print(page.url)                          # http://127.0.0.1:8000/products/1
    browser.close()
first_async.py
import asyncio
from playwright.async_api import async_playwright


async def main():
    async with async_playwright() as p:
        browser = await p.chromium.launch()
        page = await browser.new_page()
        await page.goto("http://127.0.0.1:8000/products")
        print(await page.title())
        await page.get_by_role("link", name="Ceramic Mug").click()
        print(page.url)                      # a property: no await
        await browser.close()

asyncio.run(main())

Your first script, with screenshots

Start ShopBot (or use your own site), then run this script with python first_script.py. It writes two PNG files next to the script.

first_script.py
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=False, slow_mo=300)   # watch it, slowed down
    page = browser.new_page(viewport={"width": 1280, "height": 800})
    page.goto("http://127.0.0.1:8000/products")
    page.screenshot(path="products.png", full_page=True)       # the whole scrollable page

    page.get_by_placeholder("Search products").fill("lamp")
    page.get_by_role("button", name="Search").click()
    page.get_by_role("link", name="Desk Lamp").click()
    page.get_by_role("heading", level=1).screenshot(path="heading.png")   # one element only

    print(page.title(), page.url)        # Desk Lamp - ShopBot http://127.0.0.1:8000/products/3
    browser.close()
  • launch() is headless by default (no window). headless=False shows the window; slow_mo adds a delay (ms) before each operation so you can follow along.
  • page.screenshot(full_page=True) captures the whole page; locator.screenshot() just one element. Pass mask=[locator] to hide changing content and animations="disabled" for stable images.
  • There are no sleeps: click() waits for the button to be ready, and goto() waits for the page's load event.

Your first pytest test

Scripts are good for exploring; tests are what you keep. With pytest-playwright installed, any test that asks for the page fixture receives a fresh page in a fresh context.

tests/test_search.py
import re
from playwright.sync_api import Page, expect


def test_search_finds_the_mug(page: Page):
    page.goto("/products")                                   # relative: uses --base-url
    page.get_by_placeholder("Search products").fill("mug")
    page.get_by_role("button", name="Search").click()

    expect(page).to_have_url(re.compile(r"q=mug"))
    expect(page.get_by_test_id("product-card")).to_have_count(1)
    expect(page.get_by_test_id("result-count")).to_have_text("1 results")


def test_title(page: Page):
    page.goto("/products")
    expect(page).to_have_title("Products - ShopBot")
pytest --base-url http://127.0.0.1:8000
..                                                         [100%]
2 passed in 2.31s

Notice the pattern that every test follows: arrange (go to the page), act (fill, click), assert with expect. The expect assertions retry until the page matches, so they also act as the waits.

Record a test with codegen

Codegen opens a browser and a recorder window. As you click and type, it writes the Python code, choosing the most resilient locator it can find (role, label, text or test id). It is the fastest way to learn the API and to draft a test.

playwright codegen --target python-pytest http://127.0.0.1:8000/products
# useful options
playwright codegen --target python-pytest -o tests/test_recorded.py URL   # write to a file
playwright codegen --device "iPhone 15" URL                               # record on an emulated phone
playwright codegen --save-storage auth.json URL                           # log in once, save cookies
playwright codegen --load-storage auth.json URL                           # start already logged in
playwright codegen --test-id-attribute data-qa URL                        # if your app uses another test id attribute

Targets: python (sync script, the default), python-async and python-pytest. Watch a recording session:

Codegen turns your clicks into code

Recorded code is a draft. Before committing it: give the test a meaningful name, replace the absolute URL with a relative one (so --base-url works), remove redundant clicks before fill, and make sure every important outcome has an expect. The cleaned-up test:

tests/test_recorded.py (after review)
from playwright.sync_api import Page, expect


def test_search_and_open_product(page: Page) -> None:
    page.goto("/products")
    page.get_by_role("textbox", name="Search").fill("mug")
    page.get_by_role("button", name="Search").click()
    expect(page.get_by_test_id("result-count")).to_contain_text("1 results")
    page.get_by_role("link", name="Ceramic Mug").click()
    expect(page.get_by_role("heading", name="Ceramic Mug")).to_be_visible()
Pick locator. The recorder's "Pick locator" button lets you hover any element and copy the locator Playwright would use for it, without recording an action. Great for writing tests by hand.

The Playwright Inspector, page.pause() and PWDEBUG

The Inspector is a debugging window: it shows the current call, highlights the element on the page, lets you step over one action at a time, and has the same "Pick locator" and recorder as codegen. Two ways to open it:

1. page.pause() in your code

def test_checkout(page: Page):
    page.goto("/checkout")
    page.pause()          # opens the Inspector and waits here
    page.get_by_label("Full name").fill("Alice")

Run headed: pytest --headed -k checkout. Press Resume (or step) in the Inspector. Remove pause() before committing.

2. PWDEBUG=1 for the whole run

$env:PWDEBUG = "1"
pytest -s -k checkout
Remove-Item Env:PWDEBUG
PWDEBUG=1 pytest -s -k checkout
set PWDEBUG=1
pytest -s -k checkout

With PWDEBUG=1 the browser runs headed, timeouts are disabled and the Inspector pauses before the first action. -s lets you see print output.

For failures that already happened (especially in CI), the trace viewer is better than the Inspector; it is covered on the debugging and CI page.

Pin your versions (for example in a lock file or requirements.txt) so a new Playwright release does not change browser versions under you, and add test-results/ and .venv/ to .gitignore.

VS Code tips

  • Install the Python extension, run Python: Select Interpreter and choose .venv. Then the Testing view discovers your pytest tests: run or debug one with a click.
  • Set a breakpoint and choose Debug Test: the browser stays where it is while you inspect variables. Add --headed to addopts temporarily, or run with PWDEBUG=1, to see it.
  • To set PWDEBUG for debug runs only, add "env": {"PWDEBUG": "1"} to a debug configuration in .vscode/launch.json ("purpose": ["debug-test"]).
  • The Microsoft "Playwright Test for VS Code" extension targets the Node.js test runner; it does not run Python tests. Use the Python Testing view, and playwright codegen from the terminal for recording.
  • Type hints help: annotate fixtures (page: Page) and VS Code autocompletes every Playwright method and its keyword arguments.

Common mistakes

  • Installing into the global Python. Different projects need different Playwright versions; use one virtual environment per project.
  • Forgetting playwright install after pip install --upgrade playwright. Each release pins new browser builds.
  • Hard-coding http://127.0.0.1:8000 in every test. Use relative URLs and --base-url, so the same tests run against staging.
  • Committing recorded code unchanged. Codegen does not know what matters; add the assertions yourself.
  • Leaving page.pause() or slow_mo in committed code. CI will hang or crawl.
  • Mixing sync and async in one program, or naming your file playwright.py (it shadows the real package: ModuleNotFoundError: No module named 'playwright.sync_api'; 'playwright' is not a package).

Exercises

Write a script that searches ShopBot for "pan", prints the number of results shown on the page, and saves a screenshot of just the first product card. 
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto("http://127.0.0.1:8000/products")
    page.get_by_placeholder("Search products").fill("pan")
    page.get_by_role("button", name="Search").click()
    page.wait_for_url("**/products?q=pan*")
    print(page.get_by_test_id("result-count").inner_text())      # 1 results
    page.get_by_test_id("product-card").first.screenshot(path="first-card.png")
    browser.close()

wait_for_url makes sure the search result page has loaded before reading the count; in a test you would use expect(...).to_have_text("1 results") instead.

Turn that script into a pytest test that runs against any environment and checks that the only card is the Cast Iron Pan. 
from playwright.sync_api import Page, expect


def test_search_pan(page: Page):
    page.goto("/products")
    page.get_by_placeholder("Search products").fill("pan")
    page.get_by_role("button", name="Search").click()
    cards = page.get_by_test_id("product-card")
    expect(cards).to_have_count(1)
    expect(cards).to_contain_text("Cast Iron Pan")

Run it with pytest --base-url http://127.0.0.1:8000 (or put --base-url in addopts).

Rewrite first_sync.py with the async API and open the products page and the chat page concurrently in two pages. 
import asyncio
from playwright.async_api import async_playwright


async def title_of(browser, url):
    page = await browser.new_page()
    await page.goto(url)
    return await page.title()


async def main():
    async with async_playwright() as p:
        browser = await p.chromium.launch()
        titles = await asyncio.gather(
            title_of(browser, "http://127.0.0.1:8000/products"),
            title_of(browser, "http://127.0.0.1:8000/chat"),
        )
        print(titles)        # ['Products - ShopBot', 'Support chat - ShopBot']
        await browser.close()

asyncio.run(main())
Every test in your suite should run with a German locale and a dark colour scheme. Where do you configure that, and how? 
# tests/conftest.py
import pytest


@pytest.fixture(scope="session")
def browser_context_args(browser_context_args):
    return {**browser_context_args, "locale": "de-DE", "color_scheme": "dark"}

Every context (and therefore every page) the plugin creates uses these options. Check one with page.evaluate("navigator.language"), which returns "de-DE".

A colleague's CI job fails with "Executable doesn't exist" right after a dependency bot upgraded Playwright. The job caches ~/.cache/ms-playwright with a fixed key. What happened and how do you fix it?

The new Playwright version expects new browser builds (different folder names, for example chromium-1248), but the restored cache only has the old ones and playwright install was skipped because "the cache hit". Include the Playwright version in the cache key and always run playwright install --with-deps chromium (it only downloads what is missing).
