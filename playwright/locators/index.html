Locators: finding elements

Every test has to find things on the page: the search box, the "Add to cart" button, the third product card. In Playwright you do that with locators. A locator is a description of how to find element(s), for example "the button whose accessible name is Search". It does not hold on to a DOM node; it is re-evaluated every time you act or assert, so it survives re-renders, and it waits for the element to appear.

This page covers which locator to choose, the full get_by_role options, filtering and chaining, strictness errors, iframes and shadow DOM, and ARIA snapshots. The locator playground lets you try locators against a copy of ShopBot's products page.

The locator philosophy

Locate the way a user does

A user does not see div.css-1x9k2 > span:nth-child(3). They see a button labelled "Add to cart", a text box labelled "Email", a heading "Products". Locators built on roles, labels and visible text keep working when developers rename classes or restructure the HTML, and they fail when something a user would notice really changes.

Four properties of a locator

  • Lazy: creating one does nothing; it is resolved when used.
  • Re-resolved: every action looks up the element again (no stale references).
  • Auto-waiting: actions and expect wait for it to appear and be ready.
  • Strict: an action on a locator that matches several elements fails, instead of silently clicking the first.
search = page.get_by_role("button", name="Search")   # nothing happens yet
page.goto("/products")
search.click()                                         # resolved now, waits until clickable
page.goto("/products?q=mug")
search.click()                                         # resolved again on the new page: still works

Accessible locators are also a free accessibility check: if you cannot find your "Search" button by role and name, neither can a screen reader user.

Which locator to use: the priority order

#LocatorUse it forShopBot example

5get_by_alt_text(text) / get_by_title(text)Images by alt; elements (and iframes) by titlepage.get_by_title("Loyalty card")

Rule of thumb. If a person could describe the element in words ("the Search button"), use role, label or text. If they would have to point at it ("that grey box, the second one"), add a test id rather than writing a long CSS path.

get_by_role in depth

get_by_role searches the accessibility tree: the same roles and names that assistive technology sees. Roles come from HTML semantics (a <button> is a button, <a href> a link, <h2> a heading) or from an explicit role="..." attribute. The accessible name comes from the element's text, its <label>, aria-label or aria-labelledby.

Filtering and chaining

Real pages repeat structures: four product cards, each with a heading, a price and a stock line. Start from the repeated item and narrow it down instead of writing one long selector.

ToolKeepsExample
filter(has_text="Lamp")Elements whose text contains the string (or matches a regex), anywhere insidecards.filter(has_text="Lamp") → Desk Lamp card
filter(has_not_text="In stock")Elements that do not contain the text→ Desk Lamp card (out of stock)
filter(has=locator)Elements containing a match of the inner locator (searched inside each element)cards.filter(has=page.get_by_role("heading", name="Desk Lamp"))
filter(has_not=locator)Elements that do not contain itcards.filter(has_not=page.get_by_text("Out of stock")) → 3 cards
filter(visible=True)Only visible elementsUseful when responsive layouts render a hidden mobile and a visible desktop copy
outer.get_by_role(...) (chaining)Matches searched inside each element of the outer locatorcards.filter(has_text="Pan").locator(".price") → "£39.50"
cards = page.get_by_test_id("product-card")
in_stock = cards.filter(has_text="In stock")                         # 3 cards
pan = cards.filter(has=page.get_by_role("heading", name="Cast Iron Pan"))
expect(pan.locator(".price")).to_have_text("£39.50")
pan.get_by_role("link").click()                                      # exactly one link: no strictness error

Narrowing down step by step

Inner locators are relative. In filter(has=page.get_by_role("heading")) the inner locator is written with page. but is searched inside each card, not across the page. It must not start from a different page or frame.

nth, first, last, and_ and or_

cards = page.get_by_test_id("product-card")
cards.first                    # Ceramic Mug card
cards.nth(1)                   # Cast Iron Pan card (0-based)
cards.last                     # Notebook Set card
cards.nth(-1)                  # also the last one

# and_: both must match the same element
page.get_by_role("button").and_(page.get_by_text("Search"))        # the Search button, not the label

# or_: either one (handy when the UI can be in two states)
login_or_user = page.get_by_role("link", name="Log in").or_(page.get_by_test_id("user-name"))
expect(login_or_user).to_be_visible()

# iterate over all matches (no waiting: make sure the list has loaded first)
expect(cards).to_have_count(4)
for card in cards.all():
    print(card.get_by_role("heading").inner_text())
print(cards.get_by_role("heading").all_inner_texts())   # ['Ceramic Mug', 'Cast Iron Pan', 'Desk Lamp', 'Notebook Set']
Use position sparingly. first and nth() silence the strictness check. They are right when order is part of what you test ("the newest message is first"), and wrong as a quick fix for "it matched two things"; that usually means your locator is not specific enough. If you use or_ and both sides can be visible at once, add .first to avoid a strict mode violation.

Strictness violations

Actions such as click(), fill() and inner_text() need exactly one element. If the locator matches more, Playwright stops with an error that lists the candidates and suggests a unique locator for each ("aka"). This is the real output on ShopBot:

page.get_by_test_id("product-card").click()
playwright._impl._errors.Error: Locator.click: Error: strict mode violation: get_by_test_id("product-card") resolved to 4 elements:
    1) <article class="card" data-testid="product-card">…</article> aka get_by_text("Ceramic Mug£12.00In stock")
    2) <article class="card" data-testid="product-card">…</article> aka get_by_text("Cast Iron Pan£39.50In stock")
    3) <article class="card" data-testid="product-card">…</article> aka get_by_text("Desk Lamp£24.99Out of stock")
    4) <article class="card" data-testid="product-card">…</article> aka get_by_text("Notebook Set£9.50In stock")

Call log:
  - waiting for get_by_test_id("product-card")

Fixes, best first: make the locator more specific (a role with a name, filter(has=...), chaining inside a container); assert on the whole list (expect(cards).to_have_count(4) works on many elements); and only if order matters, first / nth().

When nothing matches, actions do not fail immediately; they wait for the element to appear (default 30 s) and then raise a timeout:

playwright._impl._errors.TimeoutError: Locator.click: Timeout 30000ms exceeded.
Call log:
  - waiting for get_by_role("button", name="Buy now")

CSS and XPath (and why they are the last resort)

page.locator(".price")                     # CSS
page.locator("article h2 a")               # CSS descendant
page.locator("[data-testid=product-card]") # attribute (get_by_test_id is clearer)
page.locator("xpath=//article//a")         # XPath (prefix optional when it starts with //)
page.locator("article", has_text="Out of stock").get_by_role("link")   # mix: CSS + filter + role
  • CSS and XPath describe the structure, which changes far more often than the visible UI. div:nth-child(3) > span breaks when a banner is added.
  • CSS in Playwright pierces open shadow roots; XPath does not.
  • Avoid generated class names (.css-1x9k2, .sc-AxjAm): they change with every build.
  • Old selector strings such as "text=Search" and "button >> nth=1" still work, but the get_by_* methods are clearer and are what codegen produces.

Iframes and shadow DOM

Iframes

An iframe is a separate document, so page-level locators do not see inside it. ShopBot's account page has a "Loyalty card" iframe with a Redeem button:

# after logging in
card = page.frame_locator("iframe[title='Loyalty card']")
expect(card.locator("#points")).to_have_text("120")
card.get_by_role("button", name="Redeem").click()
expect(card.locator("#points")).to_have_text("0")

# the same, starting from a user-facing locator for the iframe element
frame = page.get_by_title("Loyalty card").content_frame
expect(frame.get_by_role("button", name="Redeem")).to_be_visible()

Shadow DOM

Web components hide their internals in a shadow root. Playwright's role, text, label, test id and CSS locators pierce open shadow roots automatically; you write the locator as if the shadow boundary was not there. (Closed shadow roots cannot be reached, by design.)

# <promo-banner> renders <p>10% off mugs</p><button>Claim offer</button> inside an open shadow root
page.get_by_role("button", name="Claim offer").click()   # works
page.locator("promo-banner button").count()              # 1: CSS pierces too
page.locator("xpath=//promo-banner//button").count()     # 0: XPath does not

ARIA snapshots

locator.aria_snapshot() returns the accessibility tree under an element as YAML: roles, names and states, without any CSS or markup noise. It is the same structure the Playwright MCP server shows to AI agents, and a fast way to see which roles and names you can use. This is the real output for ShopBot's search form and first product card:

print(page.get_by_role("search").aria_snapshot())

- search:
  - text: Search
  - textbox "Search":
    - /placeholder: Search products
  - text: Category
  - combobox "Category":
    - option "All" [selected]
    - option "Kitchen"
    - option "Office"
  - button "Search"
print(page.get_by_test_id("product-card").first.aria_snapshot())

- article:
  - heading "Ceramic Mug" [level=2]:
    - link "Ceramic Mug":
      - /url: /products/1
  - paragraph: £12.00
  - paragraph: In stock

Assert on structure with to_match_aria_snapshot. The template is matched partially: you list what matters, in order, and may leave out children, attributes and names; text values can be regular expressions.

expect(page.get_by_role("search")).to_match_aria_snapshot("""
  - search:
    - textbox "Search"
    - combobox "Category"
    - button "Search"
""")
expect(page.get_by_test_id("product-card").first).to_match_aria_snapshot("""
  - article:
    - heading "Ceramic Mug" [level=2]
    - paragraph: /£\\d+\\.\\d{2}/
    - paragraph: In stock
""")

Failure messages from expect also include an ARIA snapshot of the page, which shows at a glance what was there instead.

Common mistakes

  • Copying a CSS path from DevTools (#root > div > div:nth-child(2) > button). Use codegen's "Pick locator" or write a role locator.
  • Silencing strictness with .first and then clicking the wrong one of two "Delete" buttons. Narrow down by container instead.
  • Forgetting the name is a substring. get_by_role("button", name="Log") also matches "Log out"; add exact=True when names overlap.
  • Matching by translated or dynamic text in a multi-language app. Use test ids (or run with a fixed locale) for those.
  • Looking inside an iframe with a page locator. Use frame_locator() or content_frame.
  • Iterating with all() before the list has loaded. all() and count() do not wait; assert the count first.
  • Using page.query_selector() / ElementHandles from old tutorials. They are not auto-waiting and go stale; use locators.

Exercises

Try your answers in the playground first, then check them against the solutions.

On /products, write a locator for the price of the Desk Lamp, without CSS classes. 
lamp = page.get_by_test_id("product-card").filter(has=page.get_by_role("heading", name="Desk Lamp"))
expect(lamp.get_by_text("£")).to_have_text("£24.99")

Inside one card only one element contains "£", so get_by_text("£") is unique there.

page.get_by_text("Search").click() fails with a strict mode violation. Why, and what are two better locators?

"Search" is the text of the search box's <label> and of the button, so 2 elements match. Use page.get_by_role("button", name="Search"), or if you really mean text, page.get_by_role("button").and_(page.get_by_text("Search")).

Get the names of all products that are in stock, as a Python list. 
in_stock = page.get_by_test_id("product-card").filter(has_not_text="Out of stock")
names = in_stock.get_by_role("heading").all_inner_texts()
print(names)    # ['Ceramic Mug', 'Cast Iron Pan', 'Notebook Set']
The nav shows "Log in" for guests and the user's name (data-testid="user-name") after login. Write one assertion that passes in both states, and one that proves the user is logged in. 
expect(page.get_by_role("link", name="Log in").or_(page.get_by_test_id("user-name"))).to_be_visible()
expect(page.get_by_test_id("user-name")).to_have_text("Alice")
On /products/1, check that there are exactly two reviews and that the first one mentions coffee. 
reviews = page.get_by_role("list", name="Reviews").get_by_role("listitem")
expect(reviews).to_have_count(2)
expect(reviews.first).to_contain_text("coffee")
Write an ARIA snapshot assertion for ShopBot's main navigation that checks the order of the first three links and nothing else. 
expect(page.get_by_role("navigation", name="Main")).to_match_aria_snapshot("""
  - navigation "Main":
    - link "ShopBot"
    - link "Products"
    - link "Support chat"
""")

Partial matching lets the template omit the later links and the /url children.
