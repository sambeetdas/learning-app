Actions, auto-waiting and assertions

Once you can find an element, you do something with it (an action: click, fill, check, select, upload) and then check the result (an assertion). Playwright's big idea is that both wait automatically: an action waits until the element is ready to receive it, and an expect assertion keeps re-checking until the page shows what you expect. That is why good Playwright tests contain no sleep calls at all.

This page lists the actions, explains exactly what Playwright waits for before each one (with an animation), shows web-first assertions versus plain assert, and covers timeouts, waiting for navigation and network responses, and the anti-patterns that make tests flaky.

Auto-waiting and actionability checks

Before an action, Playwright resolves the locator to exactly one element and runs actionability checks. If a check fails, it does not give up: it waits and retries (after 20 ms, 100 ms, 100 ms, then every 500 ms) until all checks pass or the action timeout (30 s by default) runs out.

CheckPasses when
AttachedThe locator resolves to one element that is in the DOM (zero: keep waiting; several: strict mode violation)
VisibleIt has a non-empty bounding box and not visibility:hidden. display:none and zero size are not visible; opacity:0 counts as visible
StableIts bounding box was the same for two consecutive animation frames (not sliding in or animating)
Receives eventsIt is the hit target at the click point: no overlay, spinner, cookie banner or sticky header on top of it
EnabledNot disabled (also not inside a disabled <fieldset> or under aria-disabled="true")
EditableEnabled and not readonly / aria-readonly="true" (only for typing actions)

Escape hatches: force and trial

page.get_by_role("button", name="Add to cart").click(trial=True)   # run the checks, do not click
page.get_by_role("button", name="Add to cart").click(force=True)   # skip non-essential checks

trial=True is useful to wait until something could be clicked. force=True bypasses the checks that protect you from clicking through an overlay or on a disabled button; if you need it, a real user probably could not do what your test does. Fix the page or the test (close the cookie banner first) instead.

Web-first assertions versus plain assert

A web-first assertion takes a locator or page, not a value: expect(locator).to_have_text("..."). It re-reads the page until the condition holds or the timeout (5 s by default) expires. A plain assert reads the value once, at whatever moment the line runs.

# flaky: reads the text once, immediately
page.get_by_role("button", name="Send").click()
assert "[shipping]" in page.get_by_test_id("bot-message").inner_text()
# reliable: retries until the streamed answer contains it
page.get_by_role("button", name="Send").click()
expect(page.get_by_test_id("bot-message")).to_contain_text("[shipping]")

Add your own message as the second argument: expect(page.get_by_role("status"), "the cart confirmation should appear").to_have_text("Added to cart"); it becomes the first line of the error.

When is plain assert fine? For values that are already settled and not on the page: the JSON of an API response, a file you downloaded, a list you collected after an expect(...).to_have_count(n). For anything that the page shows, use expect.

The assertions

Every assertion has a negated form with not_: to_be_visible() / not_to_be_visible(), to_have_text() / not_to_have_text(). The negated form also waits: it passes as soon as the condition becomes false.

Python has no built-in soft assertions (that continue after a failure); the pytest-check plugin provides them. Screenshot comparison (to_have_screenshot) exists only in the Node.js runner; see the advanced page for Python alternatives.

Timeouts

TimeoutDefaultApplies toChange it
Action30 sclick, fill, inner_text, wait_for...page.set_default_timeout(10_000) or context.set_default_timeout(...); per call click(timeout=5_000)
Navigation30 sgoto, reload, wait_for_url, go_backpage.set_default_navigation_timeout(20_000); per call goto(url, timeout=...)
Assertion5 sEvery expect(...)expect.set_options(timeout=7_000) globally; per call to_have_text("...", timeout=10_000)
Whole testnoneA pytest testThe pytest-timeout plugin (--timeout 120)

Values are milliseconds (a datetime.timedelta also works). timeout=0 means wait forever, which is rarely what you want. To set suite-wide defaults with pytest-playwright:

tests/conftest.py
import pytest
from playwright.sync_api import expect

expect.set_options(timeout=7_000)          # every expect() in the suite


@pytest.fixture(autouse=True)
def default_timeouts(context):
    context.set_default_timeout(10_000)             # actions such as click() and fill()
    context.set_default_navigation_timeout(20_000)  # goto(), reload(), wait_for_url()
Do not "fix" flakiness by raising timeouts. A longer timeout only helps when the app is legitimately slow (a report that takes 15 s). If a test fails at 5 s and passes at 30 s, find out what it is waiting for.

Waiting for navigation and network

Most of the time you need nothing special: goto() waits for the load event, and the next expect waits for the new page's content. When you need more control:

import re

# 1. After a click that navigates: wait for the URL (glob or regex)
page.get_by_role("button", name="Log in").click()
page.wait_for_url("**/account")
expect(page).to_have_url(re.compile(r".*/account"))     # usually enough on its own

# 2. Wait for a specific response triggered by an action
with page.expect_response(lambda r: r.url.endswith("/api/cart") and r.request.method == "POST") as info:
    page.get_by_role("button", name="Add to cart").click()
response = info.value
assert response.ok and response.json()["count"] >= 1      # settled data: plain assert is fine

# 3. Downloads, pop-ups and dialogs are events too
with page.expect_download() as dl:
    page.get_by_role("link", name="Download invoice").click()
print(dl.value.suggested_filename)                        # invoice-123456.txt

page.once("dialog", lambda dialog: dialog.accept())       # register BEFORE the click
page.get_by_role("button", name="Delete account").click()
expect(page.get_by_text("Account scheduled for deletion")).to_be_visible()

# 4. Load states (rarely needed)
page.goto("/products", wait_until="domcontentloaded")     # commit | domcontentloaded | load | networkidle
page.wait_for_load_state("load")
ToolUse when
expect(page).to_have_url(...)You want to check where you landed (it waits)
page.wait_for_url(...)A script (not a test) must not continue until the URL changes
page.expect_response(...) / expect_request(...)You need the response data, or the UI gives no visible sign that a request finished
locator.wait_for(state="visible" | "hidden" | "attached" | "detached")Scripts that must wait for an element without asserting (in tests prefer expect)
page.wait_for_load_state()After something opened a page you did not navigate yourself (for example a pop-up from expect_popup)

Why networkidle is discouraged

wait_until="networkidle" waits until there have been no network connections for 500 ms. The official docs mark it as discouraged for testing: pages with analytics beacons, polling, long-polling, WebSockets or streaming (like ShopBot's chat) may never become idle, or become idle before your data has arrived; and it always costs at least half a second. It tests the network, not what the user sees. Wait for the thing you care about instead: expect(page.get_by_test_id("result-count")).to_be_visible().

Exercises

Write a test that adds 3 Ceramic Mugs to the cart and checks the confirmation and the cart counter in the navigation (start with an empty cart). 
from playwright.sync_api import Page, expect


def test_add_three_mugs(page: Page):
    page.goto("/products/1")
    page.get_by_label("Quantity").fill("3")
    page.get_by_role("button", name="Add to cart").click()
    expect(page.get_by_role("status")).to_have_text("Added to cart")
    expect(page.get_by_test_id("cart-count")).to_have_text("3")

Each test gets a new context, so the cart starts empty and the count is exactly 3.

The checkout form is submitted with an invalid email and no postcode, by a new user with an empty cart. Assert all the error messages at once. 
def test_checkout_validation(page: Page):
    page.goto("/checkout")
    page.get_by_label("Full name").fill("Alice")
    page.get_by_label("Email").fill("not-an-email")
    page.get_by_label("I accept the terms").check()
    page.get_by_role("button", name="Place order").click()
    expect(page.get_by_role("alert").get_by_role("listitem")).to_have_text(
        ["Enter a valid email", "Postcode is required", "Your cart is empty"])

to_have_text with a list checks every item, in order, and waits until they all match.

This chat test (below) is flaky. Explain why and fix it. 
page.get_by_role("button", name="Send").click()
time.sleep(1)
answer = page.get_by_test_id("bot-message").inner_text()
assert "30 days" in answer

The sleep guesses how long the streamed answer takes; on a slow machine (or with a real LLM) 1 s is not enough, and on a fast one it wastes time. The read happens once. Wait for the outcome instead, and for the stream to finish if you need the complete text:

page.get_by_label("Your question").fill("How do returns work?")
page.get_by_role("button", name="Send").click()
bot = page.get_by_test_id("bot-message")
expect(bot).to_have_attribute("aria-busy", "false")    # streaming finished
expect(bot).to_contain_text("30 days")
On the account page, test that cancelling the "Delete account" confirmation keeps the account. 
def test_cancel_delete(page: Page):
    page.goto("/login")
    page.get_by_label("Email").fill("alice@example.com")
    page.get_by_label("Password").fill("wonderland")
    page.get_by_role("button", name="Log in").click()
    expect(page).to_have_url(re.compile(r"/account$"))

    page.once("dialog", lambda dialog: dialog.dismiss())
    page.get_by_role("button", name="Delete account").click()
    expect(page.get_by_text("Deletion cancelled")).to_be_visible()
Check that clicking "Add to cart" sends a POST to /api/cart with the quantity you entered, and that the server answers 200. 
def test_add_to_cart_request(page: Page):
    page.goto("/products/2")
    page.get_by_label("Quantity").fill("2")
    with page.expect_request("**/api/cart") as req_info:
        page.get_by_role("button", name="Add to cart").click()
    request = req_info.value
    assert request.method == "POST"
    assert request.post_data_json == {"product_id": 2, "qty": 2}
    assert request.response().status == 200
