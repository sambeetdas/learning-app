Beyond testing: scraping, automation and monitoring

Everything that makes Playwright good for testing (a real browser, auto-waiting, locators that survive layout changes, network control) also makes it a general browser automation tool. Teams use it to pull data from JavaScript-heavy sites, to fill in forms in internal tools that have no API, to turn HTML into PDF invoices and screenshots, and to run a synthetic user against production every few minutes.

This page covers those jobs with working Python against ShopBot, and the responsibilities that come with them: respecting robots.txt, terms and rate limits, not defeating protections you are not authorised to bypass, and recognising when a plain HTTP client is the better tool.

What people automate with Playwright

Price and catalogue monitoringTrack your own products across your storefronts, or competitors' public prices where their terms allow it.
Data extraction for analysisExport tables from dashboards and portals that only offer an HTML view.
RPA in internal toolsFill the same form in a legacy admin system 300 times from a spreadsheet; download the monthly report.
Invoices and reports as PDFRender an HTML template with the browser's print engine: proper fonts, CSS, page numbers.
Screenshots and social cardsThumbnails of user pages, Open Graph images, documentation screenshots kept up to date.
Synthetic monitoringLog in, search, add to cart and chat every 5 minutes in production; alert on failure or slowness.
Archiving and complianceCapture what a page showed on a date (screenshot + HTML + PDF) for audit trails.
Feeding AI systemsCollect clean text from your own help centre for a RAG index; give an agent a browser.

Scraping responsibly

Being technically able to load a page does not make it acceptable to harvest it. Before you write a scraper, check these, in this order:

CheckWhat to do
Is there an API or export?Prefer an official API, data feed or bulk download. It is faster, stable and clearly permitted.
Terms of serviceMany sites forbid automated access or reuse of their content. If the terms say no, the answer is no (or ask for permission). Logging in usually means you accepted those terms.
robots.txtHonour Disallow rules and Crawl-delay for your user agent. It is a convention, not a licence: an allowed path can still be forbidden by the terms.
Personal dataNames, emails, profiles: data protection law (GDPR, UK GDPR and others) applies even when the data is public. Collect only what you need, have a lawful basis, and secure it.
Copyright and database rightsFacts may be free to use; articles, images and curated databases often are not.
LoadOne request at a time (or a small fixed number), a delay between requests, back off on 429/503, run off-peak, cache what you have already fetched.
Identify yourselfUse a descriptive user agent with a contact address, so the site owner can reach you instead of blocking you.
This page is not legal advice. For anything beyond your own sites or clearly permitted public data, ask your legal or data-protection team first.

A polite scraper, a hybrid login and a throttled response

Checking robots.txt and setting a user agent

The standard library's urllib.robotparser reads the rules. A missing robots.txt (404) means "no rules", so can_fetch returns True; a 401/403 makes it return False for everything.

scrape_products.py
import csv
import time
from urllib import robotparser
from urllib.parse import urljoin
from playwright.sync_api import sync_playwright

BASE = "http://127.0.0.1:8000"
USER_AGENT = "ShopBotCatalogueBot/1.0 (+mailto:data-team@example.com)"
DELAY = 1.0                                     # seconds between page loads

def allowed(url: str) -> bool:
    rp = robotparser.RobotFileParser(urljoin(BASE, "/robots.txt"))
    rp.read()                                   # 404 = no rules = everything allowed
    return rp.can_fetch(USER_AGENT, url)

def scrape(path: str = "/products", out: str = "products.csv") -> list[dict]:
    url = urljoin(BASE, path)
    if not allowed(url):
        raise SystemExit(f"robots.txt disallows {url}")
    with sync_playwright() as p:
        browser = p.chromium.launch()
        context = browser.new_context(user_agent=USER_AGENT)
        page = context.new_page()
        page.goto(url)
        rows = []
        for card in page.get_by_test_id("product-card").all():
            link = card.get_by_role("link")
            rows.append({
                "name": link.inner_text(),
                "url": urljoin(BASE, link.get_attribute("href")),
                "price": float(card.locator(".price").inner_text().lstrip("£")),
                "in_stock": card.get_by_text("In stock", exact=True).count() == 1,
            })
        for row in rows:                        # detail pages: one at a time, with a delay
            time.sleep(DELAY)
            page.goto(row["url"])
            reviews = page.get_by_role("list", name="Reviews").get_by_role("listitem")
            row["reviews"] = reviews.filter(has_not_text="No reviews yet").count()
        browser.close()
    with open(out, "w", newline="", encoding="utf-8") as f:
        writer = csv.DictWriter(f, fieldnames=list(rows[0]))
        writer.writeheader()
        writer.writerows(rows)
    return rows

if __name__ == "__main__":
    scrape()
# products.csv

Rate limiting and backing off

Wrap navigation in a small helper that enforces a minimum gap between requests and respects 429 Too Many Requests / 503 with their Retry-After header.

import time
from playwright.sync_api import Page

class PoliteBrowser:
    """page.goto with a minimum delay between requests and Retry-After handling."""
    def __init__(self, page: Page, min_delay: float = 1.0, max_retries: int = 3):
        self.page, self.min_delay, self.max_retries, self._last = page, min_delay, max_retries, 0.0

    def goto(self, url: str):
        for attempt in range(self.max_retries + 1):
            wait = self.min_delay - (time.monotonic() - self._last)
            if wait > 0:
                time.sleep(wait)
            self._last = time.monotonic()
            response = self.page.goto(url)
            if response is None or response.status not in (429, 503):
                return response
            retry_after = response.headers.get("retry-after", "")
            time.sleep(int(retry_after) if retry_after.isdigit() else 2 ** attempt * 5)
        raise RuntimeError(f"gave up on {url}: still throttled")

response.headers has lower-case keys. If a site keeps returning 429 at one request per second, it is telling you to slow down further or stop.

Extracting tables to CSV

HTML tables are the most common thing people want out of a portal. Two approaches: locators (readable, auto-waiting) or one evaluate call (fast for big tables, because it is a single round trip to the browser).

import csv
from playwright.sync_api import Locator

def table_to_csv(table: Locator, path: str) -> list[list[str]]:
    headers = table.locator("thead th").all_inner_texts()
    rows = [row.locator("td").all_inner_texts() for row in table.locator("tbody tr").all()]
    with open(path, "w", newline="", encoding="utf-8") as f:
        writer = csv.writer(f)
        writer.writerow(headers)
        writer.writerows(rows)
    return [headers] + rows

page.goto("/cart")
table_to_csv(page.get_by_role("table"), "cart.csv")
# [['Product', 'Qty', 'Price'], ['Ceramic Mug', '2', '£24.00'], ['Notebook Set', '3', '£28.50']]

    "t => [...t.rows].map(r => [...r.cells].map(c => c.innerText.trim()))"
)

Before running any extraction, wait for the data to be there. A web-first assertion such as expect(page.locator("tbody tr")).not_to_have_count(0) avoids scraping an empty table that has not loaded yet.

Pagination and infinite scroll

ShopBot fits on one page, so these two patterns are generic; both were tested against small fake pages served with page.route.

"Next" links

from urllib.parse import urljoin

def scrape_paginated(page, start_url: str) -> list[str]:
    items, url = [], start_url
    while url:
        page.goto(url)
        items += page.locator(".item").all_inner_texts()
        nxt = page.get_by_role("link", name="Next")
        url = (urljoin(page.url, nxt.get_attribute("href"))
               if nxt.count() else None)
    return items

Add a page limit and a visited set for safety: some sites loop. If the URL has ?page=N, generating URLs directly is simpler still.

Infinite scroll

from playwright.sync_api import expect

def scroll_until_done(page, items, max_rounds=50):
    previous = -1
    for _ in range(max_rounds):
        count = items.count()
        if count == previous:
            break
        previous = count
        page.mouse.wheel(0, 10_000)
        try:   # wait for new items, not a fixed sleep
            expect(items).not_to_have_count(count, timeout=3_000)
        except AssertionError:
            break          # nothing more arrived
    return items.all_inner_texts()

posts = scroll_until_done(page, page.locator(".post"))
An infinite-scroll page almost always fetches JSON as you scroll. Open the network tab (or page.on("response", ...)): calling that endpoint directly, if the terms allow, is faster and more reliable than scrolling. page.expect_response("**/api/feed*") lets you capture those JSON bodies while scrolling.

Handling logins

Log in once through the UI, save the cookies and local storage with storage_state, and reuse them on every later run. Keep credentials in environment variables or a secrets manager, never in the script, and never commit state.json (it is as good as a password).

import os
from playwright.sync_api import expect

STATE = "state.json"            # add to .gitignore

def logged_in_context(browser, base_url="http://127.0.0.1:8000"):
    if os.path.exists(STATE):
        return browser.new_context(storage_state=STATE, base_url=base_url)
    context = browser.new_context(base_url=base_url)
    page = context.new_page()
    page.goto("/login")
    page.get_by_label("Email").fill(os.environ["SHOP_USER"])
    page.get_by_label("Password").fill(os.environ["SHOP_PASSWORD"])
    page.get_by_role("button", name="Log in").click()
    expect(page.get_by_test_id("user-name")).to_be_visible()
    context.storage_state(path=STATE)
    page.close()
    return context

context = logged_in_context(browser)
page = context.new_page()
page.goto("/products")
page.request.post("/api/cart", data={"product_id": 1, "qty": 2})   # shares the login cookies

If the saved session has expired, the site redirects to /login: detect that (if "/login" in page.url), delete the state file and log in again. For sites with multi-factor authentication or SSO, log in by hand once in a headed browser and save the state; do not automate around MFA. The network and authentication page covers storage state in depth.

Concurrency with the async API

Most automation time is spent waiting for the network. With playwright.async_api one Python process can drive several pages at once: create one coroutine per URL and run them with asyncio.gather. Always cap concurrency with an asyncio.Semaphore; without it, 500 URLs open 500 tabs, exhaust memory and hammer the site.

import asyncio
from playwright.async_api import async_playwright

BASE = "http://127.0.0.1:8000"
MAX_PAGES = 3                         # concurrent pages: tune for your machine and the site

async def scrape_product(context, sem: asyncio.Semaphore, pid: int) -> dict:
    async with sem:                   # wait here until one of the 3 slots is free
        page = await context.new_page()
        try:
            response = await page.goto(f"/products/{pid}")
            if not response or not response.ok:
                raise RuntimeError(f"product {pid}: HTTP {response.status if response else '?'}")
            name = await page.get_by_role("heading", level=1).inner_text()
            price = await page.locator(".price").first.inner_text()
            return {"id": pid, "name": name, "price": price}
        finally:
            await page.close()
            await asyncio.sleep(0.5)  # politeness delay while still holding the slot

async def main(ids: list[int]) -> None:
    async with async_playwright() as p:
        browser = await p.chromium.launch()
        context = await browser.new_context(base_url=BASE)
        sem = asyncio.Semaphore(MAX_PAGES)
        results = await asyncio.gather(
            *(scrape_product(context, sem, i) for i in ids),
            return_exceptions=True,   # one failure must not cancel the rest
        )
        await browser.close()
    for r in results:
        print("FAILED" if isinstance(r, Exception) else "ok", r)

asyncio.run(main([1, 2, 3, 4, 99]))

asyncio.gather with a semaphore: who runs when

ChoiceWhen
Pages in one context (above)Same user, shared cookies; cheapest. Fine for public pages and a single logged-in account.
One context per taskTasks must not share cookies or storage (different accounts, clean sessions). Contexts are cheap (milliseconds), browsers are not.
Several processes (multiprocessing, a job queue)CPU-bound extraction, thousands of URLs, or crash isolation. Each process has its own browser.

Playwright objects belong to the event loop (async) or thread (sync) that created them. Do not share a sync page between threads; use the async API, or one Playwright instance per thread or process.

Screenshots and PDFs for reports and invoices

The browser is an excellent rendering engine: you design the document in HTML and CSS, and Chromium's print pipeline produces a PDF with real text, fonts and page breaks. page.pdf() works only in Chromium (headless or headed with a Chromium-based browser); Firefox and WebKit raise an error.

invoice_pdf.py
import html
from playwright.sync_api import sync_playwright

INVOICE = """<!doctype html><html><head><meta charset="utf-8"><style>
  body {{ font-family: system-ui; margin: 0; }}  h1 {{ color: #2563eb; }}
  table {{ width: 100%; border-collapse: collapse; }}
  td, th {{ border-bottom: 1px solid #ddd; padding: 6px; text-align: left; }}
</style></head><body>
<h1>Invoice {number}</h1><p>Customer: {customer}</p>
<table><tr><th>Item</th><th>Qty</th><th>Price</th></tr>{rows}</table>
<p><strong>Total: &pound;{total:.2f}</strong></p></body></html>"""

FOOTER = ('<div style="font-size:8px;width:100%;text-align:center">'
          'Page <span class="pageNumber"></span> of <span class="totalPages"></span></div>')

def render_invoice(page, number: str, customer: str, lines, path: str) -> None:
    rows = "".join(f"<tr><td>{html.escape(n)}</td><td>{q}</td><td>&pound;{p * q:.2f}</td></tr>"
                   for n, q, p in lines)
    total = sum(q * p for _, q, p in lines)
    page.set_content(INVOICE.format(number=number, customer=html.escape(customer), rows=rows, total=total))
    page.pdf(path=path, format="A4", print_background=True,
             display_header_footer=True, header_template="<span></span>", footer_template=FOOTER,
             margin={"top": "20mm", "bottom": "20mm"})

with sync_playwright() as p:
    browser = p.chromium.launch()                 # PDF generation: Chromium only
    page = browser.new_page()
    render_invoice(page, "INV-1001", "Alice Example",
                   [("Ceramic Mug", 2, 12.0), ("Notebook Set", 1, 9.5)], "invoice.pdf")
    pdf_bytes = page.pdf()                        # without path: returns bytes (e.g. for an HTTP response)
    browser.close()

html.escape matters: customer names come from users, and unescaped HTML in a template can inject markup or scripts into your own document renderer. Do not render templates from untrusted URLs with network access on a server; use set_content with your own HTML.

RPA: filling forms and downloading files

Robotic process automation is the same code as an end-to-end test, run for its effect instead of its assertions. Keep the assertions anyway: they are how the robot knows a step really worked before it moves on. Here the robot places a ShopBot order and downloads the invoice.

place_order.py
from pathlib import Path
from playwright.sync_api import sync_playwright, expect

def place_order_and_download(page, customer: dict, out_dir: Path) -> tuple[str, Path]:
    page.goto("/products/1")
    page.get_by_label("Quantity").fill("2")
    page.get_by_role("button", name="Add to cart").click()
    expect(page.get_by_role("status")).to_have_text("Added to cart")

    page.goto("/checkout")
    page.get_by_label("Full name").fill(customer["name"])
    page.get_by_label("Email").fill(customer["email"])
    page.get_by_label("Postcode").fill(customer["postcode"])
    page.get_by_label("I accept the terms").check()
    page.get_by_role("button", name="Place order").click()
    expect(page.get_by_role("heading", name="Thank you!")).to_be_visible()   # do not continue on an error page
    order_id = page.get_by_test_id("order-id").inner_text()

    with page.expect_download() as info:
        page.get_by_role("link", name="Download invoice").click()
    download = info.value
    target = out_dir / download.suggested_filename          # "invoice-275215.txt"
    download.save_as(target)
    return order_id, target

with sync_playwright() as p:
    browser = p.chromium.launch()
    context = browser.new_context(base_url="http://127.0.0.1:8000")
    page = context.new_page()
    out = Path("invoices"); out.mkdir(exist_ok=True)
    order_id, file = place_order_and_download(
        page, {"name": "Alice Example", "email": "alice@example.com", "postcode": "SW1A 1AA"}, out)
    print(order_id, file.read_text())          # Invoice for order 275215
    browser.close()

For a batch (rows from a CSV or spreadsheet), process one row per fresh page or context, record each outcome (done, failed: reason) in an output file, and make the job resumable so a crash at row 180 does not resubmit rows 1 to 179. Uploads use locator.set_input_files("report.pdf").

RPA against systems you do not own needs the owner's permission. On your own internal tools, ask whether a small API endpoint would be cheaper than maintaining a robot: UI robots break when the page changes.

Synthetic monitoring

A synthetic monitor is a short, critical user journey run on a schedule against production (or staging). It catches what uptime pings miss: the home page returns 200 but search is broken, the cart button does nothing, or the AI chat never answers. Each run records timings per step, and an alert fires after N consecutive failures (one failure is often a network blip; alerting on every one teaches people to ignore alerts).

The monitoring loop: runs, metrics, alerts and recovery

monitor.py
"""Synthetic monitor: run a short user journey, record timings, alert after repeated failures."""
import json
import os
import time
from datetime import datetime, timezone
from pathlib import Path
from typing import Protocol

import httpx
from playwright.sync_api import sync_playwright, expect

BASE = os.getenv("BASE", "https://shop.example.com")
FAIL_THRESHOLD = 2
STATE = Path("monitor-state.json")
METRICS = Path("metrics.jsonl")

class Notifier(Protocol):
    def send(self, text: str) -> None: ...

class SlackNotifier:
    def __init__(self, webhook_url: str):
        self.url = webhook_url
    def send(self, text: str) -> None:
        httpx.post(self.url, json={"text": text}, timeout=10).raise_for_status()

def run_journey(base_url: str) -> dict:
    timings, step = {}, "start"
    with sync_playwright() as p:
        browser = p.chromium.launch()
        context = browser.new_context(base_url=base_url)
        context.tracing.start(screenshots=True, snapshots=True)
        page = context.new_page()
        page.set_default_timeout(10_000)          # a monitor must fail fast
        try:
            for step, action in [
                ("home", lambda: page.goto("/")),
                ("search", lambda: (page.goto("/products?q=mug"),
                                    expect(page.get_by_test_id("product-card")).to_have_count(1))),
                ("add_to_cart", lambda: (page.goto("/products/1"),
                                         page.get_by_role("button", name="Add to cart").click(),
                                         expect(page.get_by_role("status")).to_have_text("Added to cart"))),
                ("chat", lambda: (page.goto("/chat"),
                                  page.get_by_placeholder("Ask a question").fill("How long does shipping take?"),
                                  page.get_by_role("button", name="Send").click(),
                                  expect(page.get_by_test_id("bot-message")).to_have_attribute("aria-busy", "false"))),
            ]:
                t0 = time.perf_counter()
                action()
                timings[step] = round((time.perf_counter() - t0) * 1000)
            context.tracing.stop()
            return {"ok": True, "timings_ms": timings}
        except Exception as e:
            trace = f"trace-{int(time.time())}.zip"
            context.tracing.stop(path=trace)          # evidence for whoever is on call
            return {"ok": False, "failed_step": step, "error": str(e).splitlines()[0],
                    "trace": trace, "timings_ms": timings}
        finally:
            browser.close()

def check_once(notifier: Notifier, base_url: str = BASE) -> dict:
    result = run_journey(base_url) | {"at": datetime.now(timezone.utc).isoformat(), "target": base_url}
    with METRICS.open("a", encoding="utf-8") as f:     # or push to Prometheus, Datadog, CloudWatch...
        f.write(json.dumps(result) + "\n")
    state = json.loads(STATE.read_text()) if STATE.exists() else {"failures": 0, "alerting": False}
    if result["ok"]:
        if state["alerting"]:
            notifier.send(f"RECOVERED: ShopBot journey OK ({sum(result['timings_ms'].values())} ms)")
        state = {"failures": 0, "alerting": False}
    else:
        state["failures"] += 1
        if state["failures"] >= FAIL_THRESHOLD and not state["alerting"]:
            notifier.send(f"ALERT: ShopBot '{result['failed_step']}' failed {state['failures']} times "
                          f"in a row: {result['error']} (trace: {result['trace']})")
            state["alerting"] = True
    STATE.write_text(json.dumps(state))
    return result

if __name__ == "__main__":
    result = check_once(SlackNotifier(os.environ["SLACK_WEBHOOK_URL"]))
    raise SystemExit(0 if result["ok"] else 1)

The notifier is an interface, so the alerting logic is testable without Slack. This test points the monitor at a port where nothing is listening, then at the real app:

test_monitor.py
import monitor

class FakeNotifier:
    def __init__(self):
        self.sent = []
    def send(self, text):
        self.sent.append(text)

def test_alert_after_two_failures_then_recovery(tmp_path, monkeypatch):
    monkeypatch.chdir(tmp_path)
    monkeypatch.setattr(monitor, "STATE", tmp_path / "state.json")
    monkeypatch.setattr(monitor, "METRICS", tmp_path / "metrics.jsonl")
    n = FakeNotifier()
    down = "http://127.0.0.1:8099"                 # nothing listens here

    r = monitor.check_once(n, down)
    assert not r["ok"] and r["failed_step"] == "home" and n.sent == []   # one blip: no alert
    monitor.check_once(n, down)
    assert len(n.sent) == 1 and n.sent[0].startswith("ALERT")
    monitor.check_once(n, down)
    assert len(n.sent) == 1                        # no repeated alerts while still down

    ok = monitor.check_once(n, "http://127.0.0.1:8000")
    assert ok["ok"] and set(ok["timings_ms"]) == {"home", "search", "add_to_cart", "chat"}
    assert n.sent[-1].startswith("RECOVERED")

On an ephemeral runner the state file does not survive between runs, so either alert on each failed run (simpler) or keep the failure counter in your metrics system and alert there. For production monitoring use a dedicated test account, mark its orders as synthetic so they never ship or count in sales figures, and run from more than one region so a single network path does not page you at 3am.

# production jobs and CI: headless (the default)

  • Headed: see what happens; combine with page.pause() to open the Inspector. On a Linux server without a display, run headed under xvfb-run.
  • Since Playwright 1.49 headless Chromium uses the lightweight chromium-headless-shell build; channel="chromium" opts into the full browser's "new headless" mode, which behaves more like headed Chrome.
  • If something works headed but not headless, compare viewport size, user agent and whether the page waits for focus or animations; take a screenshot or a trace of the headless run.

Bot detection, stealth and ethics

Many sites detect automation (the navigator.webdriver flag, headless fingerprints, request rates, behaviour) and respond with CAPTCHAs or blocks. There are "stealth" plugins and residential proxy services that try to hide automation. The rule for this course is simple:

Do not bypass protections you are not authorised to bypass. A CAPTCHA, a login wall, a rate limit or a bot block is the site owner saying no. Circumventing it can breach the terms of service and, depending on the country, computer-misuse or anti-circumvention law. It also harms the site's real users.
SituationRight approach
Your own site blocks your tests or monitorAsk your team to allow-list the monitor (a header, IP range or test account), or use a staging environment with bot protection off. Turn off CAPTCHAs for test accounts rather than solving them.
A third-party site blocks your scraperStop. Look for an API, a data licence, or ask for permission. Slowing down and identifying yourself is fine; disguising yourself is not.
A vendor portal you pay for (invoices, reports)Check the contract; ask the vendor for an export or API; if automation is allowed, run it at human pace with your own account.
Authorised security or bot-defence testingOnly with written scope from the owner; this is a penetration-testing engagement, not a scraping job.

Resource blocking for speed

A scraper does not need images, fonts, video or analytics. Aborting them with a route cuts bandwidth and load time, and stops your runs inflating someone's analytics. Block at the context level so every page is covered.

import re
from playwright.sync_api import Route

BLOCK_TYPES = {"image", "media", "font"}
BLOCK_HOSTS = re.compile(r"(google-analytics|googletagmanager|doubleclick|hotjar|segment)\.")

def block_heavy(route: Route):
    request = route.request
    if request.resource_type in BLOCK_TYPES or BLOCK_HOSTS.search(request.url):
        return route.abort()
    return route.continue_()

context = browser.new_context()
context.route("**/*", block_heavy)
page = context.new_page()
page.goto("http://127.0.0.1:8000/products")
  • Do not block stylesheets or scripts the page needs to render its data, and never block resources in tests that check layout or visuals.
  • A catch-all route is called for every request, which itself costs a little; a narrower pattern such as "**/*.{png,jpg,jpeg,webp,woff2}" avoids the round trip for the rest.
  • Routes disable the HTTP cache in Playwright, so measure before and after: on small pages the gain can be nil.
  • Other speed-ups: reuse one browser and create contexts per job, wait for specific elements rather than wait_until="networkidle", and call JSON endpoints directly where allowed.

2. Screenshot every product page concurrently, at most two at a time medium

Use the async API, one context, a semaphore of 2, and save shots/product-{id}.png. Return how many succeeded.

import asyncio
from pathlib import Path
from playwright.async_api import async_playwright

async def shoot(context, sem, pid, out: Path):
    async with sem:
        page = await context.new_page()
        try:
            await page.goto(f"/products/{pid}")
            await page.screenshot(path=out / f"product-{pid}.png", full_page=True)
        finally:
            await page.close()

async def main():
    out = Path("shots"); out.mkdir(exist_ok=True)
    async with async_playwright() as p:
        browser = await p.chromium.launch()
        context = await browser.new_context(base_url="http://127.0.0.1:8000")
        sem = asyncio.Semaphore(2)
        results = await asyncio.gather(*(shoot(context, sem, i, out) for i in range(1, 5)),
                                       return_exceptions=True)
        await browser.close()
    return sum(not isinstance(r, Exception) for r in results)

print(asyncio.run(main()))     # 4
3. Make the order robot resumable medium

You have customers.csv (name, email, postcode). Place one order per row with place_order_and_download from the RPA section, but skip rows already recorded in results.csv and record failures without stopping.

import csv
from pathlib import Path

def done_emails(path=Path("results.csv")) -> set[str]:
    if not path.exists():
        return set()
    with path.open(encoding="utf-8") as f:
        return {r["email"] for r in csv.DictReader(f) if r["status"] == "ok"}

def run_batch(browser, out_dir=Path("invoices")):
    out_dir.mkdir(exist_ok=True)
    done = done_emails()
    new_file = not Path("results.csv").exists()
    with open("customers.csv", encoding="utf-8") as src, \
         open("results.csv", "a", newline="", encoding="utf-8") as res:
        writer = csv.DictWriter(res, fieldnames=["email", "status", "order_id", "detail"])
        if new_file:
            writer.writeheader()
        for row in csv.DictReader(src):
            if row["email"] in done:
                continue
            context = browser.new_context(base_url="http://127.0.0.1:8000")   # clean cart per order
            try:
                order_id, file = place_order_and_download(context.new_page(), row, out_dir)
                writer.writerow({"email": row["email"], "status": "ok", "order_id": order_id, "detail": file.name})
            except Exception as e:
                writer.writerow({"email": row["email"], "status": "failed", "order_id": "", "detail": str(e).splitlines()[0]})
            finally:

4. Add a latency alert to the monitor medium

A journey that passes but takes 20 seconds is also an incident. Alert when the total time exceeds a budget on two consecutive runs, reusing the failure counter.

LATENCY_BUDGET_MS = 8_000

def classify(result: dict) -> dict:
    total = sum(result["timings_ms"].values())
    if result["ok"] and total > LATENCY_BUDGET_MS:
        return result | {"ok": False, "failed_step": "latency",
                         "error": f"journey took {total} ms (budget {LATENCY_BUDGET_MS} ms)",
                         "trace": "n/a"}
    return result

5. Choose the tool easy

For each job, browser or HTTP client? (a) Nightly copy of ShopBot's product list into a database. (b) A weekly PDF of the cart page for an auditor. (c) Checking that a single-page app's dashboard shows today's figures after login with SSO.
