Playwright with Python

← All topicsStart: Introduction →

Playwright is an open-source library from Microsoft for driving real browsers (Chromium, Firefox and WebKit) from code. You use it to test web applications end to end, to automate anything a person can do in a browser, and, increasingly, as the "hands and eyes" of AI agents that browse the web. Its Python package gives you a clean API, built-in waiting so tests are not flaky, a pytest plugin, network mocking, tracing, and a built-in MCP server that lets an LLM control a browser.

This topic goes from your first script to advanced testing, then to AI: how agents use Playwright, how to test AI and agentic applications, and four end-to-end projects that build AI-powered testing tools. All code is Python.

A first taste

from playwright.sync_api import sync_playwright, expect

with sync_playwright() as p:
    browser = p.chromium.launch(headless=False)        # a real browser window
    page = browser.new_page()
    page.goto("http://127.0.0.1:8000/products")
    page.get_by_placeholder("Search products").fill("mug")
    page.get_by_role("button", name="Search").click()  # waits until the button is ready, then clicks
    expect(page.get_by_test_id("product-card")).to_have_count(1)   # retries until true or timeout
    browser.close()

No sleeps and no manual waits: Playwright waits for elements to be ready before acting, and its assertions retry until the page reaches the expected state.

How it works

Your Python code does not talk to the browser directly. It sends commands to the Playwright driver (a bundled Node.js process), which speaks each browser's automation protocol. Press Play to follow one click.

What people use Playwright for

End-to-end testingUser journeys across pages: sign-up, search, checkout, in Chromium, Firefox and WebKit.
Regression and smoke tests in CIRun hundreds of tests in parallel on every pull request; block bad releases.
API testingCall REST endpoints with the same tool, and mix API set-up with UI checks.
Visual regressionCompare screenshots with a baseline to catch layout and styling changes.
Accessibility testingRun accessibility scans and assert on the accessibility tree.
Mobile and device emulationViewports, touch, geolocation, locale, time zone, dark mode.
Network mockingFake back-end responses, simulate errors and slow networks, replay HAR files.
Web scraping and data extractionPages that need JavaScript, logins or scrolling (respect terms and robots.txt).
Browser automation (RPA)Fill forms, download reports, upload files in internal tools without APIs.
Synthetic monitoringRun a login-and-buy script every few minutes in production and alert on failure.
Screenshots and PDFsGenerate thumbnails, social cards, invoices and reports from HTML.
Performance checksMeasure load timings and web vitals in a real browser.
AI agent browsingGive an LLM a browser through the Playwright MCP server or your own tools.
Testing AI appsTest chatbots and agents: streaming UIs, mocked LLMs, LLM-as-judge assertions.
AI-generated and self-healing testsTurn user stories into tests and repair broken locators, with human review.
Exploratory testing agentsAgents that explore an app, find bugs and file reports with traces.

The example app: ShopBot

So that every example is concrete, the pages test the same small imaginary web shop, ShopBot, running locally at http://127.0.0.1:8000. Substitute your own application's URL and labels.

PageWhat is on it

/products/{id}Name, price, a Quantity field, an "Add to cart" button, a status message, and customer reviews (one review contains a planted prompt-injection text)

/api/...JSON endpoints: GET /api/products, POST /api/cart, POST /api/chat (server-sent events), GET /api/slow

Versions used

Examples were written against Playwright for Python 1.64 and pytest-playwright 0.10 on Python 3.12 (October 2026). Playwright releases roughly monthly; check the release notes when upgrading.
