Testing with pytest: fixtures, isolation and page objects

Scripts that call sync_playwright() are fine for experiments, but a real test suite needs set-up and tear-down, isolation between tests, configuration per environment, parallel runs, retries and reports. The official pytest-playwright plugin gives you all of that on top of pytest, the standard Python test runner. You write plain functions that ask for a page; the plugin launches browsers, creates a fresh browser context for every test, and adds command-line flags such as --browser, --headed and --tracing.

This page covers the fixtures and their lifetimes, how to override them in conftest.py, your own fixtures, parametrisation and markers, cross-browser and parallel runs, configuration, the Page Object Model with a complete ShopBot example, test data, retries and the layout of a real suite. Every snippet was run against ShopBot with pytest-playwright 0.10 and pytest 9.

Test files are named test_*.py, test functions test_*. The type hint page: Page is optional but gives you autocompletion. The test id becomes test_search_finds_mug[chromium] because the plugin parametrises every browser test by browser name.

The built-in fixtures and their scopes

A fixture is a function that pytest runs to provide a value a test asks for, and whose code after yield runs as clean-up. Its scope decides how long the value lives: function (a new one per test, the default), module, package or session (one for the whole run, or per worker when running in parallel). pytest-playwright builds the browser stack from fixtures with carefully chosen scopes:

FixtureScopeWhat it is
playwrightsessionThe started Playwright object (driver process). Use it for playwright.request, playwright.devices or a second browser type.
browser_name, browser_channel, is_chromium, is_firefox, is_webkitsessionWhich browser this run uses (from --browser and --browser-channel).
browser_typesessionplaywright.chromium, .firefox or .webkit.
browser_type_launch_argssessionThe dict passed to browser_type.launch(): headless, channel, slow_mo... Override it to add options.
browsersessionThe launched Browser. Launching takes around a second, so it is shared.
browser_context_argssessionThe dict passed to browser.new_context(): base_url, device, video... Override it for viewport, locale, storage_state and so on.
new_contextfunctionA factory: new_context(**extra) creates additional contexts (with your context args, tracing and video) and closes them after the test.
contextfunctionA fresh BrowserContext per test: its own cookies, local storage, cache and permissions.
pagefunctionA new tab in that context. Most tests only need this.
base_urlsessionFrom --base-url or the base_url ini option; relative goto() and page.request URLs resolve against it.
output_pathfunctionThis test's artefact folder under --output (default test-results).

The design is the key to fast, reliable suites: the expensive thing (a browser process) is created once, the cheap thing (a context, a few milliseconds) is created per test, so every test starts with a clean, isolated "incognito profile". Step through three tests:

Isolation, proven

These two tests pass in any order, alone or in parallel, because the second one gets a new context with no cookies, so ShopBot gives it a new, empty cart:

def test_isolation_one(page: Page):
    page.goto("/products/1")
    page.get_by_role("button", name="Add to cart").click()
    expect(page.get_by_test_id("cart-count")).to_have_text("1")


def test_isolation_two(page: Page):
    page.goto("/products")
    expect(page.get_by_test_id("cart-count")).to_have_text("0")    # fresh context: empty cart
Browser isolation is not server isolation. A new context gives you a new cookie jar, but anything stored on the server (a user's cart, orders, a shared account's settings) is still shared. Two tests that log in as the same user see each other's server-side data. See test data strategies.

Overriding the plugin in conftest.py

conftest.py is a file pytest loads automatically; fixtures defined there are available to every test in that folder and below. To change how the plugin creates browsers and contexts you override its fixtures by defining a fixture with the same name. Ask for the original as a parameter and extend it, so you keep what the plugin set from the command line (--base-url, --device, --video, --headed, --browser-channel).

tests/conftest.py
import pytest
from playwright.sync_api import expect

expect.set_options(timeout=10_000)          # web-first assertions wait up to 10 s (default 5 s)


@pytest.fixture(scope="session")
def browser_context_args(browser_context_args: dict) -> dict:
    return {
        **browser_context_args,              # keep base_url, --device and video settings
        "viewport": {"width": 1280, "height": 800},
        "locale": "en-GB",
        "timezone_id": "Europe/London",
        # "base_url": "http://127.0.0.1:8000",   # or hard-code it here instead of --base-url
        # "ignore_https_errors": True,           # self-signed certificates on test servers
    }


@pytest.fixture(scope="session")
def browser_type_launch_args(browser_type_launch_args: dict, browser_name: str) -> dict:
    args = {**browser_type_launch_args, "timeout": 60_000}   # give slow CI machines 60 s to start the browser
    if browser_name == "chromium":
        args["args"] = ["--disable-dev-shm-usage"]          # Chromium flag: small /dev/shm in Docker
    return args

The override must keep scope="session" (the plugin's own fixtures depend on it). Two finer-grained tools:

@pytest.mark.browser_context_args(locale="de-DE", color_scheme="dark")
def test_german_dark_mode(page: Page):
    page.goto("/products")
    assert page.evaluate("navigator.language") == "de-DE"

Custom fixtures

Anything several tests need goes into a fixture: an API client, a signed-in page, seeded data, page objects. Code before yield is set-up, code after it is tear-down and runs even when the test fails.

tests/conftest.py (continued)
from collections.abc import Iterator

from playwright.sync_api import APIRequestContext, BrowserContext, Page, Playwright

from pages import CartPage, ProductsPage


@pytest.fixture(scope="session")
def api(playwright: Playwright, base_url: str) -> Iterator[APIRequestContext]:
    """A browser-less HTTP client for set-up and API checks (one per session or worker)."""
    ctx = playwright.request.new_context(base_url=base_url)
    yield ctx
    ctx.dispose()


@pytest.fixture
def logged_in_page(context: BrowserContext) -> Iterator[Page]:
    """A page signed in as Alice. Logs in over HTTP (fast), logs out afterwards."""
    response = context.request.post("/login", form={"email": "alice@example.com", "password": "wonderland"})
    assert response.ok, f"login failed: {response.status}"
    page = context.new_page()          # context.request shares the context's cookies
    yield page
    context.request.post("/logout")    # tear-down: end the server-side session


@pytest.fixture
def cart_with(page: Page):
    """Factory fixture: cart_with({1: 2}) puts two of product 1 in this test's cart via the API."""
    page.goto("/products")             # the first response sets ShopBot's session cookie

    def _fill(items: dict[int, int]) -> CartPage:
        for product_id, qty in items.items():
            r = page.request.post("/api/cart", data={"product_id": product_id, "qty": qty})
            assert r.ok, r.text()
        return CartPage(page).open()
    return _fill


@pytest.fixture
def products_page(page: Page) -> ProductsPage:
    return ProductsPage(page)

Test data with guaranteed clean-up

For data your application lets you create and delete, the pattern is a factory fixture that records what it created and deletes it in tear-down. ShopBot has no users API, so this one is for your own application:

import uuid

@pytest.fixture
def make_user(api: APIRequestContext):
    created: list[int] = []

    def _make(**overrides) -> dict:
        body = {"email": f"test-{uuid.uuid4().hex[:8]}@example.com", "password": "S3cret!pass", **overrides}
        r = api.post("/api/users", data=body)
        assert r.ok, r.text()
        created.append(r.json()["id"])
        return r.json()

    yield _make
    for user_id in created:                  # runs even if the test failed half-way
        api.delete(f"/api/users/{user_id}")


def test_new_user_can_log_in(make_user, page: Page):
    user = make_user(name="Bob")
    ...

Parametrisation and markers

@pytest.mark.parametrize runs one test function with several inputs; each case is reported separately. It is ideal for search queries, validation rules and roles:

@pytest.mark.parametrize(
    "query, category, expected",
    [
        ("mug", "", 1),
        ("a", "", 3),
        ("", "kitchen", 2),
        ("", "office", 2),
        pytest.param("zzz", "", 0, id="no-results"),
    ],
)
def test_search_counts(products_page: ProductsPage, query, category, expected):
    products_page.open().search(query, category)
    expect(products_page.cards).to_have_count(expected)
    expect(products_page.result_count).to_have_text(f"{expected} results")


@pytest.mark.parametrize(
    "email, password",
    [("alice@example.com", "wrong"), ("bob@example.com", "wonderland")],
    ids=["bad-password", "unknown-user"],
)
def test_bad_login(page: Page, email, password):
    page.goto("/login")
    page.get_by_label("Email").fill(email)
    page.get_by_label("Password").fill(password)
    page.get_by_role("button", name="Log in").click()
    expect(page.get_by_role("alert")).to_have_text("Invalid email or password")

Cross-browser and device runs

The same tests run on every engine; choose them on the command line, not in the code:

playwright install chromium firefox webkit
pytest --browser chromium --browser firefox --browser webkit   # 3 x the tests: test_x[chromium], test_x[firefox], test_x[webkit]
pytest --browser-channel chrome          # the installed Google Chrome instead of bundled Chromium
pytest --browser-channel msedge          # Microsoft Edge
pytest --browser webkit --device "iPhone 15"   # Safari's engine with a phone viewport, touch and user agent
RunCatchesTypical schedule
Chromium (or Chrome channel)Most bugs; it is the majority of usersEvery pull request
FirefoxGecko layout and event differences, stricter standards behaviourEvery PR for important journeys, or nightly
WebKitSafari behaviour (dates, flexbox gaps, autoplay, storage) without a MacNightly, or every PR if many users are on iOS
--device runsResponsive layout, touch, mobile navigationNightly smoke subset

WebKit on Windows or Linux is close to, but not identical with, Safari on macOS and iOS. If Safari matters a lot, add a run on a real device cloud as well (see debugging and CI).

Parallel runs with pytest-xdist

pip install pytest-xdist, then pytest -n auto starts one worker process per CPU core and spreads the tests across them. Each worker is a separate Python process with its own session fixtures: its own Playwright driver and browser. Because every test already has its own context, Playwright tests parallelise well; what usually breaks is shared server data.

Three workers sharing a queue of tests

pytest -n auto                         # one worker per CPU core (--dist load is implied)
pytest -n 4 --dist loadfile            # all tests of a file on the same worker
pytest -n 4 --dist loadgroup           # tests with the same xdist_group run on one worker
pytest -n 4 --dist worksteal           # split up front, idle workers steal from busy ones
@pytest.mark.xdist_group("alice-cart")        # these share Alice's server-side cart: keep them together (with --dist loadgroup)
def test_alice_adds_mug(logged_in_page): ...


@pytest.fixture(scope="session")
def account(worker_id: str) -> dict:
    """One test account per worker: gw0 -> qa+gw0@example.com, gw1 -> qa+gw1@..., 'master' without -n."""
    return {"email": f"qa+{worker_id}@example.com", "password": os.environ["QA_PASSWORD"]}
Rule of thumb. Parallel tests must not depend on order or on each other's data. Give each worker (or each test) its own data, use unique names (uuid4), and never assert on global counts such as "there are 12 orders". The worker_id fixture and the PYTEST_XDIST_WORKER environment variable tell you which worker you are in. More workers than cores, or than your test server can handle, makes runs slower and flakier.

The Page Object Model

When twenty tests all write page.get_by_placeholder("Search products") and the placeholder changes, you fix twenty tests. A page object is a class that owns the locators and actions of one page, so tests talk in the language of the application ("search for mug, open the card, add two to the cart") and each locator lives in exactly one place. Component objects do the same for parts that appear on many pages (a navigation bar) or many times on one page (a product card); they wrap a Locator instead of the whole page.

Guidelines that keep page objects useful: expose locators as attributes so tests can assert on them with expect; make action methods return the page object the user lands on; keep assertions in tests (an action may wait for its own outcome); no sleeps; no test logic (if on test data) inside page objects.

pages/components.py
import re

from playwright.sync_api import Locator, Page


class NavBar:
    """The main navigation bar shown on every ShopBot page."""

    def __init__(self, page: Page):
        self.page = page
        self.root = page.get_by_role("navigation", name="Main")
        self.cart_link = self.root.get_by_role("link", name=re.compile(r"^Cart"))
        self.cart_count = self.root.get_by_test_id("cart-count")
        self.user_name = self.root.get_by_test_id("user-name")
        self.login_link = self.root.get_by_role("link", name="Log in")

    def open_cart(self) -> "CartPage":
        from .cart import CartPage          # local import avoids a circular import
        self.cart_link.click()
        return CartPage(self.page)


class ProductCard:
    """One product card on /products. Wraps a locator, not the whole page."""

    def __init__(self, root: Locator):
        self.root = root
        self.title = root.get_by_role("heading")
        self.price = root.get_by_text(re.compile(r"^£"))
        self.stock = root.get_by_text(re.compile(r"stock$"))

    def open(self) -> "ProductPage":
        from .product import ProductPage
        self.root.get_by_role("link").click()
        return ProductPage(self.root.page)

        self.page = page

pages/products.py
from playwright.sync_api import Page

from .base import BasePage
from .components import ProductCard


class ProductsPage(BasePage):
    path = "/products"

    def __init__(self, page: Page):
        super().__init__(page)
        self.search_box = page.get_by_placeholder("Search products")
        self.category = page.get_by_label("Category")
        self.search_button = page.get_by_role("button", name="Search")
        self.cards = page.get_by_test_id("product-card")
        self.result_count = page.get_by_test_id("result-count")
        self.no_results = page.get_by_role("status")

    def search(self, text: str = "", category: str = "") -> "ProductsPage":
        self.search_box.fill(text)
        self.category.select_option(category)        # "" = All
        self.search_button.click()
        return self

    def card(self, name: str) -> ProductCard:
        return ProductCard(self.cards.filter(has=self.page.get_by_role("heading", name=name)))

pages/cart.py
from playwright.sync_api import Locator, Page

from .base import BasePage


class CartPage(BasePage):
    path = "/cart"

    def __init__(self, page: Page):
        super().__init__(page)
        self.rows = page.get_by_role("row").filter(has=page.get_by_role("cell"))   # body rows only
        self.total = page.get_by_test_id("cart-total")
        self.empty_message = page.get_by_text("Your cart is empty.")
        self.checkout_link = page.get_by_role("link", name="Checkout")

    def row(self, product: str) -> Locator:
        return self.rows.filter(has_text=product)

    def quantity_of(self, product: str) -> Locator:
        return self.row(product).get_by_role("cell").nth(1)

Page objects: good for

  • Suites with more than a handful of tests
  • Locators reused across tests and teams
  • Readable journeys that product people can review
  • A single place to fix when the UI changes (and a natural target for AI "self-healing" tools)

Avoid

  • A god object with every locator of the site
  • Methods like verify_everything() that hide assertions
  • Returning raw strings (inner_text()) for tests to compare: return locators and use expect, which retries
  • Deep inheritance trees; prefer composition (components)

Retries with pytest-rerunfailures

Retries hide flakiness, they do not fix it. Used carefully they stop a rare network hiccup from blocking a release while you collect evidence. Combine them with tracing so the failing attempt is kept: pytest-playwright writes each attempt into its own folder (...-retry1).

pip install pytest-rerunfailures
pytest --reruns 2 --reruns-delay 1                       # rerun any failure up to twice, 1 s apart
pytest --reruns 2 --only-rerun TimeoutError              # only action time-outs (a failed expect() is an AssertionError)
pytest --reruns 2 --fail-on-flaky                        # still exit with code 7 if a test needed a rerun
pytest --reruns 1 --tracing retain-on-failure            # keep the trace of the failed attempt
@pytest.mark.flaky(reruns=3, reruns_delay=2)     # per test, for a known third-party slowness
def test_payment_provider_redirect(page: Page): ...

The summary marks such tests as R (rerun) and lists them, so track them: a test that needs reruns every week is a bug in the test or the application. The debugging page has a table of flakiness causes and fixes.

Write a page object method and test for the "Kitchen" category filter easy

Using ProductsPage, assert that filtering by Kitchen shows exactly the Ceramic Mug and the Cast Iron Pan, in that order.

from playwright.sync_api import expect


def test_kitchen_filter(products_page):
    products_page.open().search(category="kitchen")
    expect(products_page.cards.get_by_role("heading")).to_have_text(["Ceramic Mug", "Cast Iron Pan"])
    expect(products_page.result_count).to_have_text("2 results")

to_have_text with a list checks every matching element in order, and retries as a whole.

Make every test in tests/mobile/ run as an iPhone 15 medium

Without changing the tests and without the --device flag.

# tests/mobile/conftest.py
import pytest


@pytest.fixture(scope="session")
def browser_context_args(browser_context_args: dict, playwright) -> dict:
    return {**browser_context_args, **playwright.devices["iPhone 15"]}

The device descriptor contains viewport, user_agent, device_scale_factor, is_mobile and has_touch. Its default_browser_type is a hint only; run the folder with --browser webkit for the closest match to Safari (on Firefox, remove is_mobile, which it does not support).

Find the isolation bug medium

A colleague expects the second test to pass because the first one "always runs first". It fails, every time. Why, and how do you fix it?

def test_first_adds(page):
    page.goto("/products/1")
    page.get_by_role("button", name="Add to cart").click()

def test_second_checks_cart(page):
    page.goto("/cart")
    expect(page.get_by_test_id("cart-total")).to_have_text("£12.00")

Each test gets its own context, so the second test never has the first test's session cookie and ShopBot shows it an empty cart. Even if the state were shared some other way (a shared account), the test would still break under -n 4, -k or random ordering. Make every test self-contained:

def test_cart_total(cart_with):
    cart = cart_with({1: 1})
    expect(cart.total).to_have_text("£12.00")
A fixture that records a trace only for tests marked @pytest.mark.trace hard

Without using --tracing. Save it to the test's output_path.

# conftest.py  (register "trace" under markers in pyproject.toml)
import os

import pytest


@pytest.fixture(autouse=True)
def trace_marked(request, context, output_path):
    if not request.node.get_closest_marker("trace"):
        yield
        return
    context.tracing.start(screenshots=True, snapshots=True, sources=True)
    yield
    os.makedirs(output_path, exist_ok=True)
    context.tracing.stop(path=os.path.join(output_path, "trace.zip"))

Because it is autouse and requests context, every test in its scope gets a context; put it in the conftest.py of browser-test folders only. Do not combine it with --tracing: the plugin has already started tracing and tracing.start() raises "Tracing has been already started". Open the result with playwright show-trace.

Per-worker test accounts hard

Your app has an admin API POST /api/admin/users. Give each xdist worker its own signed-in user, created once per worker and deleted at the end.

import os
import uuid

import pytest


@pytest.fixture(scope="session")
def worker_user(api, worker_id):
    email = f"qa-{worker_id}-{uuid.uuid4().hex[:6]}@example.com"
    r = api.post("/api/admin/users", data={"email": email, "password": "S3cret!pass"},
                 headers={"Authorization": f"Bearer {os.environ['ADMIN_TOKEN']}"})
    assert r.ok, r.text()
    yield r.json()
    api.delete(f"/api/admin/users/{r.json()['id']}",
               headers={"Authorization": f"Bearer {os.environ['ADMIN_TOKEN']}"})


@pytest.fixture(scope="session")
def worker_state(browser, base_url, worker_user, tmp_path_factory) -> str:
    ctx = browser.new_context(base_url=base_url)
    ctx.request.post("/login", form={"email": worker_user["email"], "password": "S3cret!pass"})
    path = tmp_path_factory.mktemp("auth") / "state.json"
    ctx.storage_state(path=path)
    ctx.close()
    return str(path)

Session fixtures run once per worker, so each worker creates, uses and deletes its own user. Tests then use new_context(storage_state=worker_state) or a folder-level browser_context_args override.
