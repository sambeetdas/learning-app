What is machine learning?

In normal programming you write the rules: if the amount is over 10,000 and the country is new, flag it. In machine learning (ML) you give the computer examples (inputs together with the right answers) and it works out the rules itself, as a mathematical function called a model. You then use the model to make predictions on data it has never seen. 

Traditional programming:   rules + data      --->  answers
Machine learning:          data + answers    --->  rules (the model)
                           new data + model  --->  predictions
TermMeaningExample

ML is a good fit when

  • The rules are too many or too fuzzy to write by hand (is this photo a cat?).
  • The pattern changes over time and the system must adapt (fraud, trends).
  • You have enough relevant, reasonably clean data with outcomes.
  • An imperfect but fast prediction is still valuable, and mistakes are affordable.

Do not use ML when

  • A simple rule or formula solves it (tax calculation, "is it a weekend").
  • You have little data, or no way to know the right answers.
  • Every decision must be 100% correct and fully explainable by law or safety.
  • You cannot maintain it: models degrade and need monitoring and retraining.

The ML project lifecycle

Modelling is only a small part. Most real effort goes into data and into running the model reliably afterwards.

  1. Frame the problem. What decision will the prediction change? What does success look like in business terms (money saved, minutes reduced)? What is the cost of each type of mistake? What is the simplest non-ML baseline?
  2. Collect and understand the data. Where does it come from, how are labels produced, how reliable are they? Explore distributions, gaps, outliers and leaks.
  3. Clean and prepare. Missing values, duplicates, wrong units, inconsistent categories.
  4. Engineer features. Turn raw data into signals the model can use (counts, ratios, time since last event, text embeddings). Often the biggest accuracy gain.
  5. Split the data into training, validation and test sets, before any fitting.
  6. Train a baseline, then better models. Start simple (logistic regression, a small tree model) and add complexity only if it pays off.
  7. Evaluate with metrics that match the business cost, on data the model never saw. Look at errors by segment, not only averages.
  8. Tune and iterate. Hyperparameters, features, data quality, model choice.
  9. Deploy. Batch scoring, real-time API, streaming or on-device.
  10. Monitor and retrain. The world changes; model quality quietly decays unless you watch it.

Rule of thumb

Roughly 60-80% of the time goes into data work (collecting, cleaning, labelling, features) and deployment, not into choosing algorithms. Better data usually beats a fancier model.

How a model learns: gradient descent

A model has adjustable numbers called parameters (weights). A loss function measures how wrong its predictions are. Training means nudging the parameters to make the loss smaller. The standard method, gradient descent, computes which direction reduces the loss fastest and takes a small step that way, over and over. The step size is the learning rate.

Watch a line learn to fit data

Try: learning rate 0.05 (slow but steady), 0.2 (good), 0.9 (the loss explodes: steps overshoot the minimum and the model diverges).

  • Stochastic / mini-batch gradient descent: real systems compute each step on a small batch of examples rather than the whole dataset. Noisier, but much faster on big data.
  • One pass through the data is an epoch. Training runs many epochs, usually stopping when validation error stops improving (early stopping).
  • Optimizers such as Adam improve on plain gradient descent by adapting the step size per parameter.
  • Tree-based models (random forest, gradient boosting) learn differently, by splitting data into groups, but still minimise a loss.

Overfitting, underfitting and the bias-variance trade-off

A model that is too simple misses the real pattern (underfitting, high bias). A model that is too flexible memorises the noise in the training data and fails on new data (overfitting, high variance). The goal is the sweet spot where error on unseen data is lowest. This is the central idea of ML.

Fit a curve to 12 noisy points

Try: degree 1 (underfit), 3 (good), 11 (overfit: wiggles through every dot). Then keep degree 11 and raise regularization: the curve calms down and test error drops.

How to fight overfitting

  • More (and more varied) data, or data augmentation (flip, crop, add noise to images).
  • Simpler model, fewer features, shallower trees.
  • Regularization: penalise large weights (L2 / ridge, L1 / lasso which also removes features), dropout in neural networks, limiting tree depth.
  • Early stopping: stop training when validation error starts to rise.
  • Cross-validation to notice the problem early, and ensembles to average it out.

Diagnosis: high training error and high test error = underfitting. Low training error but much higher test error = overfitting.

Choosing quickly

  • Tabular data with labels: start with logistic/linear regression as a baseline, then try gradient boosting. That pair solves most business problems.
  • Images, audio, video: fine-tune a pre-trained deep network (CNN or vision transformer).
  • Text: TF-IDF + logistic regression for a quick baseline; embeddings or fine-tuned transformers when meaning matters; an LLM for generation and flexible tasks.
  • No labels: clustering, anomaly detection, or self-supervised pre-training.
  • Small data: simple, regularised models and strong features; consider transfer learning.
  • Must be explainable: linear models, small trees, or boosting with SHAP explanations.

Measuring quality: choosing the right metric

Accuracy alone is often misleading. Pick the metric that reflects the real cost of mistakes.

Confusion matrix (fraud example, 1,000 transactions)

                    Predicted fraud    Predicted OK
  Actually fraud        TP = 8            FN = 2      (missed fraud)
  Actually OK           FP = 12           TN = 978    (good customers blocked)

  Accuracy  = (TP + TN) / all     = 98.6%   <- looks great, hides the story
  Precision = TP / (TP + FP)      = 40%     of the alerts are real
  Recall    = TP / (TP + FN)      = 80%     of the fraud was caught
  F1        = harmonic mean of precision and recall

  • Threshold: classifiers output a score; you choose the cut-off. Set it from the cost of each error type, not at 0.5 by default.
  • Calibration: if the model says "70%", is it right 70% of the time? Needed whenever probabilities feed decisions; fix with Platt scaling or isotonic regression.
  • Offline vs online: a better offline metric does not guarantee better business results. Confirm with an A/B test.
  • Check slices: good average performance can hide poor performance for a region, device or customer group.

Hyperparameter tuning

Parameters are learned from data (weights). Hyperparameters are settings you choose before training (tree depth, learning rate, number of layers, regularization strength).

  • Grid search: try every combination. Simple, wasteful for many settings.
  • Random search: sample combinations at random. Usually finds good settings faster than a grid.
  • Bayesian optimisation (Optuna, Hyperopt): uses past trials to choose the next one. Efficient for expensive models.
  • AutoML (Azure AutoML, SageMaker Autopilot, Vertex AutoML, AutoGluon, H2O): automates model selection and tuning, a strong baseline in minutes.
  • Always tune using validation data or cross-validation, never the test set.

Ensembles: combining models of the same kind

Many weak or varied models voting together are usually more accurate and more stable than any single model. The errors of individual models partly cancel out.

MethodIdeaReducesExamples
BaggingTrain many models in parallel on random resamples of the data, then average or vote.Variance (overfitting)Random forest
BoostingTrain models one after another; each focuses on the mistakes of the previous ones, and their outputs are added up.Bias (and some variance)XGBoost, LightGBM, CatBoost, AdaBoost
Voting / averagingDifferent model types predict independently; combine by majority vote or by averaging probabilities.VarianceLogistic regression + random forest + boosting
StackingA final "meta-model" learns how best to combine the predictions of several base models.Both, if models differscikit-learn StackingClassifier, Kaggle winning solutions

Ensembles work best when the models are accurate and different (different algorithms, features or data). Ten copies of the same model add nothing. The cost: more compute, more complexity, harder to explain.

from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.ensemble import (RandomForestClassifier,
                              HistGradientBoostingClassifier, StackingClassifier)
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split, cross_val_score

num, cat = ['age', 'income'], ['country', 'plan']

prep = ColumnTransformer([
    ('num', Pipeline([('imp', SimpleImputer(strategy='median')),
                      ('sc',  StandardScaler())]), num),
    ('cat', OneHotEncoder(handle_unknown='ignore'), cat),
])

stack = StackingClassifier(
    estimators=[('rf', RandomForestClassifier(n_estimators=300, class_weight='balanced')),
                ('gb', HistGradientBoostingClassifier())],
    final_estimator=LogisticRegression(),      # the "meta-model" that blends them
    cv=5)

model = Pipeline([('prep', prep), ('clf', stack)])   # preprocessing lives INSIDE the pipeline (no leakage)

Deep learning and neural networks

A neural network is layers of simple units (neurons). Each neuron multiplies its inputs by weights, adds them up, and passes the result through an activation function (such as ReLU). Stacking layers lets the network build complex features from simple ones: edges, then shapes, then objects. Training uses backpropagation: the error is pushed backwards through the layers to find how each weight should change, then gradient descent updates them.

Ideas that make modern ML practical

  • Embeddings: turning words, products, users or images into vectors where similar things sit close together. They power search, recommendations and RAG.
  • Transfer learning: reuse a model trained on huge general data and adapt it with your small dataset. Usually the right starting point for images and text.
  • Large language models (LLMs): transformers pre-trained to predict the next token on vast text, then tuned to follow instructions. Prompting, fine-tuning (including LoRA) and retrieval (RAG) are three ways to adapt them. They can state falsehoods confidently, so ground and evaluate their output.
  • GPUs and batches: deep learning needs parallel hardware (GPU/TPU). For tabular data, CPU-based boosting is usually enough.
  • Deep learning is not always better: on structured business data, gradient boosting often matches or beats it with far less effort.

Reinforcement learning and bandits

An agent takes actions in an environment, receives rewards, and learns a policy that maximises total reward over time. The core tension is explore (try something new) versus exploit (repeat what works).

  • Multi-armed bandits are the simple, widely used case: pick one of several options (headline, offer, recommendation) per visit, learn which wins, and shift traffic gradually. Smarter than a fixed A/B test when you want to earn while you learn.
  • Full RL handles sequences where today's action changes tomorrow's situation (robot control, game play, supply chains). Needs a simulator or lots of safe experimentation, so it is rarer in business use.
  • RLHF (reinforcement learning from human feedback) is used to align LLMs with human preferences.

Responsible AI: fairness, explainability, privacy, security

  • Bias and fairness: models learn the biases in their data (historic hiring or lending decisions) and can amplify them. Check performance and error rates across groups, review features that act as proxies for protected attributes, and agree on a fairness definition before training.
  • Explainability: global (which features matter overall: permutation importance), local (why this prediction: SHAP, LIME), or inherently interpretable models. Required for regulated decisions such as credit.
  • Privacy: minimise and anonymise personal data, respect consent and deletion rights (GDPR), and consider differential privacy or federated learning. Models can memorise and leak training data.
  • Security: adversarial inputs (tiny changes that fool image models), data poisoning, model theft, and for LLMs prompt injection and data leakage through prompts. Validate inputs, limit what tools a model can use, and keep a human check on high-impact actions.
  • Governance and regulation: document data sources, intended use, limits and test results (model cards). Rules such as the EU AI Act classify systems by risk and impose duties on high-risk ones.
  • Reliability: know when the model is unsure and fall back safely. Provide a way for people to contest and correct decisions.

Things beginners often do not know

ConceptWhy it matters
Always build a baselineA simple rule, average or logistic regression tells you if the fancy model adds value at all. Many projects stop there.
Correlation is not causationPrediction finds patterns; it does not tell you what happens if you intervene. For "should we offer a discount?" you need experiments or causal methods (uplift modelling).
Training-serving skewFeatures computed differently offline and online silently break models. Share the feature code or use a feature store.
Feedback loopsThe model's decisions change the data it later learns from (you only see outcomes for loans you approved). Plan for exploration and unbiased samples.
Cold startNew users and new items have no history. Use popular/content-based fallbacks until data arrives.
Concept driftBehaviour changes (new fraud tactics, post-pandemic demand), so yesterday's model slowly gets worse. Monitor and retrain.
Interpretability vs accuracyOften a small accuracy gain is not worth losing explainability, especially in regulated areas.
The cost of a wrong prediction is not symmetricMissing a fraud costs far more than one extra check. Optimise decisions, not accuracy.
Distribution shiftIf production data differs from training data (new country, new camera), accuracy drops, even without a bug.
RandomnessDifferent seeds give different results. Report averages over several runs and fix seeds for reproducibility.
Human labelling effortLabels are often the biggest cost. Active learning (label the most informative examples first) and weak supervision reduce it.
Synthetic data and augmentationCan fill gaps for rare cases, but must resemble reality or it teaches the wrong thing.
Foundation modelsLarge pre-trained models you adapt rather than train from scratch. Changes the build-or-buy decision for text, vision and speech.
Small models can winLatency, cost and privacy often favour compact, distilled or classic models over giant ones.

Quick reference and learning path

Rules to remember

  • Start simple; baseline first.
  • Data quality and features beat model choice.
  • Split before you do anything else; guard the test set.
  • Pick metrics from the business cost of errors.
  • Tabular data: try gradient boosting. Images/text: fine-tune pre-trained models.
  • Combine models where each covers another's weakness.
  • A model in production is a service: monitor, retrain, roll back.

Suggested learning path

  1. Python, pandas, basic statistics and probability.
  2. Linear and logistic regression; train/test split; metrics.
  3. Trees, random forest, gradient boosting; cross-validation; feature engineering.
  4. Clustering, PCA, anomaly detection.
  5. Neural networks with PyTorch; CNNs; transformers; embeddings.
  6. MLOps: tracking, deployment, monitoring.
  7. Build 2-3 end-to-end projects with real, messy data.
